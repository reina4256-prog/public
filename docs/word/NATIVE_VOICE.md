# nativeの声選び・開発接続

## 声が出ないときのローカル診断

追加の説明分類：`explanationClasses`には既知のエラー定型句に応じた分類だけ、`rejectedFields`には既知の送信項目名だけを記録する。`generation_incomplete`はGoogleが生成未完了と説明した場合で、指示のどの語が原因か／安全方針による拒否かを示さない。`parameter_rejected`と項目名はパラメータ検査の手掛かり、`policy_rejection`は明示的な安全／方針拒否の定型句、`unclassified`は分類不能を示す。全文・自由な要約・未知の項目名は保存しない。改修後に再起動して一度試す必要があり、助手からの追加生成は行わない。

2026-11-24：ゲームを再起動して本人が一度試すと、mainの処理段階・HTTP番号・固定分類・所要時間を`%APPDATA%/AIPetGame-WordLearning-LLMNative/native-voice-diagnostics.jsonl`へ追記する。失敗分類は起動した端末にも出る。APIキー、指示文、会話文、声ID、エラー本文は保存しない。追加通信／自動再送／予算変更なし。HTTP429は回数・金額など複数の制限を含むため、1000円到達を単独で証明しない。`sample_format`／`sample_wav`は受信音声、`timeout`は60秒待ち、`network`は応答前の通信失敗、`http`は応答番号を併せて確認する。`complete`はmainでの音声検査完了で、画面側の再生完了を保証しない。改修前の失敗の詳細は残っていないため復元できない。ゲーム内の自然な案内は維持し、診断表示をプレイヤー画面へ追加しない。

正本は[声の所有仕様](../specs/core/word_llm_native_system.md#声を選んで同じ子と話す2026-11-23)。旧版／比較版の声設定・VOICEVOX停止を保持する。Live／マイクの追加ではない。

## 一度だけ行う開発用接続

1. AI Studioの既存`ai-pet-game`のAPIキーを本人がコピーする。新規キーの自動作成は行わない。キーをチャット／Git／本人ノートへ貼らない。
2. `public`で`node scripts/experimental/setup_native_voice.js`を実行する。これはゲーム外の開発用窓でありゲーム内には表示しない。
3. API key欄へ本人が貼り付け、Save connectionを押す。Saved表示後に窓を閉じる。この操作は鍵のOS暗号化保存だけで、API生成／課金変更／購入はしない。Windowsの同じアカウントでだけ使う。環境に暗号化機能がなければ保存しない。
4. 起動中の本人のゲームは本人が×で閉じ、`npm run start:word:native -- --fast-trial`で再起動する。本人セーブを消さず、既存本人は「つづきから」。ゲームの「この子の声」から選び、声をきく／この声にするで確認する。新規本人は設問後のキャラクター画面で選び、従来どおり手描きサインする。

接続キーはmain専用`native-voice-key.bin`、声とON/OFFは`native-voice-preferences.json`。どちらも専用userData内で、旧`word-audio-preferences.json`や本人セーブを変更しない。開発用の`WORD_GEMINI_TTS_KEY`指定も可（main取得後CLIへ継承せず削除）。キーをコマンド履歴に直接書かない。

### 保存できない場合

接続窓の保存に時間切れはなく、APIへの有効性検査も行わない。旧工具には旧`AIza`形式限定の判定と204文字の入力上限があったため、新しい認証キーを拒否／途中切断する不備があった。修正版の窓へ開き直し、AI StudioのCopyボタンで既存キー全体をコピーし直す。現行工具はドットを含む20〜512文字のキーを受け付け、入力欄で途中切断しない。[公式のキー種類](https://aistudio.google.com/docs/api-key)を参照。

失敗表示は入力形式／Windows暗号化／保存先への書込み／接続窓の検証を区別する。暗号化できない場合は平文保存へ切り替えず、例外本文やキーを表示／ログ出力しない。Savedはローカル暗号化保存の成功であり、APIの認証・利用枠・実試聴の成功ではない。

PCをシャットダウンしても、通常の起動コマンドだけでよい。追加サーバーやVOICEVOXの起動、キーの毎回入力は不要。2026-11-24修正では、Windowsの暗号化領域が登録窓とゲームで異なっていた不備を解消し、mainが登録時と同じvoice-setupの短命読取プロセスから専用pipeでキーを受け取る。キーは引数／環境変数／ログへ出さず、読取プロセスは起動時の一度だけで常駐しない。既存の暗号化キーは移動・再入力しない。[Electronの暗号化領域の説明](https://github.com/electron/electron/issues/39733)。

## キャラクターらしい声をつくる

設問後の本人情報、または既存本人の「この子の声」で「声をつくる」を開く。小さく丸い不思議な生き物の声が初期値。八つの選択項目だけで指定でき、補足したい時だけ自由入力300文字を使う。「声をつくってきく」を押した時だけ作成し、聞いてから「この声にする」で確定する。初回はサインの確定時に保存する。同じ設定は保存済みの候補を再利用し、毎回別の声を自動作成しない。

追加送信は選択式の特徴の説明と任意の原文だけ。名前／会話／日記／署名を追加送信せず、独立した`native-voice-designs.json`へ設定と登録声を保存する。声の作成先は既存Googleプロジェクト。公式の期限は「最長1年」ではなく「1年の未使用で期限切れ、利用で延長」で、訂正後の条件を本人が承認済み。現行案内では保存だけの継続料金はなく、声を作る際の試聴音声生成と読み上げ時に利用料金が発生する。新しい月額契約や自動補充は追加しない。実装検査では模擬APIを使い、実際の生成・声質は本人の試遊で確認する。[Voice design](https://aistudio.google.com/docs/voice-design)、[保存期限のAPI説明](https://aistudio.google.com/api-reference/voices/create-voice)、[公式フォーラムの料金説明](https://discuss.ai.google.dev/t/gemini-voices-api/186815)。

## 費用と送信範囲

- ユーザーが設定した月1000円上限／前払い800円／自動補充OFFを保持。上限はAI Studio側のもので、反映遅延の超過をアプリが厳密に防ぐものではない。アプリは購入／自動補充／課金設定を変更しない。
- 声を選ぶだけでは生成せず、明示した試聴または新しい会話の保存済み返答だけを送る。固定試聴は七言語の同じ短文をcacheし、個人別の本文は音声の永続cacheへ入れない。音声に失敗しても保存済み文字返答を残す。
- 返答TTSには確定返答文と声を送る。原入力／受け取り方／履歴／日記／世界全体／署名／マイク音声を新たに送らない。生成音声を学習根拠や実績へ戻さない。
- 公式：[TTS](https://aistudio.google.com/docs/speech-generation)、[課金と上限](https://aistudio.google.com/docs/billing)。会話CLIの契約内利用・追加クレジットOFFは従来どおり。

## 検証上の区別

専用Node／rendererの合成WAVによる接続・停止・保存確認と、実キーによるクラウド生成・実際の声質／遅延は別。実キー未設定の実装検証を、ゲーム内での実試聴成功として報告しない。最新の検証結果と未確認はCURRENT_IMPLEMENTATIONを参照。
