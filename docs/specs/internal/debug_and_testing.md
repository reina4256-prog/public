# デバッグ・検証支援仕様

状態: 実装済み

## 現在の実装仕様

- 育成画面で `Shift + D` を使い、統合デバッグオーバーレイを開く。
- システム・マップ・AI・放牧を選択的に初期化でき、初期状態では破壊的な項目を選択しない。
- 任意の師匠・Rank変更、特定職業履歴のRank 0リセット、能力、欲求、世代、年齢、時間、季節、無敵、姿、アイテム、Goldを操作できる。
- 闘技場WAVE、ダンジョン階、襲撃、防衛、復興、種族カットインを直接テストできる。
- TCGコレクションリセット、カジノ解放、カード取得、カード画像クロップ調整を支援する。
- タイトル画面エディターは姿の表示/非表示、種族フィルター、座標、拡大率、回転、クロップを調整する。
- カードアート調整は本番アルバムと同じ描画関数を使い、プレビューのために一時的に解放済み表示を生成してから実状態を戻す。
- AI調整画面の `CASTLE（城マップチップ）` は、城の6画像それぞれについて床・壁・室内装飾の切り取り定義を切り替え、画像、切り取り位置・範囲、拡大率等を調整する。変更は開いている城内マップへ即時反映し、`Shift + S` で `CASTLE_SPRITES` をコンソールへ出力する。
- AI調整画面の `BLACKSMITH（鍛冶屋マップチップ）` は、石床・石壁、3種の商品棚、炉・金床・素材置き場・冷却水場の9切り抜きを切り替え、画像、切り取り位置・範囲、拡大率等を調整する。石床・石壁は一マス全体、設備は切り抜き幅を一マス幅へ正規化して下端中央を足元にする本編と同じ枠をプレビューする。変更は開いている鍛冶屋マップへ即時反映し、`Shift + S` で `BLACKSMITH_SPRITES` をコンソールへ出力する。
- 統合デバッグの `施設初期マップ配置` は、通常セーブとプレイヤー向け自由エディットを変更せず、マイホーム、レストラン、鍛冶屋、城、カジノの制作者初期配置を共通画面で編集する。マイホーム・城・カジノは現行初期段階、レストランはLv1・Lv5・Lv10・Lv23、鍛冶屋はLv1・Lv10・Lv23の構造変化段階を扱い、全Lvの同一構造を重複表示しない。
- 統合デバッグの `鍛冶屋経営` は、所有している自分の鍛冶屋をLv1～30へ即時設定する。通常のLv到達処理と同じ1階40マス拡張、2階、地下1階、上位設備、自由エディット解放を適用して保存する。Lvを下げる操作では獲得済み設備と拡張済み構造を削除せず、現在Lv、経験値、現在Lvの評判上限だけを更新する。鍛冶屋未所有と範囲外入力は状態表示欄へ理由を表示し、セーブを変更しない。
- 鍛冶屋Lv1の制作者初期配置は、初回チュートリアル開始時と同じく設備0件で表示する。入口マーカーは左端を鍛冶師、右端をAIキャラクター、中央を通常客に割り当て、基本設備7種は左側パレットから必要に応じて配置できる。
- 施設初期マップ配置では、現行の切り抜き定義を使って床、壁、入口、設備・マップチップ、キャラクターと動線基準位置を表示する。各切り抜きは専用のクリップ枠で元画像の他領域を隠し、床・壁はマス全体、設備は一マス幅、パレットの縮小見本は切り抜き全体が収まる縦横比で表示する。マス配置、クリック／ドラッグ移動、追加、複製、削除、向き、前後順、階層、倍率、元に戻す／やり直す、制作者初期配置へのリセット、境界・入口・到達性の基本検証を行える。
- 未完成作業は通常ゲームセーブと分離した `facility_template_editor_draft_v1` だけへ自動保存する。`Ctrl + Shift + E` は選択中段階をF12コンソールへ整形済みJSONで出力し、画面ボタンは選択中または全施設をJSONファイルで出力する。出力データは表示用翻訳文を除外し、施設・段階・階層・タイル・画像・設備・キャラクターの言語非依存IDと座標を保持する。プレイヤーの正規初期配置へは自動適用せず、ユーザーが出力内容を開発側へ提示して確認後にコードへ反映する。
- デバッグ機能は通常セーブを意図せず破壊しないよう、対象と保存タイミングを明示する。
- `resetConciergeBeforeApprentice()` は手動デバッグ専用で、通常プレイからは呼ばない。コンシェルジュのランク・皆伝・受注中課題・一部屋内状態を消すが、次世代特別依頼の資格 `specialQuestEligibleGeneration.concierge` 等は保持するため、次世代ではリセット後も思い出クエストが先に提示され得る。完全な初対面・未修行セーブへのリセットではない。

### 保護テスト環境

- 統合デバッグの「保護テスト環境」から、通常セーブを残したまま再現条件を開始できる。
- 初回開始時は対象ゲーム進行を `IndexedDB` の専用領域へ退避する。テスト中は通常の `localStorage` キーをテスト状態として使うため、既存ゲーム処理と自動セーブをそのまま検証できる。
- テスト中は画面上部へ常時バナーを表示する。ブラウザやアプリを閉じて再起動しても、明示的に終了するまでテスト状態を継続する。
- 「テストを終了して通常セーブへ戻る」は退避データの存在を確認してから復元する。退避データが失われている場合は現在状態を上書きしない。
- 一つのテスト状態を「再開地点」として保存し、変更後に同じ地点へ戻せる。これは通常プレイヤー向けの複数セーブスロットではない。
- 条件切替は毎回、退避した通常セーブを土台に再構築し、前のテストで生じた状態を持ち越さない。
- チュートリアル専用履歴 `game_tutorial_archive_v1` も退避・復元し、テスト中に発生した初回解放を通常プレイの履歴へ混ぜない。世代をまたぐ通常時の保持方針は [`../core/tutorial_archive.md`](../core/tutorial_archive.md) が所有する。
- テスト中はクラウドセーブの送受信、酒場AI・オンラインデッキ公開、各ランキング更新、救助、フレンド送信、取引、TCGマーケットなどの外部書き込みを停止する。テスト退避マーカーを消すニューゲーム初期化も停止する。認証と読み取りは停止しない。
- 現在の冒険家プリセットは次の3件。
  - Rank 3開始: 木材・石を各0個、Rank 1・2通過時の最低想定能力に設定する。
  - Rank 3達成直前: 木材・石を各4個にし、5個目の取得と所持品正規化後のカウントを確認する。
  - Rank 8開始: 良質な木材・硬い石を各0個、Rank 1〜7通過時の最低想定能力に設定する。
- 全プリセットは冒険家へ弟子入り中、対象Rank課題を受注済み、`探検`・`森`・`山` を使用可能、体力・満腹度100、無敵OFF、晴天・昼、行動予約なしで始まる。森や山が現在マップにない場合はテスト側だけへ補う。
- 保護テスト中は、森・山の探検ドロップを `通常抽選`、`現在の冒険家課題素材だけ（確率は通常）`、`現在の冒険家課題素材を各階で確定（能力の壁は残す）` から選び、「保存して再開」で適用できる。Rank 3は森で木材・山で石、Rank 8は森で良質な木材・山で硬い石へ固定する。
- 保護テスト中は「実際の自律判断で『探検』を今すぐ試す」を使える。待機時間と行動抽選だけを固定し、本番の `performIdleAction()` へ1回限りの要求を渡す。`探検` の学習、冒険家資格、体力・満腹度、通常の目的地選択と開始処理は省略しない。結果は、予定追加、欲求不足、未学習、資格不足のいずれかでDebug画面へ残す。
- 冒険家プリセット適用時は前のセーブに残った余生ルートを解除し、自律探検テストが余生活動へ置き換わらないようにする。
- 統合Debugで変更した能力、欲求、時刻、Gold、無敵、探検ドロップ設定は「保存して再開」で実体の `aiPet` とローカルセーブへ反映する。0も有効な入力値として保存し、Debugを開いただけでは無敵状態を変更しない。
- `system.js` の起動時に、本体の `aiPet` とUI/Debugが参照する `window.aiPet` を同じ実体へ接続する。

## 検証経路

- JavaScript構文は変更ファイルごとに `node --check`。
- テキスト・Markdownを含む差分は `git diff --check` とリンク検査。
- 状態ロジックは必要に応じNode VMハーネスで実コード関数を読み込み検証する。
- `tests/blacksmith_business.test.js` は固定レシピ非移行、鍛冶師の入口来店、鍛冶師とAIキャラクターの会話、名称を出す前のAIマインド概念説明、基本設備7種が各 `○○がない時 → かえる` の保存前には置かれず保存後に置かれること、`つくる` / `うる` の学習、製作設備順、棚格納、来客・注文・会計・退店、鍛冶師退店、旧チュートリアルセーブと途中レイアウト退避の移行、追従カメラ計算、設備の一マス幅・下端中央基準、床壁の全マス描画、同一内容の画面ホストを再生成しないこと、キャラクター移動が静的マップを無効化しないこと、停止中の動的DOMを保持すること、開閉パネル入口、`resetBlacksmithTutorialState()` が経営成果を維持してチュートリアルだけを戻すこと、Lv5・複数階・配置検証、デバッグLv30による全構造・設備解放とLv1へ戻した場合の非破壊性を確認する。`tests/smithing_encounter_myhome.test.js` は育成画面側の鍛冶師初回遭遇5行動、マイホーム屋内での抑止、マイホーム移動より前の判定順を確認する。
- `tests/facility_template_editor.test.js` は5施設・10構造段階の初期データ、全段階の基本検証、鍛冶屋の入口開始位置、城の6人、カジノの6来客候補、切り抜き専用クリップ、一マス幅とパレット全体表示の使い分け、鍛冶屋AI調整プレビューの本編同一縮尺、翻訳表示文を除外する出力、通常セーブ非書き込み、統合デバッグ入口、コンソール／JSONファイル出力を確認する。
- 見た目・入力・BGMは `npm run start:web` またはElectronで実機確認する。
- `BROWSER_TESTING.md` にWeb、代替ポート、LAN、Electronの起動方法を記載する。

## 主な状態と実装

- `main.js`, `index.html`: 統合デバッグ入口と各操作。
- `blacksmith_map_core.js`: 鍛冶屋Lv変更の正規化、解放反映、保存、状態表示。
- `debug_test_core.js`: 通常セーブ退避、再現条件、再開地点、通常復帰、テスト中バナー。
- `facility_template_editor.js`: 5施設の初期配置アダプター、共通編集画面、分離下書き、JSON出力。
- `ui_controller.js`: UI、音楽館、カード画像調整等。
- `cloud_manager.js`: 保護テスト中の外部書き込み停止。
- 各 `feature_*.js`, `dungeon_*.js`, `tcg_core.js`: 個別デバッグ入口。
- `browser_server.js`, `BROWSER_TESTING.md`: Web検証。

## 他コンテンツとの依存関係

- デバッグ操作は対象コンテンツの正規状態初期化・正規化関数を優先して利用する。
- テスト用の解放状態を恒久仕様や通常進行条件として扱わない。

## 確定している将来仕様

- 新職業を追加するときは、師匠・Rank変更と状態リセットを統合デバッグへ追加する。
- 詳細仕様の修正時は、対象の境界条件を保護テスト環境の再現プリセットとして追加できる構造を維持する。
