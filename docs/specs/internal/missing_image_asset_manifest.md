# 追加機能・不足画像アセット制作一覧

状態: 一部制作済み・残件確定

監査日: 2026-09-12

## 目的

追加エディット機能、鍛冶屋屋内経営、水槽・池、魚画像、レストラン調理設備、マイホーム拡張について、現在の画像ファイルとスプライト登録を照合し、新規制作が必要な画像と既存流用できる画像を分ける。別AIへ画像生成を依頼するときと、次の実装チャットで仮画像・本画像の境界を判断するときの共通チェックリストにする。

機能仕様は各所有文書を優先する。この文書は画像制作対象だけを集約し、ゲーム挙動、解放条件、数値を重複定義しない。

## 現在の実装仕様

- 鍛冶屋屋内経営マップ用の提供済み3画像はゲームへ組込み済みである。
- 魚・水生生物18種の独立PNGは制作済みだが、魚種カタログへの画像登録、釣り・水槽・発見表示への組込み、実画面での縮尺・透過・向きの確認は未実装である。

## 共通制作基準

- 既存の屋内画像に合わせ、太い暗色輪郭、明確なピクセル、正面寄りで上面も少し見えるクォータービューにする。
- 生成元は設備・魚ごとの独立した透過PNGで保管し、ゲーム組込み時にアトラスへまとめる。最初から一枚のアトラスだけを生成しない。
- 画像へ日本語、英語、メーカー名、ロゴ、説明文を焼き込まない。
- 設備は原則として画像下側をAI・客が操作する正面にする。左右反転で対応できる差分は別画像にしない。
- 炎、湯気、水流、泡、回転、発光等は本体画像へ固定せず、必要に応じてコード側の演出レイヤーにする。
- 表の占有マスは画像制作時の構図目安であり、完成画像を実マップへ仮配置してから切抜き・縮尺・最終占有を確定する。
- 魚のシルエットは通常画像のアルファ領域を単色化して生成するため、別画像を制作しない。
- チュートリアル画像は既存画素材と本番レンダラーから実行時に合成するため、完成スクリーンショット画像を別制作しない。

## 優先度

| 優先度 | 意味 |
|---|---|
| A | 鍛冶屋経営マップ用画像。ユーザー提供画像へ切替済みで追加制作不要 |
| B | 仕様確定済み機能の初版に必要。鍛冶屋の後に制作可能 |
| C | 構造だけ先に実装できる、または詳細効果・家具内容の確定後に制作した方が安全 |

## B: 水槽・池本体

魚を設備の内部へ描き、ガラス・縁を魚より手前へ重ねる必要がある。このため各設備を、一枚の完成絵ではなく同じキャンバス・同じ座標の `背面／水面` と `前面枠／ガラス反射` の2レイヤーで制作する。淡水・海水の別画像は作らず、水レイヤーの色と環境表現をコードで変える。

| 管理番号 | 設備 | 数 | 目安占有 | 必要レイヤー | 制作要点 |
|---|---|---:|---|---|---|
| B-AQ-01 | 小型水槽 | 2 | 1×1 | 背面水槽内／前面枠・ガラス | 卓上または小型台付き。魚を1匹以上識別できる透明内部 |
| B-AQ-02 | 中型水槽 | 2 | 2×1 | 背面水槽内／前面枠・ガラス | 横長。小型との差が一目で分かる |
| B-AQ-03 | 大型水槽 | 2 | 3×1目安 | 背面水槽内／前面枠・ガラス | 複数魚を重ならず描ける大きな内部。将来の床・天井水槽とは分ける |
| B-AQ-04 | 小型池 | 2 | 2×2目安 | 底・水面／手前の縁・反射 | 中庭にも置ける自然石または施工済みの池。上面を十分見せる |
| B-AQ-05 | 大型池 | 2 | 3×3目安 | 底・水面／手前の縁・反射 | ヌシを収容できる広さを視覚化。小型池の単純拡大にしない |

合計は5設備、10レイヤーファイル相当である。画像生成側で完全に位置の合う2レイヤーを作れない場合は、完成見本1枚、前面枠1枚、内部領域の白黒マスク1枚を同じキャンバスで納品する方式でもよい。

## 新規画像が不要な追加機能

| 機能 | 新規画像が不要な理由 |
|---|---|
| タイトル画面自由エディット | 背景、ロゴ、5メニュー文字、図鑑解放キャラクターの既存表示をそのまま編集する |
| 島自由エディット | 現在マップ上に存在する地形・建物・自然物だけを並べ替える。未使用道路3種は初版対象外 |
| マイホーム自由エディット本体 | 既存床・壁・家具・椅子・テーブルを編集し、外周壁は既存壁から自動生成する |
| レストラン自由エディット本体 | 既存床、壁、家具、厨房、階段を使用する。新規画像が必要なのは前記14調理設備のみ |
| カジノ自由エディット本体 | `casino_mapchip.png` と `casino_game_mapchip.png` に床、壁、スロット、ポーカー、TCG、椅子がそろっている。階段は共通画像を使う |
| BGM自由選択UI | 既存音楽館UIを共通化するため、設備画像はCDプレイヤー1点だけでよい |
| チュートリアル再現画像 | 本番画面と既存素材を実行時合成する。説明文、矢印、枠はローカライズ可能なコード描画にする |
| 魚の未発見シルエット | 通常魚画像を単色化して生成する |

## 確定している将来仕様

- A・B優先度の対象と、新規画像を必要としない追加機能は初期実装範囲として確定している。制作済み魚画像も、魚種カタログ登録と実画面確認を終えるまでは組込み完了として扱わない。

## 構想段階の案

- C優先度の対象は機能の方向性だけを保持し、効果、取得条件、占有、外観が確定してから制作する。
