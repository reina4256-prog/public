# 基本ゲーム進行・育成仕様

状態: 実装済み

## 対象範囲

起動、新規開始、性格診断、AIキャラクターの基本状態、通常育成、寿命までのゲームループを扱う。進化と世代交代の詳細は `evolution_lifecycle_inheritance.md`、言葉とタスクは `ai_words_and_tasks.md` が所有する。

## 現在の実装仕様

- ゲームはクォータービューの島でAIキャラクターを育成・観察するブラウザゲームで、Electron/Steam版と通常ブラウザ版が同じソースを使う。
- 起動時はスタジオロゴからタイトルへ遷移する。タイトルには図鑑で解放した種族・進化形態が描画され、現在はY座標で奥行きを決め、ドラゴンは最前面になる。将来のプレイヤー向け自由配置は [`title_screen_editor.md`](title_screen_editor.md) が所有する。
- ニューゲームは性格診断と初期種族選択を通る。引継ぎで姿と性格を選んだ場合は診断を省略し、前世の基本形態と性格を使う。
- 基本能力は `intel`（賢さ）、`power`（活力）、`beauty`（美しさ）、`speed`（素早さ）。行動、職業課題、進化、闘技場、ダンジョンなどが参照する。
- 生存状態として体力、満腹度、機嫌、年齢、寿命、病気、過労などを持つ。通常行動で時間と欲求が進み、寿命到達で思い出生成と引継ぎへ進む。
- 現在の育成側満腹度は実質100を上限として扱い、個体別の最大満腹度を保持していない。ダンジョン探索中に成長した最大満腹度も帰還時には反映されない。
- 新世代開始処理は重病を示す `isSick` を解除するが、同じ `aiPet` オブジェクトの `conditions` を作り直さないため、風邪、腹痛、中毒が前世から次世代へ残り得る。
- チャット指示と性格に基づく自律行動が共存する。タスク中に体力・満腹度が危険域へ入ると、神モードを除き過労防止処理が中断する。
- 性格は能力の偏りから判定され、種族・進化形態ごとのセリフへ反映される。
- 腐った食べ物や生魚は病気の原因になり、病気は寿命や機嫌へ不利益を与える。薬剤師系の薬や特効薬で対処する。
- 共通ゲームシェルは上部ステータス、中央シーン、右側コマンドセンター、下部メニュー・チャットを持つ。島とマイホームを中央で切り替え、マイホームでも同じコマンドセンターと言葉一覧を使う。マイホーム限定フィルターや専用の退出ボタンは設けない。
- `game_shell.js` はシーンと停止トークンを管理する。収納、ドレッサー、作戦編集、進化・会話イベント、共通ログ等の排他的画面を開くと、屋内DOM・座標・経路を保持したまま背景の育成・移動・来客を停止する。最後の停止理由を解消するまで再開しない。フォーカスを最前面内へ制限し、閉じると元の操作要素へ戻す。
- 排他的コンテンツは専用更新処理を登録できる。背景更新の停止判定より前に、その画面だけが最前面かつ唯一の停止理由である場合に限って進める。追加モーダル・独立した停止理由・従来の停止フラグがある間は専用更新も止める。現時点の接続対象はマイホームのコンシェルジュ入門試験のみ。他施設への接続は各施設の移行時に行う。
- 停止時間を鮮度、来客の食事期限、マイホームの掃除対象生成周期、非表示タブからの追い付き時間へ加算しない。保存時も停止中の時刻基準を補正する。既存のレストラン・鍛冶屋シミュレーション入口も共有停止を参照するが、未移行屋内マップ自体を排他的画面とは判定しない。
- 共通クエストHUDは島・マイホームの中央画面右上に表示し、受注元をマイホームに限定しない。ログの保存と表示は [`ai_words_and_tasks.md`](ai_words_and_tasks.md) が所有する。
- 基本日課と不在精算を先行接続し、通常非表示中の重複フレーム進行を廃止する。日課・設定の表示中は共通停止を明示所有し、非表示になった時点から不在として扱う。対応範囲・未接続の付随効果・報告は [`ai_words_and_tasks.md`](ai_words_and_tasks.md) が所有する。
- 画面上部の `aiStatus` は800px幅の1行15列へ時間、天候、世代、年齢、欲求、能力、性格、称号を連結した特性、Gold、病気とバフを連結した健康状態を詰め込み、長い値は省略表示する。複数の病気・称号等をそのまま並べると内容を表示し切れない。

## 解放と主要な流れ

1. ロゴ、タイトル、新規開始または続きから。
2. 新規世代は性格診断または引継ぎ済みの姿・性格で開始。
3. 食事、睡眠、勉強、筋力訓練、ランニング、探索などで成長。
4. 師匠と遭遇し、1世代につき1つの職業を免許皆伝まで進める。
5. 条件を満たすと進化し、寿命後半は余生方針を選ぶ。
6. 寿命到達時に現在の姿を思い出化し、魂の引継ぎを選んで次世代へ進む。

## 永続状態とリセット境界

- 中心状態は `aiPet`。能力、欲求、年齢、現在姿、履歴、所持品、職業、言葉を保持する。
- `assets` は島の地形・施設・師匠拠点を保持する。
- 図鑑履歴と音楽館履歴は世代交代時に無条件で保持される。
- その他の能力、所持品、言葉、職業、姿・性格、マップ、Goldは引継ぎショップの選択に従う。

## 関連実装

- `main.js`: 初期化、ゲームループ、画面モード。
- `system.js`: 初期状態、性格診断、マップ、保存、音楽。
- `ai_core.js`: AI更新、状態、タスク、寿命、進化、引継ぎ。
- `view_renderer.js`: フィールドとキャラクター描画。
- `ui_controller.js`: 育成UIとコマンド。

## 確定している将来仕様

### 共通ゲームシェルと画面遷移

- 島・マイホーム・レストラン・鍛冶屋の中央表示と共有停止基盤は実装済み。経営施設は既存操作バーを中央領域に残す。個別仕様は [レストラン](../business/restaurant_business.md) と [鍛冶屋](../business/blacksmith_business.md) を参照する。カジノ・城・ダンジョンは未移行で、全施設の固有進行・復帰・保存の全面統合は未実装。

- 通常プレイ中は、画面上部の共通ステータス、中央のシーン表示領域、右側のコマンドセンター、下部の共通メニュー・チャットからなるゲームシェルを維持する。
- `育成画面 -> 施設 -> 屋内マップ` までは全画面へ切り替えず、中央のシーン表示領域だけを島マップ／各屋内マップへ差し替える。対象にはレストラン、鍛冶屋、マイホーム、カジノ、城、ダンジョンを含む。
- 屋内マップでは、施設ごとに重複しているチャット欄や共通操作ボタンを廃止し、ゲームシェル側の共通UIを場面に応じて利用する。施設固有の状態や操作は、右側のコマンドセンターへ場面別に表示する。
- 共通UIを表示し続けることは、すべての操作を全施設で許可することを意味しない。現在地で成立しない操作は無効化し、必要に応じてゲーム内UIで理由を示す。
- 屋内マップからさらに起動する管理画面、編集画面、ゲーム、戦闘、イベント等は、排他的な全画面コンテンツとして表示する。どの画面を排他的コンテンツとするかは各コンテンツ仕様で定義する。
- 排他的な全画面コンテンツの実行中は、そのコンテンツ固有の進行だけを許可し、ゲーム内時刻、加齢、体力・満腹度等の育成値、主人公・住人の移動とスケジュール、店舗営業、来客、環境・鮮度等を含む背後のシミュレーションを停止する。停止時間を不在・オフライン時間として後から精算しない。
- 全画面コンテンツを閉じた際は、起動元の施設、階層、座標、カメラ、選択状態等へ復帰する。施設から退出した場合にのみ島マップへ戻す。
- 全画面コンテンツの背後へポインター、キーボード、ゲームパッド入力を通さない。多重画面や入れ子のダイアログがあっても、最後の排他的コンテンツが終了するまで背後を再開しない。
- 実装では、屋内マップを閉じて作り直すのではなく一時停止して状態を保持し、共通のシーン管理と参照カウント可能な停止管理を使用する。個別の真偽値だけで停止・再開を管理しない。
- 全画面コンテンツ実行中の保存、強制終了、再開、結果確定／取消は各コンテンツの仕様に従うが、二重精算を起こさず、起動元の復帰情報を保持する。

- ゲーム終了中も実時間に応じて主人公の年齢と寿命を進める。繰り返し行動スケジュールが未設定でも加齢は停止しない。行動、欲求、店舗等のオフライン進行条件と上限は [`ai_words_and_tasks.md`](ai_words_and_tasks.md) が所有する。
- 加齢速度はゲーム起動中、起動中の非アクティブ、不起動中で同じ変換率を使う。初期値は現在の通常プレイ相当である実時間約72分につき1歳とするが、ハードコードせず一つの設定値から後で全体調整できるようにする。非アクティブ時だけ60fps換算にして加齢を速めない。
- オフライン経過中に `age >= lifespan` へ到達した場合も死亡・世代交代導線へ進める。具体的な精算停止地点、不在報告と引継ぎ画面の表示順は [`evolution_lifecycle_inheritance.md`](evolution_lifecycle_inheritance.md) が所有する。
- 育成側にも個体別の恒常的な最大満腹度を持たせ、食事、自然消費、表示、保存、スケジュール試算等は固定100ではなくその値を上限として使う。ダンジョンで成長した最大満腹度を帰還時に反映する境界は [`../dungeon/dungeon_common.md`](../dungeon/dungeon_common.md) が所有する。
- 世代交代で新しい主人公が始まるときは、引継ぎショップで何を選んだ場合でも、重病、風邪、腹痛、中毒等の前世の病気・症状をすべて解除し、健康な状態から開始する。病気は能力、持ち物、姿と性格その他の引継ぎデータへ含めない。
- 世代交代では集中、頑丈その他の一時バフも引継ぎ項目にかかわらずすべて解除する。任意のタイミングで使用した一時効果が世代交代で失われることはプレイヤー責任とし、次世代へ残すための例外を設けない。
- 複数病気や長い称号・特性を上部HUDへ全文横並びにしない。PC版の上部HUDは2段構成とし、1段目へ時刻、天候、世代、年齢、体力、満腹度、Gold、健康概要、2段目へ賢さ、活力、機嫌、美しさ、素早さ、性格、特性、称号概要を置く。モバイル版は体力、満腹度、健康等の生存情報だけを常時表示し、展開操作で残りを表示する。
- 上部の健康概要は、健康なら `🟢健康`、病気が1件なら病名と重症度、複数なら病気件数と重症件数、病気と一時効果が併存するならそれぞれの件数を短く表示する。押すと詳細を開けるようにし、病気を複数保持できるデータ仕様は表示幅を理由に制限しない。称号・特性も同様に短い概要だけを上部へ置き、全文は詳細で確認する。
- ステータス詳細画面は、基本能力、健康状態、人物情報、一時効果の4区分へ整理する。健康状態には全病名、重症度、原因、影響、自然治癒予測、対応薬、人物情報には性格、特性、称号、職歴、一時効果にはバフ・デバフと残り回数を省略せず表示し、上部HUDより詳しい情報の正本とする。
