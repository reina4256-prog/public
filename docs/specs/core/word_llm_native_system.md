- 回復時計：最初の取得で満杯から減った実時刻を回復開始とし、その60分後から1個ずつ補充する。不足中に二個目を採っても次回復時刻を後ろへ延ばさない。満杯になったら余剰時間を持ち越さず、次に減った時刻から再計測。同時刻の回復と取得は回復→取得の順。UTCの保存時刻差を使い、言語・タイムゾーン／半球変更では経過を変えない。回復はオンライン／留守中で共通、所持品への直接付与ではない。水は回復しても空の水筒がなければ採水できず、留守番の対象は初回は木材／石のみ。
- 計算例：一つの満杯の森で、移動時間を例から除いた場合、10分で木材1個、20分で2個取得。最初の回復は70分、次は130分で、採集完了はそれぞれ80分／140分。継続できれば8時間で約9個、24時間で約25個。実際は往復時間と候補地／在庫で変わる。複数の許可地点があれば本人の計画に従って回り、次の回復を待つだけより多く集まる場合がある。これらを最低保証／日別上限にはしない。
- 依頼と範囲：通常チャットで留守中／次に会うまでの採集を明示して依頼し、本人が引き受けるか判断する。一件だけ保持し、木材か石、任意の目標数量（正の安全整数）、出発点、本人が選ぶ候補順を原依頼とともに保存する。初回の候補は依頼時の既存の通常worldへ供給する最大6実chip内の到達可能な該当採集地だけ。「この森」ならその確認済み地点だけ、「知っている森」等の範囲依頼ならその候補集合だけを許可し、毎回の往復にプレイヤーの指示を要しない。未知の地点・道を追加しない。別の移動／採集／冒険家の未完依頼・会話中は新規開始せず、まず既存行動の終了／取消を明示してもらう。丸／肯定だけの依頼登録・出発は禁止する。
- 開始と取消：依頼は引受と保存が成功してから有効な予約となり、その本人の本編を離れるまで留守番としては進めない。本編からタイトル／別本人へ移った時・正常終了時を離席境界として保存する。入力待ち、一時停止、日記／星座の閲覧や一時的な画面非表示だけでは留守番へ切り替えない。突然終了は最後に確実に保存できた本編活動時刻を基準にした目安とし、終了時刻を断定しない。プレイ中の活動時刻checkpointは既存の約10秒保存と終了／切替保存で更新する。目標に達した場合は現在の往復を帰還して終了し、余分な取得をしない。取消は以後の作業を止め、実位置と既取得品は保持する。新しい依頼で旧計画を黙って上書きしない。
- 再開時の途中状態：一個の採集10分が完了した時点で資源を減らして現物を取得する。移動途中の座標／残経路、採集途中の秒数は保持し、未完の一個は取得しない。取得済み品は現行採集と同様に取得時点で本人の所持品へ入り、未帰還でも失われない。再開するとその時点で自動周回を止めて実状態を表示し、本人は「集めた数／帰還済みか／途中か」を正しく報告する。続行／帰還は後続の明示指示を必要とし、その入力だけで通常の短時間採集へ変換せず、留守番計画の再予約と通常採集を区別する。途中作業の破棄を伴う別移動等は計画の取消として記録し、既取得品を消さない。
- 長期放置と保存：回復・採集・往復を時刻順に評価し、秒ごとの描画や生成を閉じていた分再演しない。同値の周期はイベント時刻へのジャンプや集計で計算する。長い不在の成果を黙って時間上限で捨てない。物理的な保存／数値限界に達した場合は安全に止め、未清算範囲を明示する。各取得には一意の証拠とIDを持ち、旧品／spent・贈呈の原履歴を保持し、回復しただけで旧取得IDを再使用しない。結果と清算済み時刻を同じ原子的保存に含め、再開連打／別セーブ切替／失敗した書込で二重取得しない。旧セーブの初回接続時は旧の残採集数をそのまま初期量とし、導入時刻から回復を開始、過去の不明な取得日時や導入前の放置報酬を補作しない。時計逆行では回復も成果も加算せず、既存の基準を後ろへ戻さない。

#### 会話と育ちの案

- 原発言、本人の受け取り方、ゲーム内の実体験を区別して保持する。「ご主人様がそう教えた」と「自分で確かめた」を同じ事実へまとめない。LLMの要約や解釈には元の入力／実イベントを紐付け、生成返答を根拠へ循環させない。
- 一般知識を使って話せることと、本人がその場所・対象・仕事を知っていること、できることを区別する。LLMへ渡せる本人知識と、未知のことをどう扱うかは育ち方の設計として詰める。一般知識の存在だけで能力や実績を与えない。
- 名前や説明は出所付きの「教わった内容」として記憶更新候補にできるが、全発言を命名へ変換しない。訂正は元の教示・受け取り方を残して新しい版を加える案。確信度の数値や習得条件は未決定で、件数だけの確定は採用しない。

#### LLMとゲームの分担と送信の相談

- LLMは自由文理解、返答、次にしたいこと、受け取り方／記憶の候補を提案する。ゲームは原資料・実世界・本人の実績を管理し、根拠ID・対象・許可操作・状態の版・現在の成立条件を検査する。意味理解を旧パーサで再判定することを必須にせず、機械的に検査できない解釈の誤りは別に残す。
- 発話と行動を一つの提案へ関連付け、意図・開始・完了を分ける。拒否された行動について成功文を出さない。失敗時の表示方法は未決定で、整合のために毎回二度目のLLM呼出を必要とする構成にはしない案。原返答の書換方式も合意後に決める。
- 次に相談する送信候補は、最新原入力、本人の名前／一人称／呼び方、有限の直近会話、出所付きで選んだ記憶、本人が観測できた自己状態、試作で許可する行動と条件。これは新システム用の候補表であり、[現行比較版](word_llm_reply_comparison.md)の送信許可から継承済みと扱わない。原文ノートやセーブ全体を自動供給しない。
- 特に、対象の見た目・所在・呼び名、仕事・味・移動先などの体験詳細、実行可能な行動一覧／条件も世界情報を伝え得る。許可項目・取得元・量・未知情報を含めない条件を具体化して相談するまで送信しない。地図全体・隠し正解・未解放情報は初期試作の供給候補に含めない。記憶の選択方法・上限・直近会話に含める生成文の扱いも未決定。
