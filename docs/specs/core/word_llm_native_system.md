# LLM中心の新システム

## 現在の実装仕様

### 採集依頼と会話で開閉する所持品（2026-11-25）

- 本人が具体案へ「はい、その範囲で実装をおねがいします」と承認。新しい出会いの提案を、材料を探して持ち帰り見せる依頼へ変更する。本人は参加／見送り／自由チャットでの相談を判断する。既存セーブの途中の観察練習は元の段階と内容を保ち、過去の観察・台詞から所持品を遡って取得しない。
- 森は木材、山は石。実chipごとの採集対象は固定二個で、各chip IDと0／1に結びつく個体IDを使う。二回の現地探索で各一個まで取得し、同じ現物の二重取得・起動／中断再開による補充は行わない。現地で六秒探す動作と周囲を探す表示を経てゲーム側が取得・保存し、その後に本人がプレイヤーへ発見を話す。採り尽くした場合は取得なしを伝える。架空の道・木の実や、生成文からのアイテム作成を復活させない。
- `game.inventory`の現物列は品種・元chip・依頼ID・探索回・取得時刻を保持する。所持数は現物列から数え、探索の実観察記録と照合して保存を検査する。冒険家への実帰還報告後も品物は手元に残し、納品消費はしない。セーブ／本人ごとに分離し、途中の取得・所持品画面の開閉状態も保存する。
- 所持品画面は品名と数を表示し、「インベントリを開いて」「道具をみせて」等の通常チャットの明確な依頼から開く。「閉じて」「しまって」等で閉じる。検査済み原文引用付き`inventoryView`だけを適用し、質問・否定・教示・引用・肯定だけや生成返答の文面から開閉しない。直接の開閉ボタン、外側クリック、Escapeによる開閉は置かず、画面表示中もチャットできる。七言語の表示・入力境界を使い、プレイヤー原文や保存識別子は翻訳しない。
- 提案→本人判断→現地の探索／発見発話二回→冒険家への帰還報告→返答の最大6生成／6音声を維持する。既存の二つの観察slotを使い、取得のための追加生成や自動反復・再送は行わない。探索発話とその読了・声の終了を待ってから現地移動／帰路へ進む。提案／返答の相手は本人、発見発話はプレイヤー、帰還報告は冒険家。全文と既存の自動文字／文送りを保持し、台詞のない吹き出しは非表示にする。
- 承認された追加送信は、既存context1200文字／会話込み4000文字の枠内に依頼品種・目標数・今回取得した数と各探索回の取得有無を加える範囲。通常チャットには木材／石の所持数と所持品画面の開閉状態を限定供給し、既存一返答で開閉意図を扱う。冒険家へ全所持品・全資源配置／経路座標・他の記録を追加しない。通常の自由採集指示はまだ実行せず、今回の依頼内の取得だけを接続する。保存からの自動再開・生成開始条件は前節の承認範囲を保持する。
- 物の使用・装備・売買・納品消費・戦闘・技能報酬へは進めない。丸／肯定だけの移動・参加・再開・学習禁止、生成文から知識／技能／実績を取得しない条件、日記／星座・育ちB・旧版／比較版・本人／声／原文ノート、予算／追加クレジットOFFと他全保留を保持する。以下の旧節の採集未接続・観察専用の制限は今回の依頼に限り置換する。検証・本人試遊・発行はCURRENT。

### 有声の挨拶・段階表示と自動文送り（2026-11-25）

- 本人が、声と文字が自然に流れる会話、および新しい実到着・出会い動画終了後の最初の自動生成を承認。新しい歩行指示をこの起動中に受け、実際に到着した遭遇だけ、一度限りの自動開始対象にする。初対面は動画終了／スキップ後、再会は窓が開いた後に既存offer一回を開始する。保存済みの到着・途中歩行・動画／会話を起動し直しただけでは自動生成・声を開始せず、既存の明示操作を待つ。失敗／取消から自動再送しない。
- 冒頭の文字だけの定型挨拶を新しい自動会話には置かず、挨拶と短い提案を既存offer一台詞に含め、その全文を既存の冒険家の声で一度読む。既存metを根拠にした初対面／再会の区別一項目をofferのcontextへ追加し、1200文字・会話込み4000文字枠内に収める。初対面なら確定personaに沿う短い自己紹介、再会なら保存済みの実会話に沿う声かけとし、例示された島の謎／任務等を新設定として採用しない。従来の最大6生成・6音声、台詞300文字を保持する。
- 原台詞一件の音声を途中で分割・再生成せず、復号した音声の長さと再生時計に合わせて文字を一文字単位（結合文字・絵文字は一まとまり）で増やす。文字ごとの発音時刻は供給されないため、厳密な発音位置の同期ではなく、全文音声の長さを使う表示。既存の文／長い節の区切りで短い間を置き、自動で次ページへ進む。音声が極端に短くても最低の表示時間を確保する。音声OFF／取得・再生失敗時も文字速度と読了猶予で自動送りする。
- 台詞末尾の表示と読了猶予・声の終了を両方待ってから、次の本人判断／台詞／実移動へ進む。手動文送りボタンは不要とし、全文は既存の振り返り・会話欄・保存済み原台詞へ残す。終了／中断／非表示・画面／本人切替ではアニメーションと声を取り消し、遅延更新を採用しない。プレイヤーへの相談は普段の自由チャットで本人の回答を待つ。旧互換三往復は既存の生成開始操作を維持し、一台詞内の表示だけ自動化する。
- 以下の初回実装にある「到着自動生成なし」「末尾のつづけるで読了」は本節の範囲で置換する。通常歩行・丸／肯定だけで移動・参加・再開・学習しない条件、生成文から知識／技能／実績を取得しない条件と他全保留を維持。観察供給の拡張・採集／戦闘／技能報酬・追加クレジットは追加しない。検証・本人試遊・発行はCURRENT。

### 探検の表示・向き・会話相手と文送り（2026-11-25）

- 初回の五点は表示・向き・聞き手・発話と探索段階の同期・文送り。開始／挨拶／読了操作は同日後続の「有声の挨拶・段階表示と自動文送り」で更新し、最大6生成と送信上限を維持する。空の吹き出しは表示しない。
- 通常歩行・探索往路・現地移動・帰路の実経路の次の異なる地点から左右の向きを決め、縦移動では直前の左右向きを保持する。探索窓の人物にも同じ反転を適用する。旧版の窓は既存描画のまま。観察中／台詞待機中は歩行アニメーションにしない。
- 聞き手は、提案／返答が本人、参加／見送りの返事が冒険家、相談がプレイヤー、独り言は相手なし、帰還報告が冒険家。プレイヤー呼称を冒険家の呼称に流用しない。二回の限定観察を広範な探索へ言い過ぎず、実記録にない具体物を補わない。送信する情報項目は増やさず、生成指示で区別する。実台詞の自然さは本人試遊で確認する。
- 観察イベント後は該当独り言の生成まで実移動を待ち、表示・文送り・既存の声の終了まで世界の進行を待つ。帰還前の独り言は現地からの次の意向として扱い、帰路へ先行しない。帰還結果がある時だけ報告する。既存slotの送信時点の実段階をそろえる変更であり、送信開始条件の拡張ではない。
- 台詞は表示時だけ七言語の文境界で分割し、長い一文は節／語の区切りを優先して短く送る。長い一語は文字単位の最終分割とし、元の全文は変えない。文送り／読了は後続の自動表示節に従う。音声は原台詞一件につき従来の一生成・一再生で、ページ送りで再生成／再送しない。全文は既存の会話振り返りと通常会話欄・保存済み原台詞に残す。終了／中断は読了待機も解除し、再開だけで読み上げ直さない。
- 観察供給の追加、採集／戦闘／技能・報酬、他全保留を進めない。生成内容から知識／技能／実績を取得せず、丸／肯定だけで移動・参加・再開・学習しない。日記／星座・育ちB・旧版／比較版・本人／声／原文ノート・予算／追加クレジットOFFは既存どおり。検証・本人未受入の区別はCURRENTへ記録する。

### 冒険家の探検練習と本人の参加判断（2026-11-24）

- 本人が送信・保存・生成回数を含む一単位を承認。冒険家が実際の森／山での短い現地探索と帰還報告を提案し、別の生成で本人が参加・見送り・プレイヤーへの相談を判断する。本人には空腹／疲れ、実際の観察／移動経験、目的地・往復可否と提案を渡す。判断できない時は普段の自由チャットで尋ね、プレイヤーの回答を生成して補完しない。選択／歩行ボタンは追加しない。
- この練習に限り、本人の明示した参加判断を根拠に、実対象と実地往復経路をゲームが検査して自主的に出発・探検・帰還する。通常チャットの自由歩行の「丸→一致確認→後続指示」は変更しない。丸やプレイヤーの肯定単独では練習の参加／再開を採用しない。相談への明確な参加依頼・中断後の明確な再開依頼だけを、原文引用付き`practiceChoice`で検査する。体調不足（空腹／疲れが0.8以上）、経路不成立等は実行を止め、生成文で安全条件を上書きしない。
- `native_practice`のゲーム状態はセーブ内`game.practices`に独立保持する。元の冒険家到着ID／対象、帰還地点、実対象とgraph上の往復・現地の小さな巡回、観察待ち、段階、実結果、生成済みslotと原台詞を記録する。実到着後は二地点で各6秒の観察と実移動を行い、帰還地点へ実際に戻った結果の後だけ報告・師匠返答へ進む。地形／経路の検査に既存ground／road graphを使い、架空の道・木の実・取得物は作らない。旧15階層・採集・戦闘・職業資格・能力報酬は接続しない。
- 現地探索中は`view_renderer.drawActionWindow()`を直接流用し、旧300×200窓の森／山背景と当人の動作を描く。提案・本人判断・帰還報告／返答は既存の師匠窓で双方の姿と台詞を表示し、独り言・相談は普段の会話欄と吹き出しへ残す。提案後の本人判断、参加後の独り言・報告／返答に追加の選択操作は要求しない。初回は従来の出会い動画。新規到着での開始と声／文送りは2026-11-25の「有声の挨拶・段階表示と自動文送り」に従い、保存からの再開だけでは自動生成しない。
- 既存CLIに提案・本人判断・状況の独り言最大2回・本人報告・師匠返答の最大6生成を行う。slotを送信前に保存し、先行生成・自動反復・自動再送はしない。追加状況は目的／段階／実対象・往復可否・空腹／疲れ・限定した実体験／実結果を最大1200文字、直近の会話記録と合わせる追加枠はJSON構造を含め4000文字以内。古い会話を送信枠から外しても原台詞は保存する。全map／経路座標列・日記・署名・過去のプレイヤー会話を冒険家へ追加送信しない。相談への応答はプレイヤーの入力ごとに既存通常CLIで生成し、師匠にはその原入力を追加供給しない。
- 音声は最新の保存済みslotだけをmainが取得し、その台詞と既存話者声だけを送る。最大6台詞、追加の作成声登録は行わない。失敗時も文字を保持する。中断・終了・非表示・別画面・セーブ切替は生成と再生を取消して停止／保留し、遅延結果を採用しない。進行済みの観察と位置を保存し、再起動では停止状態へ復元する。再起動だけでは生成・音声再生・オフライン探検をせず、明示した再開を待つ。消費済みの失敗／取消slotを自動再送しない。
- 師匠の応答は実結果に基づく会話であり、生成文から知識／技能／課題達成／実績を自動取得しない。既存の日記／星座・育ちB・旧版／比較版・本人・声設定・原文ノートと全保留を保持する。CLI追加クレジットOFF・月1000円設定／自動補充OFFを維持し、アプリが厳密な円上限を保証する仕組みを追加したとはしない。旧3往復会話と保存記録は互換のまま保持する。
- 所有：root `native_practice`が実地進行・検査・限定状況、main `native_practice`が単独話者protocolと送信上限、`native_store`が送信前／返却前保存・取消・権限ゲート、`native_mentor_ui`と`native_scene`が既存窓／会話／描画の接続、`native_runtime`が通常チャットの当時snapshotと相談の引用検査、`native_voice`がmain確定台詞の音声を所有する。実装検証と本人の試遊はCURRENTを参照。

### 冒険家との会話の保存と振り返り（2026-11-24）

- 本人が追加送信・保存範囲に「この範囲で実装する」と回答。成功した冒険家との原会話を、実到着ID・対象chip・話者とともにセーブごとの`mentorConversations`へ保存する。一回最大三組六発言・各300文字。追加生成で要約せず、再起動でも保持し、別セーブとは共有しない。以前の「窓を閉じると全台詞を破棄」は本節で置換する。窓内の再生用状態は引き続き終了で破棄する。
- 通常チャットへ直近一回の最大六発言1800文字を`mentorConversation`として追加供給する。入力時点の原会話を当該turnへsnapshot保存し、後から得た会話を過去の供給へ混入させない。冒険家との再会時は同じセーブの直近一回を`previous`、今回の直近六発言を`recent`として供給する。台詞合計最大3600文字、ID等とJSON構造を含む追加枠4000文字以内。上限を超える際は以前の会話の古い組から送信対象を外し、原記録は保持する。古い会話全体が毎回モデルへ渡るとは保証しない。
- 会話が行われた事実と実台詞を根拠に、通常チャットで振り返り、再会では続きとして自然に話す。過去の「会わなかった」という誤返答より実会話記録を優先する。台詞内の主張は未検証の発言であり、指示・事実・習得知識へ昇格させない。生成会話から知識／技能／課題／実績、日記／星座の学習根拠を自動追加しない。プレイヤーとの通常会話・日記・署名・全mapを冒険家へ追加送信しない。追加の要約生成／先行生成／自動再送は行わず、既存CLI追加クレジットOFF・月1000円設定／自動補充OFFと他全保留を保持する。
- mainは成功pairをセーブへ原子的に保存してから窓へ返す。保存失敗では会話を止め、失敗／取消・閉じた窓への遅延結果を記録として採用しない。旧セーブは新項目なしで読める。既存ローカル`native-playtest.jsonl`にのみ残る直近会話は、同じ保存済み入力packet・成功result・実到着receiptが完全一致し、同じ本人・一意の連続した会話組を照合できる時だけ起動時に復元する。壊れた／16MiB超のログ、不一致・曖昧な記録は移入しない。原ログ／過去turnは書き換えず、新しいセーブ保存には既存backupを使う。復元／再起動だけではモデル／TTSを呼ばない。
- 所有は`native_runtime`（原会話検査・保存形・当時snapshot・通常packet）、`native_store`（保存後の返却・取消・セーブ分離）、`native_mentor`（再会packetと上限・旧ログ照合）、`native_electron`（同端末の旧ログ読出の接続）。窓・声・歩行の実行条件は既存のまま。検証・本人受入・発行はCURRENTを参照。

### 実chipへの歩行と冒険家との出会い（2026-11-24）

- 同日の追加試遊後、本人が「誤説明の修正と、確認後の案内」を不自然にならない範囲で優先するよう依頼。歩行対応worldを受ける返答指示では、歩行は実装済みであり過去返答の未接続説明より現在の規則／状態を優先する。`confirmed:null`は対象未確認で、`walkable:false`や空の行動一覧を歩行機能全体の欠落と説明しない。確認済みでも可否が偽なら表示範囲／経路を確かめる状態とし、実結果なしに到達不能を断定しない。過去の誤説明を問われた場合は短く自然に訂正する。

#### LLMとゲームの分担と送信の相談

- LLMは自由文理解、返答、次にしたいこと、受け取り方／記憶の候補を提案する。ゲームは原資料・実世界・本人の実績を管理し、根拠ID・対象・許可操作・状態の版・現在の成立条件を検査する。意味理解を旧パーサで再判定することを必須にせず、機械的に検査できない解釈の誤りは別に残す。
- 発話と行動を一つの提案へ関連付け、意図・開始・完了を分ける。拒否された行動について成功文を出さない。失敗時の表示方法は未決定で、整合のために毎回二度目のLLM呼出を必要とする構成にはしない案。原返答の書換方式も合意後に決める。
- 次に相談する送信候補は、最新原入力、本人の名前／一人称／呼び方、有限の直近会話、出所付きで選んだ記憶、本人が観測できた自己状態、試作で許可する行動と条件。これは新システム用の候補表であり、[現行比較版](word_llm_reply_comparison.md)の送信許可から継承済みと扱わない。原文ノートやセーブ全体を自動供給しない。
- 特に、対象の見た目・所在・呼び名、仕事・味・移動先などの体験詳細、実行可能な行動一覧／条件も世界情報を伝え得る。許可項目・取得元・量・未知情報を含めない条件を具体化して相談するまで送信しない。地図全体・隠し正解・未解放情報は初期試作の供給候補に含めない。記憶の選択方法・上限・直近会話に含める生成文の扱いも未決定。
- 本人の記憶と送信記憶を分け、保存しているからすべて送るとはしない。ゲーム側で今回何を供給したかを記録する案。モデルへファイル・シェル・保存の直接操作権を渡さず、既存契約枠と追加課金禁止を維持する。
