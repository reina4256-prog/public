### 実チップの確認・保存停止修正・事前起動（2026-11-22）

- 保存時の歴史検査は、各turnまでの原資料だけでpacketを復元する。後の発言で検索候補が入れ替わっても、当時の正しいreferencesを不正扱いしない。当時worldは保存snapshotのまま使い、引用・未来の出所・未供給参照等の検査を緩めない。`native_store`は整合／サイズ／I/O等の理由と失敗段階を私用診断に分け、完了保存失敗では検査済みの未保存結果も診断に残す。保存不能なら送信・進行を止め、成功と偽らない。再起動時のpending原文保持・failed化は継続し、自動再送しない。
- ユーザーが具体的な送信範囲を承認。外部worldは従前の2000文字以内で、現在画面内に描く実チップ最大6件のID・登録済みの種類／見た目・画面内x/y/width/height（0〜1）と、確認中の対象IDを含む。現在地・状態と直近実観察最大3は維持する。画面は固定800×480の同じカメラで照合する。foregroundの実チップを近い順に優先し、なければ実地面／水面等を候補にし、枠を越える場合は件数を減らす。全map・asset画像・資源数・職業活動・未表示領域・全履歴の一括供給はしない。登録された「山／森／建物」等は絵の説明であり、住人・仕事中・入れる建物・食べ物や能力の証拠にしない。
- 新`native_perception.js`が実chip抽出／限界／観察／focus検査を所有する。新gameは`perception:2`。新本人に架空のberry/path/shade観察を作らず、既存本人の旧gameはバックアップを伴う通常保存で移行する。旧turn・原文・呼称・島assets・過去receiptは削除せず、合成目的地への途中移動／食事／休息は止め、route／destinationを解除する。この単位の新しい行動提案はaction=null、availableActions=[]。旧walk/eat/restの検査・実行コードは旧保存・歴史検証の互換用に残すが、新試遊から呼ばない。資源補充や空腹／疲労の進行もこの確認単位では進めない。
- LLMは`focus:null`または`{targetId,quote}`を提案し、quoteは今回原入力の完全一致部分、targetIdは今回供給した実chipに限る。ゲーム検査後にその実chipの描画範囲を一つだけ丸で囲み、本人が「この場所のこと？」等の自然な会話で確かめる。常設丸・架空の物体／道・対象名札・確認ボタンは出さない。確認中IDを次の入力へ渡すが、新入力受付で古い丸を消し、新しい正当なfocusだけを表示する。丸・肯定返答だけで移動・学習・技能・実績を与えない。見えていない対象へのfocusや引用不正は棄却する。
- 絵日記の紙面／手書き文字・絵上／本文下・縦横／続き頁・根拠閲覧は保持し、新しい本文／絵は実chipの観察を使う。絵は同じassetの実描画部分を紙面用の単色にし、架空の木の実／道を描き足さない。旧合成行動のreceiptは「過去の試作の記録」に分けて保持し、今回の現実世界の観察へ読み替えない。星座の新しい実観察ノードも実chipとし、過去の架空食事から甘い関係を新規に付与しない。原教示候補の短語／引用・未確認の区別は維持する。
- 速度は以前の条件を揃えて比較するユーザー依頼に従い、`npm run start:word:native -- --fast-trial`でnativeランチャーの子プロセスにだけHydrogen Lowを渡す。明示WORD_GEMINI_MODEL指定を尊重し、通常起動のモデル既定・CLIの恒久settings／旧版のモデルは変えない。`native-warmup`は引数なし・既存と同じsender/frame検査付きで、空の1回使い切りCLIを最大1件だけ準備する。本人／下書き／履歴は送信まで渡さず、無意味なwarmup生成もしない。開始／表示復帰／入力開始／返答後／停止解除で準備し、停止・非表示・閲覧への移行・終了で未使用準備を破棄する。生成中は別準備を増やさず、固定の待機秒数を入れない。追加クレジットOFF／tool deny／最終JSON・出所検査は維持する。
- native結果の私用診断に要求モデル・helperのspawn/init/初本文/result/終了等・事前起動利用と送信前初期化の有無・main受信／保存までの時間を記録する。本文の途中を表示して検査を省かず、5秒の保証ともしない。合成の同一packet・同一モデルの通常3件／事前起動3件で比較し、本人試遊・DOM描画・通信内側の保証と区別する。

### 旧第1版の流れと境界（世界なしの履歴）

- `experimental_word_llm_native.js`が原入力turn、packet作成、LLM提案の検査・確定、保存形式検査を所有する。`native_store.js`が安全な保存とmain側session、`native_window.js`がmain frame／送信元／URL検査付きIPC、`native_electron.js`が専用保存先・既存認証を使う接続、専用UIが会話・日記・星座を所有する。旧解析・全文共起・旧日記担当群を理解入口へ使わない。
- rendererは原入力と選択言語をmainへ渡す。mainが本人設定と保存原資料からpacketを作る。外部送信は入力4000文字まで、本人の名前／一人称／呼び方各100文字まで、直近最大6発言・各1200文字まで、選んだ原発言＋当時の受け取り方最大12組・合計8000文字まで。場所／周囲対象／地図／仕事／自己状態／実体験／行動一覧／旧本人情報は供給しない。
- 記録選択は直近4件を優先し、原入力の文字二連続の共通と新しさで12件まで選ぶ。これは送信する記録の検索であり、意味理解や学習の判定ではない。原文＋受け取り方が残予算に収まる組だけを新しい順に採り、送信は時系列順。原文を切断せず、直近会話も1200文字超のplayer入力を含む組は省く。原発言の保存自体は削らない。
- LLMは一入力一回で返答、解釈kind／summary、今回の原入力に紐付く引用付き教示候補、供給済み原資料の参照申告を返す。返答は1200、解釈は600文字まで、教示候補は3件まで（引用1000／内容600）。kindはteaching／correction／question／request／social／unclear。教示候補はteaching／correctionだけ、sourceIdは今回turn ID、quoteは今回原文の実部分文字列を必須とする。過去参照は実際に供給した原発言IDだけを許可する。
- ゲームが形式・余剰field・長さ・引用・出所・revisionを検査してから保存し、保存成功後に表示する。返答文を引用元や教示取得証拠にしない。保存する教示は「本人が教わった未確認の内容」であり、実確認・能力・実績ではない。訂正は新しいturnで別保持し、以前の原文や当時理解は書換えない。意味的に正しい分類や要約であることまで機械検査が保証するとは扱わない。
- 接続には既存`gemini_reply.createResponder`の内部protocol adapterを使い、返答専用のdefault protocol／prompt／上限は維持する。追加クレジットOFF・全tool deny・shellなし・単一SUCCESS／exit code検査は共通。構造出力は最大9000文字のJSONとし、非JSON・不正出所等は提案全体を棄却する。失敗・quota・中止では記憶候補を採用せず、原入力だけ残す。旧解析へ黙ってfallbackしない。初回版では事前起動を追加せず、入力確定後に接続する。
- 自分の発言に基づく記憶更新、世界行動、実体験の取得、性格・能力・進化値の変化はこの単位に含めない。教示を試す判断へ使い実結果を加える第2単位は試遊後に相談する。

### 旧第1版の日記・星座と検証記録（試遊で不採用）

#### LLMとゲームの分担と送信の相談

- LLMは自由文理解、返答、次にしたいこと、受け取り方／記憶の候補を提案する。ゲームは原資料・実世界・本人の実績を管理し、根拠ID・対象・許可操作・状態の版・現在の成立条件を検査する。意味理解を旧パーサで再判定することを必須にせず、機械的に検査できない解釈の誤りは別に残す。
- 発話と行動を一つの提案へ関連付け、意図・開始・完了を分ける。拒否された行動について成功文を出さない。失敗時の表示方法は未決定で、整合のために毎回二度目のLLM呼出を必要とする構成にはしない案。原返答の書換方式も合意後に決める。
- 次に相談する送信候補は、最新原入力、本人の名前／一人称／呼び方、有限の直近会話、出所付きで選んだ記憶、本人が観測できた自己状態、試作で許可する行動と条件。これは新システム用の候補表であり、[現行比較版](word_llm_reply_comparison.md)の送信許可から継承済みと扱わない。原文ノートやセーブ全体を自動供給しない。
- 特に、対象の見た目・所在・呼び名、仕事・味・移動先などの体験詳細、実行可能な行動一覧／条件も世界情報を伝え得る。許可項目・取得元・量・未知情報を含めない条件を具体化して相談するまで送信しない。地図全体・隠し正解・未解放情報は初期試作の供給候補に含めない。記憶の選択方法・上限・直近会話に含める生成文の扱いも未決定。
- 本人の記憶と送信記憶を分け、保存しているからすべて送るとはしない。ゲーム側で今回何を供給したかを記録する案。モデルへファイル・シェル・保存の直接操作権を渡さず、既存契約枠と追加課金禁止を維持する。

#### 最小試作の相談案

- 別起動・別保存の架空本人、文字入力、原則一入力一生成。対象教示の曖昧さを試せる小さな場面と、休息一種類の実行を候補とする。旧本人のコピーや既存世界全体への接続を前提にしない。日記・星座を試作に含め、会話だけ完成して両機能を後回しにしない。
- 前記3例に加え、「教示の訂正」「曖昧な対象」「行動できない状態」「生成失敗／古い提案」を確認する案。日記では教示と実体験の区別、星座では供給記憶／申告参照／実結果の区別、保存再開では出所と訂正の保持を確認する。合格基準は採用範囲確定後に詳細化する。
- 先に外部送信なしの固定応答で記録・検査・両表示・保存を検証し、その後、送信項目の合意を得た範囲だけ既存契約内の実モデルで会話品質を確かめる案。固定応答の成功をLLMの理解品質や実接続の成功とは扱わない。試作成功を既存の職業・探索・ダンジョン対応の完了ともしない。
