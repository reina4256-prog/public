# LLM中心の新システム

## 現在の実装仕様

- 2026-11-21時点では方針合意のみで、新システムは未実装。既存のLLMなし版と[Gemini応答比較版](word_llm_reply_comparison.md)の起動・保存・動作を今回変更しない。現在遊べるGemini版を新システムの実装済みと扱わない。

## 確定している将来仕様

- 2026-11-21ユーザー採用：本人の育ち方はBを軸にする。LLMで自由文を理解し、本人が語る知識は本人が教わったこと・体験したことを中心にする。一般知識で広く会話するAを基本方針にはしない。これは育ち方の方向の採用であり、初期知識、推測・一般知識の許容範囲、教示から行動への採用条件、記憶形式・表示・送信・試作の具体案まで一括採用したものではない。LLM内部の知識を消去する保証とも区別する。
- 2026-11-21ユーザー採用：「新システム（旧版はそのまま比較版として残す）」は、「既存版へのLLM追加から、LLM中心の構成を設計し、必要な既存部品を選ぶ進め方へ切り替える」。新システムの設計はこの方針で進める。旧版を維持することと、新システムで旧版の仕組みを必ず使うことを区別する。
- 旧版はそのまま比較用に残す。新システムのために旧版の実装や本人・声設定・教わった原文ノートを削除・上書きしない。既存部品は新システムでの役割と必要性から再利用・置換・不採用を判断し、従来の自由入力解析・仮学習・日記処理の存続を目的にしない。
- 2026-11-21ユーザー追加指定：LLM中心の新システムでも「日記」と「星座」の機能自体を残す。両機能の存続は確定条件であり、再利用部品の選定や再設計を理由に廃止しない。「日記処理の存続を目的にしない」は旧内部実装の再利用を必須にしない意味で、日記機能を不要とする意味ではない。星座も同様に、機能保持と旧解析処理の再利用を区別する。
- 日記・星座をLLM中心の記憶／理解とどう接続し、何を表示・保存するかは具体設計で詰める。旧版と既存記録の保護を維持し、LLMが生成した文章や関連を、実体験・習得・実績の証拠として自動認定しない。
- Geminiを出発点とし、今後複数のAIを使う可能性を視野に設計する。複数AIの実接続・切替機能や別サービスの採用まで決定したものではない。
- 追加課金禁止を継続する。追加クレジット購入・課金APIキー・Google Cloud従量課金・新たな有料契約へ切り替えない。
- 新システムの方針採用だけで、既存版の理解／学習／行動境界や世界情報の送信範囲を変更しない。新システムでの具体的な境界・送信範囲は設計で明らかにし、変更前に相談する。生成返答をそのまま知識・実績の取得証拠にすることは採用しない。
- 既存機能とダンジョンの合意を保持する。音声実装、既出4修正（返答と行動のずれ・睡眠状態の断定・反復案内・下書き開始による応答取消）、カード／カジノ・4e DW／DXの保留を自動解除しない。

## 構想段階の案

- LLMによる自由文理解・会話・意図の解釈と、プログラムによる世界状態・実行結果・保存の管理を分担する。具体的な分担やデータ形式は未採用。
- 記憶・学習は望む育ち方から設計し直す。従来の共起候補を調整し続けることを、新システム設計の前提にしない。

### 最初の構成案（2026-11-21・設計提案、未採用／未実装）

採用済みなのはLLM中心へ切り替える進め方。以下はその具体化として提示する案であり、旧版の境界や新システムの実行権限を変更する合意ではない。

| 段階 | 役割の案 | 保持する根拠・制限 |
| --- | --- | --- |
| 入力 | ゲームが原文・話者・時点を保存する | プレイヤー原文を後の要約で置換しない |
| 会話への情報供給 | ゲームが本人設定、選んだ記憶、許可済みの本人状態・体験を渡す | 世界全体や隠れた正解を自動供給しない。追加する仕事体験・対象情報は送信前に相談 |
| 理解と意思 | LLMが発言の意味・返答・本人がしたいこと・記憶の更新候補をまとめて提案する | 原則1発話1回の生成を目指す。旧文型解析の理解成功を入口条件にしない。1回での構造出力の可否と品質・待ち時間は未検証 |
| 検査 | ゲームが提案の形式・根拠ID・実在対象・許可された操作・現在の実行条件を確認する | LLMの意味解釈や証言の真偽まで機械検査で保証できるとは扱わない。曖昧な対象を秘密の正解へ補正しない |
| 発言と行動 | 検査後に発言を表示し、成立する本人の意思を実行要求へ渡す | 行動の予定・開始・完了を分ける。拒否／状況変化で不整合になる返答はそのまま表示せず、実行結果を捏造しない |
| 結果と記憶 | ゲームが実際の開始・完了・失敗を記録し、次の会話で参照する | 発言を実行証拠にせず、行動完了・実績は実イベントから確定する |

#### 会話と育ちの案

- 原発言、本人の受け取り方、ゲーム内の実体験を区別して保持する。「ご主人様がそう教えた」と「自分で確かめた」を同じ事実へまとめない。LLMの要約や解釈には元の入力／実イベントを紐付け、生成返答を根拠へ循環させない。
- 一般知識を使って話せることと、本人がその場所・対象・仕事を知っていること、できることを区別する。LLMへ渡せる本人知識と、未知のことをどう扱うかは育ち方の設計として詰める。一般知識の存在だけで能力や実績を与えない。
- 名前や説明は出所付きの「教わった内容」として記憶更新候補にできるが、全発言を命名へ変換しない。訂正は元の教示・受け取り方を残して新しい版を加える案。確信度の数値や習得条件は未決定で、件数だけの確定は採用しない。
- 例「体力や空腹感はどう？」は体調への問いとして返すことを目標にし、鍛冶師の呼び名へ全文を保存する旧共起処理を新システムの必須経路にしない。例「この実はころだよ」は、本人に対象を特定できる根拠があれば教示候補、不明なら確認する。例「疲れたなら休んでね」は条件付きの気遣いとして解釈し、即時休息・全快・命令受諾を文面だけで確定しない。これらは受入例の案であり理解規則の実装ではない。

#### 部品の選び方の案

- 再利用候補：世界の時間・体調・移動・食事・仕事などの実処理、実イベント、表示、保存の安全な書込、既存契約内のGemini接続・事前起動。いずれも新しい入力／結果形式への適合を確認してから使う。旧部品をそのまま接続できるという調査結果ではない。
- 置換候補：自由入力を既存カタログの文型へ当てはめる理解入口、未知の短文を注目対象へ全文関連付けする学習入口。旧版側は保持し、新システムのために旧版を改造してから移植する順序を取らない。
- 再設計候補：本人の記憶・理解の表示と日記。大量の旧解析／日記担当を再利用必須にせず、新システムの原発言・解釈・実体験から必要な表示を考える。
- 日記と星座の機能は確定将来仕様どおり保持する。その接続案として、日記は出所付きの会話・受け取り方・実体験を読み返せる表示、星座は保持された言葉・記憶・関連を見渡せる表示として設計する。教わったこと・本人の解釈・自分で確かめたことや未確かな関連を区別する。具体的な表示内容・構成は未採用。星座はLLM内部の非公開思考過程を取得／再現するものとは扱わず、実際に保持したデータに基づく表示を検討する。
- AI接続は入力context／提案結果／失敗分類の共通境界を検討し、Gemini固有の認証・起動・quotaを接続部へ閉じ込める。モデル切替で本人の原文記憶を作り直さない。複数AIの同時呼出や相互採点は初版の前提にせず、契約利用枠の消費と待ち時間を抑える。

#### 最初の検証範囲の案

- 旧データを操作しない架空本人の文字会話で、体調の質問・対象を教える会話・休息への気遣いの3例を確認する。原文と解釈の分離、根拠なしの命名／実績が増えないこと、可能／不可能／曖昧な行動要求、失敗時の状態非変更を確認する。これは今すぐ外部モデルへ送信する承認ではない。
- LLM接続は現行返答専用helperのtool denyを解除せず、ゲーム側が検査した要求だけを実行する案。モデルへファイル・シェル・保存の直接操作権を渡さない。
- 人物切替や状態変化後の古い提案を適用しない照合、生成失敗やquota時に旧解析へ黙って戻さない扱いを設計する。取消の操作方法は未決定で、旧版の保留修正を再開しない。
- 新システムは別起動・別保存の検証環境から始め、既存本人の移行はその後に相談する案。コピー対象・ID・旧ノートの意味・声設定を確認せず自動移行しない。

### 日記・星座から具体化する相談案（2026-11-21・未採用／未実装）

以下は設計相談用。日記・星座の保持は採用済みだが、この節の記録構造・表示・役割・送信・試作範囲は未採用。実装や外部送信の許可として扱わない。

#### 育ちと記憶

2026-11-21追記：下記のA／B比較は相談時の案として保持する。最新回答でBを軸にする方針は採用済み。次は「教わったことを未確認として会話・試行に使う範囲」を相談する。教示を実確認へ自動昇格しないことと、未経験だから教示を一切使えないことを区別する。具体的な採用・試行条件は未決定。

- 育ちは、会話回数や生成文の量ではなく、「誰に何を教わったか」「本人がどう受け取ったか」「試して何が起きたか」「後でどう考え直したか」の積み重ねとして見せる案。好み・関係・期待も候補にできるが、一度の返答で恒久的な性格へ固定しない。既存の体力・満腹度・進化条件／ルートの変更は含めず、新記憶との接続は別途相談する。
- 保存する基礎記録を三つに分ける案：原発言（原文・話者・時点）、受け取り方（解釈した時点・出所ID・対象・教示／質問／気遣いなどの意味・未確かな点）、実体験（ゲームが記録した行為者・対象・開始／完了／失敗・結果）。受け取り方はLLMによる仮説であり、原発言と同等の一次資料にしない。
- それらから参照用の記憶を作る案。各記憶に出所ID、本人が受け取った内容、適用する対象／場面、教わった内容か実確認か、訂正前後の関連を保持する。具体的なJSON形式・上限・採用条件は未決定。出所が実在することの検査だけでは、要約が元資料の意味を正しく保つことまで保証しない。
- 訂正や矛盾では、元記録を残して現在参照する解釈を更新し、当時の日記／星座を後の知識で書き換えない。要約は閲覧・検索用の派生物として扱い、要約を新たな教示・実体験の証拠にしない。LLMの返答文や「自分はできる」という自己申告から習得・能力・実績を増やさない。
- 最初の相談点は一般知識の扱い。A案は一般知識で自然に会話しつつ、本人が教わったこと／実体験／できることを別管理する。B案はLLMの言語理解を使いながら、本人が未経験・未教示の内容を知識として語る範囲も絞る。Aは会話の広さ、Bは覚えていく変化を重視するが、Bでもモデル内部の知識を消去した保証はできない。どちらも未採用で、旧解析の文型制約へ戻す案ではない。

#### 同じ記録を日記と星座で読む

| 表示 | 最初の案 | 根拠と注意 |
| --- | --- | --- |
| 日記 | 出来事ごとに、短い本人の文章と「教わったこと」「その時の受け取り方」「実際の結果」を必要な分だけ表示。原文・元イベントへ展開できる | 文章は記録に基づく表現。未経験の出来事や心情を補わない。本人文を生成する頻度・追加呼出の要否は未決定。初期試作は保存済み解釈／結果の簡単な表示で検証し、旧日記部品の大量移植を前提にしない |
| 星座の常設表示 | 言葉・対象・教わった内容・実体験の結び付き。選択すると出所と訂正履歴へ移れる | 線は教示、受け取り方、実確認、訂正など記録された関係を区別。未確かな関連は区別して示す。距離・明るさを理解度や確信度と断定しない |
| 星座の会話表示 | 今回の入力→ゲームが供給した記憶→LLMが参照したと申告する出所／解釈・意思候補→ゲームの検査→実表示・実結果 | 「供給した」「参照したと申告した」「ゲームが検査／実行した」を区別する。供給した記憶すべてを実際の判断理由として光らせない。LLMの非公開思考・注意重み・真の因果を再現した図にはしない |

日記と星座は同じ出所付き記録の別の見せ方とし、閲覧や文章生成だけで学習・実績を増やさない案。長期記憶の保持量と会話の当時snapshotの保持量は別に決める。旧星座の24入力・起動中だけという制限を新システムへ自動採用せず、無制限保存も前提にしない。旧版の表示正本は[既存の星座](word_constellation_and_voice.md)のまま保持する。

#### LLMとゲームの分担と送信の相談

- LLMは自由文理解、返答、次にしたいこと、受け取り方／記憶の候補を提案する。ゲームは原資料・実世界・本人の実績を管理し、根拠ID・対象・許可操作・状態の版・現在の成立条件を検査する。意味理解を旧パーサで再判定することを必須にせず、機械的に検査できない解釈の誤りは別に残す。
- 発話と行動を一つの提案へ関連付け、意図・開始・完了を分ける。拒否された行動について成功文を出さない。失敗時の表示方法は未決定で、整合のために毎回二度目のLLM呼出を必要とする構成にはしない案。原返答の書換方式も合意後に決める。
- 次に相談する送信候補は、最新原入力、本人の名前／一人称／呼び方、有限の直近会話、出所付きで選んだ記憶、本人が観測できた自己状態、試作で許可する行動と条件。これは新システム用の候補表であり、[現行比較版](word_llm_reply_comparison.md)の送信許可から継承済みと扱わない。原文ノートやセーブ全体を自動供給しない。
- 特に、対象の見た目・所在・呼び名、仕事・味・移動先などの体験詳細、実行可能な行動一覧／条件も世界情報を伝え得る。許可項目・取得元・量・未知情報を含めない条件を具体化して相談するまで送信しない。地図全体・隠し正解・未解放情報は初期試作の供給候補に含めない。記憶の選択方法・上限・直近会話に含める生成文の扱いも未決定。
- 本人の記憶と送信記憶を分け、保存しているからすべて送るとはしない。ゲーム側で今回何を供給したかを記録する案。モデルへファイル・シェル・保存の直接操作権を渡さず、既存契約枠と追加課金禁止を維持する。

#### 最小試作の相談案

- 別起動・別保存の架空本人、文字入力、原則一入力一生成。対象教示の曖昧さを試せる小さな場面と、休息一種類の実行を候補とする。旧本人のコピーや既存世界全体への接続を前提にしない。日記・星座を試作に含め、会話だけ完成して両機能を後回しにしない。
- 前記3例に加え、「教示の訂正」「曖昧な対象」「行動できない状態」「生成失敗／古い提案」を確認する案。日記では教示と実体験の区別、星座では供給記憶／申告参照／実結果の区別、保存再開では出所と訂正の保持を確認する。合格基準は採用範囲確定後に詳細化する。
- 先に外部送信なしの固定応答で記録・検査・両表示・保存を検証し、その後、送信項目の合意を得た範囲だけ既存契約内の実モデルで会話品質を確かめる案。固定応答の成功をLLMの理解品質や実接続の成功とは扱わない。試作成功を既存の職業・探索・ダンジョン対応の完了ともしない。
