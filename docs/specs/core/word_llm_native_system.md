# LLM中心の新システム

## 現在の実装仕様

- 2026-11-21時点では方針合意のみで、新システムは未実装。既存のLLMなし版と[Gemini応答比較版](word_llm_reply_comparison.md)の起動・保存・動作を今回変更しない。現在遊べるGemini版を新システムの実装済みと扱わない。

## 確定している将来仕様

- 2026-11-21ユーザー採用：「新システム（旧版はそのまま比較版として残す）」は、「既存版へのLLM追加から、LLM中心の構成を設計し、必要な既存部品を選ぶ進め方へ切り替える」。新システムの設計はこの方針で進める。旧版を維持することと、新システムで旧版の仕組みを必ず使うことを区別する。
- 旧版はそのまま比較用に残す。新システムのために旧版の実装や本人・声設定・教わった原文ノートを削除・上書きしない。既存部品は新システムでの役割と必要性から再利用・置換・不採用を判断し、従来の自由入力解析・仮学習・日記処理の存続を目的にしない。
- Geminiを出発点とし、今後複数のAIを使う可能性を視野に設計する。複数AIの実接続・切替機能や別サービスの採用まで決定したものではない。
- 追加課金禁止を継続する。追加クレジット購入・課金APIキー・Google Cloud従量課金・新たな有料契約へ切り替えない。
- 新システムの方針採用だけで、既存版の理解／学習／行動境界や世界情報の送信範囲を変更しない。新システムでの具体的な境界・送信範囲は設計で明らかにし、変更前に相談する。生成返答をそのまま知識・実績の取得証拠にすることは採用しない。
- 既存機能とダンジョンの合意を保持する。音声実装、既出4修正（返答と行動のずれ・睡眠状態の断定・反復案内・下書き開始による応答取消）、カード／カジノ・4e DW／DXの保留を自動解除しない。

## 構想段階の案

- LLMによる自由文理解・会話・意図の解釈と、プログラムによる世界状態・実行結果・保存の管理を分担する。具体的な分担やデータ形式は未採用。
- 記憶・学習は望む育ち方から設計し直す。従来の共起候補を調整し続けることを、新システム設計の前提にしない。

### 最初の構成案（2026-11-21・設計提案、未採用／未実装）

採用済みなのはLLM中心へ切り替える進め方。以下はその具体化として提示する案であり、旧版の境界や新システムの実行権限を変更する合意ではない。

| 段階 | 役割の案 | 保持する根拠・制限 |
| --- | --- | --- |
| 入力 | ゲームが原文・話者・時点を保存する | プレイヤー原文を後の要約で置換しない |
| 会話への情報供給 | ゲームが本人設定、選んだ記憶、許可済みの本人状態・体験を渡す | 世界全体や隠れた正解を自動供給しない。追加する仕事体験・対象情報は送信前に相談 |
| 理解と意思 | LLMが発言の意味・返答・本人がしたいこと・記憶の更新候補をまとめて提案する | 原則1発話1回の生成を目指す。旧文型解析の理解成功を入口条件にしない。1回での構造出力の可否と品質・待ち時間は未検証 |
| 検査 | ゲームが提案の形式・根拠ID・実在対象・許可された操作・現在の実行条件を確認する | LLMの意味解釈や証言の真偽まで機械検査で保証できるとは扱わない。曖昧な対象を秘密の正解へ補正しない |
| 発言と行動 | 検査後に発言を表示し、成立する本人の意思を実行要求へ渡す | 行動の予定・開始・完了を分ける。拒否／状況変化で不整合になる返答はそのまま表示せず、実行結果を捏造しない |
| 結果と記憶 | ゲームが実際の開始・完了・失敗を記録し、次の会話で参照する | 発言を実行証拠にせず、行動完了・実績は実イベントから確定する |

#### 会話と育ちの案

- 原発言、本人の受け取り方、ゲーム内の実体験を区別して保持する。「ご主人様がそう教えた」と「自分で確かめた」を同じ事実へまとめない。LLMの要約や解釈には元の入力／実イベントを紐付け、生成返答を根拠へ循環させない。
- 一般知識を使って話せることと、本人がその場所・対象・仕事を知っていること、できることを区別する。LLMへ渡せる本人知識と、未知のことをどう扱うかは育ち方の設計として詰める。一般知識の存在だけで能力や実績を与えない。
- 名前や説明は出所付きの「教わった内容」として記憶更新候補にできるが、全発言を命名へ変換しない。訂正は元の教示・受け取り方を残して新しい版を加える案。確信度の数値や習得条件は未決定で、件数だけの確定は採用しない。
- 例「体力や空腹感はどう？」は体調への問いとして返すことを目標にし、鍛冶師の呼び名へ全文を保存する旧共起処理を新システムの必須経路にしない。例「この実はころだよ」は、本人に対象を特定できる根拠があれば教示候補、不明なら確認する。例「疲れたなら休んでね」は条件付きの気遣いとして解釈し、即時休息・全快・命令受諾を文面だけで確定しない。これらは受入例の案であり理解規則の実装ではない。

#### 部品の選び方の案

- 再利用候補：世界の時間・体調・移動・食事・仕事などの実処理、実イベント、表示、保存の安全な書込、既存契約内のGemini接続・事前起動。いずれも新しい入力／結果形式への適合を確認してから使う。旧部品をそのまま接続できるという調査結果ではない。
- 置換候補：自由入力を既存カタログの文型へ当てはめる理解入口、未知の短文を注目対象へ全文関連付けする学習入口。旧版側は保持し、新システムのために旧版を改造してから移植する順序を取らない。
- 再設計候補：本人の記憶・理解の表示と日記。大量の旧解析／日記担当を再利用必須にせず、新システムの原発言・解釈・実体験から必要な表示を考える。
- AI接続は入力context／提案結果／失敗分類の共通境界を検討し、Gemini固有の認証・起動・quotaを接続部へ閉じ込める。モデル切替で本人の原文記憶を作り直さない。複数AIの同時呼出や相互採点は初版の前提にせず、契約利用枠の消費と待ち時間を抑える。

#### 最初の検証範囲の案

- 旧データを操作しない架空本人の文字会話で、体調の質問・対象を教える会話・休息への気遣いの3例を確認する。原文と解釈の分離、根拠なしの命名／実績が増えないこと、可能／不可能／曖昧な行動要求、失敗時の状態非変更を確認する。これは今すぐ外部モデルへ送信する承認ではない。
- LLM接続は現行返答専用helperのtool denyを解除せず、ゲーム側が検査した要求だけを実行する案。モデルへファイル・シェル・保存の直接操作権を渡さない。
- 人物切替や状態変化後の古い提案を適用しない照合、生成失敗やquota時に旧解析へ黙って戻さない扱いを設計する。取消の操作方法は未決定で、旧版の保留修正を再開しない。
- 新システムは別起動・別保存の検証環境から始め、既存本人の移行はその後に相談する案。コピー対象・ID・旧ノートの意味・声設定を確認せず自動移行しない。

## 未決定事項

- LLMへ任せる判断とプログラム側で検査・実行する範囲、記憶の出所・更新・訂正、本人の知識と一般知識の扱い。
- 再利用する具体的な部品、複数AIの接続境界、待ち時間・失敗・取消時の動作。
- 新システムの起動・保存分離の具体的方法、既存本人を試す際のコピー／移行方法。旧保存の破壊的移行や直接共有は未採用。
- 周囲の対象・仕事・実体験など、モデルへ渡す情報の種類と量。

## 次の設計作業

- プレイヤー入力から、本人の解釈・記憶・発言・行動と実行結果までの流れを具体化する。各段階でLLMに任せる役割とゲームが保証する事実を示し、その流れに必要な既存部品を選ぶ。これは採用済みの進め方に基づく設計であり、旧版の仮学習修正を先に実装する手順ではない。
