# チュートリアル図鑑仕様

状態: 実装済み・継続更新

## 対象範囲

画面下部のチュートリアルボタン、進行に応じた項目解放、分類表示、既読状態、旧フラグ移行、世代をまたぐ保存、ゲーム内ヒントの情報量を扱う。各コンテンツ固有の内部条件や数値は、それぞれの所有仕様書が管理する。

## 基本方針

- チュートリアルは答えを提示する攻略表ではなく、プレイヤーが試行錯誤するためのヒント集とする。
- 未解放の大分類、小分類、項目名、本文は一切表示しない。存在自体を伏せ、将来要素のネタバレを防ぐ。
- 項目はゲーム進行やプレイヤー操作に応じて1件ずつ解放する。
- 一度解放された項目はいつでも読み返せる。
- 探検の必要能力名、必要値、現在値、不足量はチュートリアルにもキャラクターのセリフにも表示しない。
- 能力全般を説明する独立項目では、各能力の名称と大まかな影響範囲をヒントとして示してよい。ただし、個別コンテンツの正解となる組合せや閾値は示さない。

## 現在の実装仕様

### 1. 起動方法と画面構成

- 画面下部の `📘 チュートリアル` ボタンから開く。
- 解放済み項目は「大分類 → 小分類 → 項目」の3段階で表示する。
- 大分類と小分類はアコーディオン式で開閉する。同じ階層の大分類は同時に1つだけ開く。
- 項目を選ぶと右側へ本文を表示する。狭い画面では分類一覧の下へ本文を表示する。
- 未読項目には印を付け、チュートリアルボタンには未読件数を表示する。
- 解放済み項目がない場合は、ゲーム進行で追加されることだけを表示する。

### 2. 解放時の通知

- 初回解放時だけ、画面下部へ「チュートリアルに追加されました」という小さな通知を一定時間表示する。
- 通知は操作を遮るモーダルではなく、本文も自動表示しない。
- 同じ条件が再発しても項目は重複せず、通知も繰り返さない。
- 既存の一度きりの機能解放画面を見た扱いで追加する項目は、通知を出さず閲覧済みにする。

### 3. 現在の項目と解放条件

未解放の項目は分類ごと画面に存在しない。現在のカタログには通常探検の項目はあるが、ダンジョン専用のチュートリアル項目と解放フックは存在しない。

| 大分類 | 小分類 | 項目 | 解放条件 | 解放直後 |
|---|---|---|---|---|
| はじめに | ことば | 最初のことば | 初回の言葉チュートリアル開始、または旧セーブに学習済み言葉がある | 閲覧済み |
| はじめに | 能力 | 能力について | ステータス画面を初めて開く | 未読 |
| アクション | 探検 | 探検前の準備 | 探検開始前または探検中に体力・満腹度が不足する | 未読 |
| アクション | 探検 | さらに奥へ進むには | 通常探検で中層・深層の能力条件を満たせず帰還する | 未読 |
| 暮らしの機能 | 救済 | 救済について | 救済機能が解放される | 閲覧済み |
| 交流 | オンライン | オンライン機能 | 7語以上を学習し、オンラインアカウントへログインした状態でオンライン機能が解放される | 閲覧済み |
| コレクション | 思い出 | 思い出について | 初めて思い出を1枚取得する | 閲覧済み |
| コレクション | カード | カードについて | 思い出60枚以上、建設済みカジノへの入場済み、Dealer Rank 6の全条件を満たし、TCGが正式解放される | 閲覧済み |
| 仕事 | 修行 | 修行への入口 | いずれかの師匠と初めて顔合わせを完了する | 未読 |
| 仕事 | レストラン | レストランの基本 | 店内チュートリアルを完了する | 閲覧済み |
| 仕事 | 鍛冶屋 | 鍛冶屋の評判と経営破綻 | 初回鍛冶屋チュートリアルで評判・破綻・救済・再建の説明を受ける | 未読 |

- `思い出について` はカード、デッキ、バトルに触れず、正式解放前の名称を `思い出` に統一する。
- `カードについて` はTCG正式解放後にだけ追加し、思い出をカードとして使えるようになったこととデッキ・バトルを案内する。
- `修行への入口` は具体的な師匠名や職業名を出さず、再訪と修行の入口だけを案内する。

### 4. 能力についての情報量

`能力について` では、次の範囲だけを案内する。

| 能力 | 表示するヒント |
|---|---|
| 活力 | 力や持久力を使う行動、力仕事で力を発揮しやすくなる |
| 賢さ | 学習、調理、ものづくり、判断等の知識を使う行動が得意になる |
| 機嫌 | AIの気分と行動傾向に影響し、成功や失敗等で上下する |
| 美しさ | 見た目や仕上がり、相手への印象が重要な仕事で生かしやすい |
| 素早さ | 動きの速さや、とっさの対応が必要な場面で役立つ |

個別の仕事・探検・ダンジョン等がどの能力をいくつ要求するかは、この項目に追記しない。

- チュートリアル内の用語は既存項目に合わせる。既存の `能力について` が `活力`、`素早さ` 等の個別能力名を説明しているため、一般的な影響を案内する釣りのチュートリアルでも `活力` と `素早さ` を使用する。数式、閾値、現在値、不足量までは表示しない。

### 5. 探検失敗時の案内

- 開始前または途中の体力・満腹度不足では、キャラクターが「体力やお腹の準備が足りない」「休息や食事をしてから挑戦する」程度を話す。
- 中層・深層の条件不足では、キャラクターが「今の能力では危険」「もう少し成長してから挑戦する」程度を話す。
- 必要量、現在量、不足量、必要能力名、必要値、推奨する特定トレーニングは表示しない。
- 探検失敗のたびに詳細画面を開かない。初回だけ対応するチュートリアル項目を未読で解放する。
- 内部の判定値とデバッグ記録は [`field_exploration.md`](field_exploration.md) が管理し、プレイヤー向け表示制限とは分離する。

### 6. 保存と世代継承

- 履歴は育成本体の `aiPet` ではなく、`localStorage` の `game_tutorial_archive_v1` へ保存する。
- 初回思い出案内は `memory_tutorial_done_v1`、カード正式解放案内は `tcg_card_tutorial_done_v3`、ログイン確認済みオンライン案内は `online_tutorial_login_verified_v1` で一度きりの発生を管理する。
- 保存値はスキーマ版と、項目IDごとの解放日時・閲覧日時を持つ。本文は保存せず、現在のカタログから描画する。
- 世代交代では初期化しない。魂の引継ぎ画面で一切選択しなくても無条件で残る。
- 強くてニューゲームの育成データ初期化対象にも含めない。
- ゲーム設定のデータ管理から多段階確認を経て完全初期化した場合は、`game_tutorial_archive_v1` と、初回思い出・カード正式解放・ログイン確認済みオンライン案内等のチュートリアル用一度きりフラグをすべて削除する。完全初期化後の新しいセーブでは各項目を解放条件から改めて登録する。
- 現在の手動ゲームデータリセットもこの専用キーを削除しない。
- 開発用保護テストではこのキーも退避・復元対象とし、テスト中の解放を通常履歴へ混ぜない。

### 7. 旧状態からの復元

次の既存フラグを検出した場合、対応項目を解放済みかつ閲覧済みとして復元する。

| 既存状態 | 復元する項目 |
|---|---|
| `aiPet._tutorialDone` または学習済み言葉あり | 最初のことば |
| `aiPet.unlockedFeatures.shop` | 救済について |
| `aiPet.unlockedFeatures.online` とログイン確認済み状態 | オンライン機能 |
| `localStorage.tcg_tutorial_done_v2` | 思い出について。TCGが現在正式解放済みの場合だけカードについても復元 |
| `aiPet.shopTutorialCompleted` | レストランの基本 |
| `aiPet.apprentice.metMasters` に1件以上 | 修行への入口 |

ステータス画面には既存の閲覧フラグがないため、旧セーブでも次にステータス画面を開いた時点で `能力について` を未読解放する。
旧実装がログイン前に追加した未確認のオンライン項目と、TCG正式解放前に追加した未確認のカード項目は、現在の条件を満たしていない場合に履歴から取り除き、正しい段階の項目へ補正する。一度ログインまたはTCG正式解放を確認できた履歴は、後のログアウト・世代交代・進行リセットでは失わない。

## 主な実装

- `tutorial_core.js`
  - 項目カタログ、専用保存、旧状態移行、未読数、解放通知、分類画面。
  - `unlockTutorialEntry()`, `markTutorialViewed()`, `openTutorialArchive()`, `syncTutorialArchiveFromLegacy()`。
- `index.html`
  - 画面下部のチュートリアルボタンとスクリプト読込。
- `ai_core.js`
  - 初回言葉、救済、オンライン、通常探検の解放フック。
- `ui_controller.js`
  - ステータス画面、初回思い出、カード正式解放、最初の師匠との顔合わせの解放フック。
- `shop_map_core.js`
  - レストラン店内チュートリアル完了フック。
- `blacksmith_map_core.js`
  - 鍛冶屋項目の未読解放と、本番マップチップ・キャラクター描画を再利用した正常営業／評判低下／経営破綻の3固定状態レンダラー。
- 鍛冶屋項目は最大3枚の静止画を本文内へ表示し、クリック／タップでゲーム内拡大表示を開く。前後切替、閉じる、Escapeを持ち、図鑑を開く前の鍛冶屋一時停止状態を閉じるまで保持する。
- 旧セーブの `blacksmithTutorialCompleted` は鍛冶屋項目を閲覧済みとして静かに復元し、新しい会話での初回解放だけを未読通知する。
- `debug_test_core.js`
  - 専用保存キーの保護テスト退避・復元。

## 確定している将来仕様

- 王様から受注する防衛戦と、隊長から受注する闘技場には、セーブ全体で各1回必須となる実戦形式のチュートリアルを追加する。どちらも主人公だけや仮の訓練兵では開始せず、入居中で参加可能な実在住人を最低1人含み、全員が城へ実際に移動できる通常と同じ参加条件を満たした場合だけ受講できる。完了までは対応する通常モードを開始できない。
- 各チュートリアルは1戦2WAVEとし、第1WAVEでプレイヤー指揮、第2WAVEで全AUTOを体験する。WAVE間に休憩と個人作戦の変更を挟み、失敗・中断時は失敗したWAVEの開始状態から安全に再開する。王様・隊長の説明は戦闘を一時停止し、師匠用の共通会話イベントウィンドウで表示する。具体的な戦闘内容は [`../castle/defense.md`](../castle/defense.md) と [`../castle/arena.md`](../castle/arena.md) が所有する。
- 防衛戦チュートリアル完了時は `戦闘` → `防衛戦`、闘技場チュートリアル完了時は `戦闘` → `闘技場` に基本項目を未読で追加し、本文を自動表示しない。図鑑は説明の読み返しだけを担当し、実戦再履修は王様または隊長の通常会話イベントから選ぶ。再履修時も実在住人の通常参加条件を省略しない。
- 既存セーブに対応する通常戦績が一件以上ある場合は、そのコンテンツの初回チュートリアルを完了済み、対応図鑑項目を閲覧済みとして通知なしで復元し、通常モードを再びロックしない。任意再履修は利用できる。
- 音楽制作室を初めて利用するときは、コンシェルジュが共通会話イベントウィンドウで機材、かんたん制作、自動作曲、こだわり制作、保存、自作CD化の基本を案内する。完了時に `マイホーム` → `音楽制作` の基本項目を未読で追加し、本文は自動表示しない。初回案内はセーブ系譜で一度だけとし、案内後は図鑑で常時読み返せるほか、コンシェルジュの通常会話から実地案内を任意に再履修できる。制作機能の詳細は [`../collections/music_creation_studio.md`](../collections/music_creation_studio.md) が所有する。
- 初回ダンジョン導入時に、`アクション` → `ダンジョン` の項目を解放し、ダンジョン内の状態異常が残ったまま帰還すると育成側の病気へ変換されること、病気の変換分類、重症度、複数発症、治療の基本をいつでも読み返せるようにする。項目解放時に本文を自動表示せず、通常どおり未読通知だけを出す。将来の冒険家同行による固定マップチュートリアル内でも同じ内容に触れる。具体的な変換規則と導入進行は [`../dungeon/dungeon_common.md`](../dungeon/dungeon_common.md) が所有する。
- 冒険家同行の5階構成の共通固定マップをすべて完了した時点で、`アクション` → `ダンジョン` に `スカルダンジョンの準備` と `クリスタル迷宮の準備` を別項目として解放する。前者は手持ち持込、育成能力反映、死亡時ロスト、後者は持込不可、Lv1開始、現地調達・成長を中心に説明する。どちらも解放通知だけを出し、本文は自動表示しない。修了後は通常の生還と同じく育成画面へ戻る。再履修はチュートリアル図鑑からではなく、普段の師匠会話イベントウィンドウで冒険家に依頼し、全階または任意の階を選ぶ。
- 初めて釣りを開始した時点で、`アクション` → `釣り` → `釣りの基本` を未読項目として解放する。活力と素早さが魚を釣り上げる力に、釣り竿の種類が成功しやすさに影響することは、既存の能力チュートリアルと同じ個別能力名を使って説明してよい。ただし、ヌシ魚種ごとの難易度、成功率計算式、必要値、現在値、不足量、最適育成手順は表示しない。
- 捕獲失敗時のAI吹き出しはチュートリアル本文を数値付きで読み上げず、踏ん張る力、相手の動きへの対応、道具の頼もしさ等を示す世界観内の間接的なヒントに留める。同じ未解決状態で同じヒントを繰り返さない規則は [`automatic_feedback_and_retry.md`](automatic_feedback_and_retry.md) に従う。
- 既存項目と今後追加する全チュートリアル項目へ、文章を補助するスクリーンショット風の合成画像を最低1枚登録する。実際のゲーム画面を撮影した画像は必須にせず、既存の背景、マップチップ、キャラクター、魚、設備、アイコン、ウィンドウ枠等の画素材を組み合わせて構成する。一連の手順を一枚で説明できない場合は、一項目につき最大3枚を順番に表示できるようにする。
- 合成画像は簡略図ではなく、説明対象となる実際の画面を可能な限り完全再現する。本番と同じ画像素材、切抜き値、座標系、拡大率、反転、前後順、UI部品、CSS、Canvas描画関数を再利用し、チュートリアル専用に似た部品を別実装して見た目が分岐しないようにする。
- Canvas主体の画面は、本番の描画処理を副作用のない共通描画関数へ分離し、固定されたチュートリアル用状態をOffscreenCanvasまたは専用Canvasへ渡して描く。DOM主体の画面は、本番と同じDOM生成処理とCSSクラスを、操作を無効化した隔離コンテナ内へ固定データで描画する。表示のために現在のAI、所持品、進行、セーブデータを書き換えない。
- 再現画面内のAI名、能力値、所持数、進捗、日時等はプレイヤーの現在値を参照せず、項目ごとに定義した固定の説明用データを使う。キャラクター外見だけは固定データの例外とし、現在の世代の `baseType` や `currentSkin` ではなく、そのセーブで最初に図鑑登録された未進化の基本種を本番のキャラクター描画へ渡す。この代表基本種は図鑑とともに世代を越えて保持し、ゲーム全体の完全初期化だけで初期化する。旧セーブの補完規則は [`../collections/pokedex_and_grazing.md`](../collections/pokedex_and_grazing.md) に従う。通常項目では進化、色変更、オーラ、衣装等の後付け外見を適用せず、代表基本種本来の姿を表示する。進化を説明する項目で表示してよい進化形は、そのセーブで最初に図鑑登録された進化形一種だけとし、未登録の進化形や後から登録された別の進化形を説明例として先に見せない。カラー変更とオーラは各機能の解放時点で全候補がプレイヤーへ公開されるため、それぞれの説明項目ではプレイヤーの現在選択ではなく、項目ごとに固定した説明用カラーまたは説明用オーラを表示してよい。将来の衣装は衣装自体を説明する項目に限って表示する。複数の無関係な外見要素は同時適用しない。代表基本種を復元できない旧データや画像読込失敗時だけ安全な基本種へフォールバックする。チュートリアル画面内に表示されていること自体で説明用だと判断できるため、合成画像へ `説明用画面` 等の透かしや注記は重ねない。
- チュートリアルカタログには、再現する画面ID、固定状態、表示領域、注目対象、必要な補助レイヤー等を言語非依存で登録する。本番UIを完全再現した上へ、説明用の強調枠、矢印、番号、暗幕等を別レイヤーとして重ねる。現在のゲーム状態や実際のスクリーンショットには依存せず、同じ説明は常に同じ構図で表示する。
- 各項目の1枚目は原則として説明対象の画面またはパネル全体を表示する。全体表示では注目箇所が小さすぎて判別できない場合だけ、2～3枚目に同じ本番画面の対象周辺を拡大した構図を置く。完全再現部分そのものを書き換えず、その上へ矢印、強調枠、番号、周囲の暗幕等を追加して案内する。
- 画像内へ説明文を焼き込まず、見出し、注釈、操作名等の文字はローカライズ可能なDOMまたはCanvas文字レイヤーとして別管理する。プレイヤー名、作成名、所持数等の個人データを合成画像へ含めない。画像が読み込めない場合やスクリーンリーダー利用時にも文章だけで内容が成立するよう、画像は補助情報とし、項目ごとに代替説明を持たせる。
- PCと狭い画面の両方で本文幅に収まるよう、論理座標で一度構成して表示領域に合わせて縮小する。小さい画面でも注目箇所が判別できるよう、一枚へ情報を詰め込みすぎず、必要なら同じ項目へ複数の合成画像を順番に配置できる構造にする。
- 基本の合成画像はPC版の実画面を基準に完全再現する。狭い画面でも単に縮小されるだけで操作配置が同じ項目はPC版を共用し、モバイル幅でボタン位置、画面構成、操作手順自体が変わる項目だけ別のモバイル版構図を登録する。
- 初期仕様の合成画像は静止画とし、動画、GIF、チュートリアル内だけで動く再現アニメーションは含めない。動きや状態遷移を説明する場合は、一項目最大3枚の静止画を順番に並べて表現する。
- 各合成画像はクリックまたはタップでゲーム内デザインの拡大表示を開けるようにする。拡大画面は元のチュートリアル項目へ戻る操作、前後画像の切替、Escape／戻る操作を持ち、Windows等のシステムダイアログは使わない。拡大中は背後のゲーム操作へ入力を通さない。
- チュートリアル図鑑を開いた時点でゲーム、AI、施設、時間経過その他の通常進行を停止し、図鑑内の画像拡大中も停止を維持する。開く前の停止状態を保存し、図鑑を閉じたときだけその状態へ復元する。図鑑を開く前から別のモーダル、イベント、デバッグ等で停止中だった場合は、閉じても勝手に再開しない。画像拡大を閉じて図鑑本文へ戻るだけでは通常進行を再開しない。
- 本番画面の素材、切抜き、座標、CSS、DOM構造、描画処理を変更したときは、同じ共通レンダラーを参照するチュートリアル再現も更新されることを基本とする。共有できず個別記述が残る画面は、変更時に本番とチュートリアルの比較確認を必須にし、代表画面の画像差分検査を将来の実装検証へ含める。

## 構想段階の案

- 項目数が増えた場合、解放済み項目だけを対象にした検索や「未読のみ」絞り込みを追加する。
- 現在は進化、カラー変更、オーラのゲーム機能が存在するが、着脱できる衣装システムは実装されていない。衣装チュートリアルとその再現画像は、将来衣装機能を実装するときに追加する候補とする。

## 未決定事項

- ゲーム進行とは別に、チュートリアル履歴だけを明示的に消す操作を用意するか。
- 既存の一度きりの機能解放モーダルも、将来すべて非モーダル通知へ統一するか。
- 既存各チュートリアルへ割り当てる具体的な固定状態、構図、使用素材、注釈内容。画面全体を表示するか説明対象のパネル周辺へ切り抜くかという項目別の表示範囲。
