# チュートリアル図鑑仕様

状態: 実装済み・継続更新

## 対象範囲

画面下部のチュートリアルボタン、進行に応じた項目解放、分類表示、既読状態、旧フラグ移行、世代をまたぐ保存、ゲーム内ヒントの情報量を扱う。各コンテンツ固有の内部条件や数値は、それぞれの所有仕様書が管理する。

## 基本方針

- チュートリアルは答えを提示する攻略表ではなく、プレイヤーが試行錯誤するためのヒント集とする。
- 未解放の大分類、小分類、項目名、本文は一切表示しない。存在自体を伏せ、将来要素のネタバレを防ぐ。
- 項目はゲーム進行やプレイヤー操作に応じて1件ずつ解放する。
- 一度解放された項目はいつでも読み返せる。
- 探検の必要能力名、必要値、現在値、不足量はチュートリアルにもキャラクターのセリフにも表示しない。
- 能力全般を説明する独立項目では、各能力の名称と大まかな影響範囲をヒントとして示してよい。ただし、個別コンテンツの正解となる組合せや閾値は示さない。

## 現在の実装仕様

### 1. 起動方法と画面構成

- 画面下部の `📘 チュートリアル` ボタンから開く。
- 解放済み項目は「大分類 → 小分類 → 項目」の3段階で表示する。
- 大分類と小分類はアコーディオン式で開閉する。同じ階層の大分類は同時に1つだけ開く。
- 項目を選ぶと右側へ本文を表示する。狭い画面では分類一覧の下へ本文を表示する。
- 未読項目には印を付け、チュートリアルボタンには未読件数を表示する。
- 解放済み項目がない場合は、ゲーム進行で追加されることだけを表示する。

### 2. 解放時の通知

- 初回解放時だけ、画面下部へ「チュートリアルに追加されました」という小さな通知を一定時間表示する。
- 通知は操作を遮るモーダルではなく、本文も自動表示しない。
- 同じ条件が再発しても項目は重複せず、通知も繰り返さない。
- 既存の一度きりの機能解放画面を見た扱いで追加する項目は、通知を出さず閲覧済みにする。

### 3. 現在の項目と解放条件

未解放の項目は分類ごと画面に存在しない。

| 大分類 | 小分類 | 項目 | 解放条件 | 解放直後 |
|---|---|---|---|---|
| はじめに | ことば | 最初のことば | 初回の言葉チュートリアル開始、または旧セーブに学習済み言葉がある | 閲覧済み |
| はじめに | 能力 | 能力について | ステータス画面を初めて開く | 未読 |
| アクション | 探検 | 探検前の準備 | 探検開始前または探検中に体力・満腹度が不足する | 未読 |
| アクション | 探検 | さらに奥へ進むには | 通常探検で中層・深層の能力条件を満たせず帰還する | 未読 |
| 暮らしの機能 | 救済 | 救済について | 救済機能が解放される | 閲覧済み |
| 交流 | オンライン | オンライン機能 | 7語以上を学習し、オンラインアカウントへログインした状態でオンライン機能が解放される | 閲覧済み |
| コレクション | 思い出 | 思い出について | 初めて思い出を1枚取得する | 閲覧済み |
| コレクション | カード | カードについて | 思い出60枚以上、建設済みカジノへの入場済み、Dealer Rank 6の全条件を満たし、TCGが正式解放される | 閲覧済み |
| 仕事 | 修行 | 修行への入口 | いずれかの師匠と初めて顔合わせを完了する | 未読 |
| 仕事 | レストラン | レストランの基本 | 店内チュートリアルを完了する | 閲覧済み |

- `思い出について` はカード、デッキ、バトルに触れず、正式解放前の名称を `思い出` に統一する。
- `カードについて` はTCG正式解放後にだけ追加し、思い出をカードとして使えるようになったこととデッキ・バトルを案内する。
- `修行への入口` は具体的な師匠名や職業名を出さず、再訪と修行の入口だけを案内する。

### 4. 能力についての情報量

`能力について` では、次の範囲だけを案内する。

| 能力 | 表示するヒント |
|---|---|
| 活力 | 力や持久力を使う行動、力仕事で力を発揮しやすくなる |
| 賢さ | 学習、調理、ものづくり、判断等の知識を使う行動が得意になる |
| 機嫌 | AIの気分と行動傾向に影響し、成功や失敗等で上下する |
| 美しさ | 見た目や仕上がり、相手への印象が重要な仕事で生かしやすい |
| 素早さ | 動きの速さや、とっさの対応が必要な場面で役立つ |

個別の仕事・探検・ダンジョン等がどの能力をいくつ要求するかは、この項目に追記しない。

### 5. 探検失敗時の案内

- 開始前または途中の体力・満腹度不足では、キャラクターが「体力やお腹の準備が足りない」「休息や食事をしてから挑戦する」程度を話す。
- 中層・深層の条件不足では、キャラクターが「今の能力では危険」「もう少し成長してから挑戦する」程度を話す。
- 必要量、現在量、不足量、必要能力名、必要値、推奨する特定トレーニングは表示しない。
- 探検失敗のたびに詳細画面を開かない。初回だけ対応するチュートリアル項目を未読で解放する。
- 内部の判定値とデバッグ記録は [`field_exploration.md`](field_exploration.md) が管理し、プレイヤー向け表示制限とは分離する。

### 6. 保存と世代継承

- 履歴は育成本体の `aiPet` ではなく、`localStorage` の `game_tutorial_archive_v1` へ保存する。
- 初回思い出案内は `memory_tutorial_done_v1`、カード正式解放案内は `tcg_card_tutorial_done_v3`、ログイン確認済みオンライン案内は `online_tutorial_login_verified_v1` で一度きりの発生を管理する。
- 保存値はスキーマ版と、項目IDごとの解放日時・閲覧日時を持つ。本文は保存せず、現在のカタログから描画する。
- 世代交代では初期化しない。魂の引継ぎ画面で一切選択しなくても無条件で残る。
- 強くてニューゲームの育成データ初期化対象にも含めない。
- 現在の手動ゲームデータリセットもこの専用キーを削除しない。
- 開発用保護テストではこのキーも退避・復元対象とし、テスト中の解放を通常履歴へ混ぜない。

### 7. 旧状態からの復元

次の既存フラグを検出した場合、対応項目を解放済みかつ閲覧済みとして復元する。

| 既存状態 | 復元する項目 |
|---|---|
| `aiPet._tutorialDone` または学習済み言葉あり | 最初のことば |
| `aiPet.unlockedFeatures.shop` | 救済について |
| `aiPet.unlockedFeatures.online` とログイン確認済み状態 | オンライン機能 |
| `localStorage.tcg_tutorial_done_v2` | 思い出について。TCGが現在正式解放済みの場合だけカードについても復元 |
| `aiPet.shopTutorialCompleted` | レストランの基本 |
| `aiPet.apprentice.metMasters` に1件以上 | 修行への入口 |

ステータス画面には既存の閲覧フラグがないため、旧セーブでも次にステータス画面を開いた時点で `能力について` を未読解放する。
旧実装がログイン前に追加した未確認のオンライン項目と、TCG正式解放前に追加した未確認のカード項目は、現在の条件を満たしていない場合に履歴から取り除き、正しい段階の項目へ補正する。一度ログインまたはTCG正式解放を確認できた履歴は、後のログアウト・世代交代・進行リセットでは失わない。

## 主な実装

- `tutorial_core.js`
  - 項目カタログ、専用保存、旧状態移行、未読数、解放通知、分類画面。
  - `unlockTutorialEntry()`, `markTutorialViewed()`, `openTutorialArchive()`, `syncTutorialArchiveFromLegacy()`。
- `index.html`
  - 画面下部のチュートリアルボタンとスクリプト読込。
- `ai_core.js`
  - 初回言葉、救済、オンライン、通常探検の解放フック。
- `ui_controller.js`
  - ステータス画面、初回思い出、カード正式解放、最初の師匠との顔合わせの解放フック。
- `shop_map_core.js`
  - レストラン店内チュートリアル完了フック。
- `debug_test_core.js`
  - 専用保存キーの保護テスト退避・復元。

## 確定している将来仕様

なし。追加項目は、そのコンテンツの実装・表示タイミング・ネタバレ範囲を決定した上で個別に登録する。

## 構想段階の案

- 項目数が増えた場合、解放済み項目だけを対象にした検索や「未読のみ」絞り込みを追加する。

- 既存の一度きりの機能解放モーダルも、将来すべて非モーダル通知へ統一するか。
