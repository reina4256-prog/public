# 自動通知・失敗再試行の重複抑止仕様

状態: 未実装・仕様確定

## 対象範囲

状態変化を自動検知して出すAIの吹き出し、ゲーム内通知、警告、ログ等と、進展できない自律行動の再試行を共通して扱う。プレイヤーが自分で開く詳細画面とチュートリアル図鑑の恒久既読はそれぞれの所有仕様が扱う。外部通知にも同じ事象IDと状態エピソードを渡すが、実際の送信経路、配信時刻、日次集約はオンライン仕様が所有する。

## 現在の実装仕様

- コンテンツごとに個別の通知、吹き出し、失敗報告、一度だけのフラグがあり、ゲーム全体で同一状態を識別して重複を抑える共通基盤はない。
- チュートリアル通知等、一部には個別の重複防止があるが、自律行動の失敗再試行まで統一してはいない。

## 主な状態と実装

- 共通の状態識別子、通知済み状態、失敗した自律行動の待機状態、解除契機は未実装で、正確なフィールド名は未決定。
- 実装時は表示言語や翻訳後の文章ではなく、事象種別、発生元、対象、失敗理由、判定に使った関連状態を表す言語非依存IDから同一状態を識別する。

## 確定している将来仕様

- 同じ原因、発生元、対象および関連状態が継続している間を一つの「状態エピソード」として扱い、そのエピソードに対する同一の自動通知、AI吹き出し、警告、ログは最初の一回だけ表示する。文章だけを比較して抑止せず、言語非依存の事象IDと状態識別子で判定する。
- 将来の外部通知を採用した場合も同じ事象IDと状態識別子を利用し、同じ状態エピソードをチャネル側の再接続や定期確認のたびに再送しない。危険度の段階移行等、個別仕様で別の通知契機として定義した実質的な状態変化は別事象として扱う。
- 状態エピソード中に進展できない同一の自律行動は、失敗処理と理由報告を一回行った後、関連状態が変わるまで同じ対象へ自動で再試行しない。材料不足、設備不足、経路なし、ロック中、容量不足等のまま、同じ判定と台詞を更新周期ごとに繰り返さない。
- 原因が解消された時点で状態エピソードを終了する。同じ問題がいったん解消した後に再発した場合は新しいエピソードとして扱い、再び一回だけ行動判定と通知を行える。
- ゲーム終了後の次回起動、タイトルへ戻った後の再開、セーブの再ロード等、表示ログや吹き出し履歴が初期化された後は、原因が未解決でも新しい表示セッション中に一回だけ自動判定と理由表示を行う。一般的な重複抑止履歴はセーブへ永続化せず、プレイヤーが以前の報告を画面上で確認できる表示セッション単位で管理する。履歴初期化後に何も反応せず、停止・故障と誤認される状態を作らない。
- プレイヤーがボタン、チャット、決定操作等から同じ処理を明示的にもう一度要求した場合は、自動発生の重複抑止を適用せず、その都度実行判定と失敗理由を返す。無反応に見せない。
- 対象、原因、必要素材、到達性、ロック、容量等の判定結果が実質的に変わった場合は、同じ大分類の事象でも新しい状態として再評価する。重要な変化まで古い重複抑止によって隠さない。
- 一回の処理で実際に進捗が生じ、次の対象、残数、工程等へ状態が変わる正常な反復行動は抑止しない。接客、複数個の仕込み、連続取得等は、それぞれ進行可能な限り通常どおり続ける。
- 失敗によって待機した自律行動は、所有コンテンツの規則に従って別の実行可能な行動へ進むか待機する。個別仕様が代替対象への自動切替を禁止している場合は、その禁止を優先する。
