# 通常探検詳細仕様

状態: 実装済み

## 対象範囲

島マップ上の `探検`、`森`、`山` 指示から始まる通常探検を扱う。目的地選択、移動、探索階層、体力・満腹度消費、能力条件、通常ドロップ、職業素材による上書き、帰還・中断・進捗を本書が所有する。

スカルダンジョンとクリスタル迷宮は、通常探検の目的地候補から専用UIへ引き渡される別システムである。入場後のルールは [`../dungeon/dungeon_common.md`](../dungeon/dungeon_common.md) と各ダンジョン仕様を参照する。島、施設、所持品、鮮度の共通規則は [`world_items_and_facilities.md`](world_items_and_facilities.md)、言葉・予定タスクの共通規則は [`ai_words_and_tasks.md`](ai_words_and_tasks.md) を参照する。

## 用語

- **通常探検**: 島の森、山、その他の通常候補へ移動し、`exploreState.depth` を進めながら抽選を繰り返す処理。
- **探索処理1回**: `processExploration()` が1回呼ばれ、体力・満腹度消費、階層進行、能力の壁、成功・失敗、ドロップ等を判定する単位。
- **浅層**: 1～3階。
- **中層**: 4～7階。
- **深層**: 8階以上。
- **ダンジョン探索**: スカルまたはクリスタルの専用ローグライク。通常探検の階層・抽選とは別である。

## 判定早見表

| 項目 | 現在の実装 |
|---|---|
| 手動指示 | 学習済みの `探検`、`森`、`山`。類義語は正規語へ変換する |
| 手動開始条件 | 冒険家へ弟子入り中、冒険家Rank 10以上、または `retired.explore` が真 |
| 手動タスク時間 | 60。予定一覧では分として表示されるが、実ループは約1秒ごとに1減る |
| 開始前予測 | 15階踏破と帰還判定の計16回の階層消費、探索中320更新分の連続消費、残量5を合算する。標準倍率・時計なしの必要量は体力・満腹度各38.6 |
| 探索処理ごとの消費 | 体力と満腹度をそれぞれ `2 × 探索用消費倍率 × 時計倍率` 消費 |
| 疲労帰還 | 探索処理の消費後、体力または満腹度が5以下なら短い準備ヒントを話して強制帰還。探検完了には数えない |
| 中層条件 | 活力50以上、素早さ30以上。未達なら能力不足だけを短く話し、体力-20、機嫌-20、強制帰還。探検完了には数えない |
| 深層条件 | 活力80以上、素早さ60以上、賢さ50以上。未達なら能力不足だけを短く話し、体力-40、機嫌-40、強制帰還。探検完了には数えない |
| 階層進行 | 能力値にかかわらず探索処理1回につき1階 |
| 実動最深部 | 森・山の定義は15階。旧データや未定義通常施設も実行時に15階未満なら15へ補正する |
| 最深部帰還 | 最深階を処理した次の探索処理で体力・満腹度を消費後、機嫌+20して帰還 |
| 神モード | 消費と負の数値ペナルティを防ぐが、中層・深層の能力不足による強制帰還は防がない |

## 現在の実装仕様

### 1. 指示語と開始資格

チャット入力は、完全一致を先に、部分一致を後に判定して次の正規語へ変換する。

| 正規語 | 主な類義語 |
|---|---|
| `探検` | 冒険、出かけ、外、散歩、探索、探検 |
| `森` | 森、もり、林、はやし |
| `山` | 山、やま |

- 入力語は未学習なら、記憶容量に空きがある場合に正規語として先に学習される。
- 手動指示は、正規語そのものが `aiPet.apprentice.learnedWords` に入っている場合だけ実行候補になる。`探検` を知っていても `森` と `山` は個別に学習が必要である。
- 手動の通常探検は、次のいずれかを満たすと `schedule` へ追加される。
  - `apprentice.currentMaster === 'explore'`
  - `apprentice.rank.explore >= 10`
  - `apprentice.retired.explore` が真
- 条件を満たさない場合は予定へ追加せず、冒険家を探すよう報告する。ただし入力語の学習自体はすでに完了している。
- `探検` は自動選択、`森` は `exploreTarget: 'forest'`、`山` は `exploreTarget: 'mountain'` を持つタスクになる。

### 2. 自律探検

- 手動指示と同じ `canUseNormalExploration()` を使い、冒険家へ弟子入り中、冒険家Rank 10以上、または `retired.explore` が真の場合だけ自律探検を選べる。
- 待機時の体力または満腹度が20未満なら、神モードまたは消費倍率0を除き自律行動を選ばない。
- `探検` を学習済みの場合、アイドル性格は自律行動候補として探検を選ぶことがある。ストイック・完璧超人も自己研鑽候補へ探検を含める。
- 自律探検は最初に `duration: 150` で予定へ追加されるが、タスク初期化時に60へ上書きされる。
- 保護テスト中は、待機時間と行動抽選だけを固定して `performIdleAction()` の実経路を1回実行できる。学習語、冒険家資格、開始前消費、目的地選択は本番と同じ判定を通る。

### 3. 通常の進行フロー

1. `explore` タスクを予定へ追加する。
2. 重病、開始前の体力・満腹度、目的地有無を確認する。
3. 目的地アセットを選び、`startBuildingInteraction()` で移動を開始する。
4. 到着時に `actionState: 'inside'`、`isIndoors: true` とし、探索用のアクション画面へ入る。
5. 通常目的地では約20更新ごとに `processExploration()` を呼ぶ。
6. 探索処理ごとに消費、階層、能力の壁、成功・失敗、ドロップを順に判定する。
7. 疲労、能力不足、最深部、資源枯渇等で `finishExploration()` を呼び、退出状態へ移る。
8. 次の更新でタスク完了処理が予定を取り除き、次の予定へ進む。

通常の更新間隔は50msで、`exploreTimer` が20に達するごとに探索処理を呼ぶため、画面が通常速度で動作していれば探索処理は名目上約1実秒に1回である。移動時間、描画停止、別モード、処理負荷によって実時間は変わり得る。

### 4. 目的地候補

#### 4.1 候補への追加

島の `assets` から次を候補にする。

- `type === 'nature'`
- `type === 'building'`
- `type === 'skull'` または `type === 'crystal'`
- UID、名前、種別からダンジョンと判定されたアセット

ダンジョン判定は、`skull` / `crystal` 種別、同接頭辞のUID、または名前にスカル、クリスタル、迷宮、ダンジョン、洞窟、水晶、鉱山等を含む場合に真となる。

候補は距離順ではなく、条件を満たす配列から一様ランダムに選ぶ。同種施設を複数配置すると、その施設種別が選ばれる総確率も個数に応じて増える。

#### 4.2 水域の向こう側

- 基準点は最初に見つかった畑、レストラン、小屋の中心とし、見つからなければ `(400, 240)` を使う。
- 基準点と目的地の間に水域がある場合、カジノ用の橋ルート判定 `isCasinoBridgeRouteComplete()` が真でなければ候補から除外する。
- 橋ルート判定が存在しない場合だけ、橋が2個以上あることを代替条件にする。

したがって、通常探検の対岸アクセスは単純な移動可能性ではなく、カジノ解放用の接続済み橋ルートへ依存している。

#### 4.3 指示・職業課題による選択優先度

| 優先 | 条件 | 選択 |
|---:|---|---|
| 1 | `森` 指示 | UIDが `palms` で始まるか、名前に森を含む通常候補から選ぶ |
| 1 | `山` 指示 | UIDが `mountain` で始まるか、名前に山を含む通常候補から選ぶ |
| 2 | 美容師Rank 1、2、9の課題中 | 85%で森系候補を優先する |
| 2 | 美容師Rank 6、7、8の課題中 | 90%でダンジョン候補を優先する |
| 3 | ダンジョンと通常候補が両方ある | 70%でダンジョン、30%で通常候補 |
| 4 | 片方だけ存在 | 存在する側から選ぶ |

- 冒険家Rank 10未満ではダンジョンを候補から除外する。`retired.explore` だけではダンジョン候補を解禁しない。
- `森` または `山` の直接指定で対応候補がない場合、通常は別種の目的地へフォールバックせず開始失敗になる。
- 到達経路を作れない場合は現在タスクを `aborted` にして終了する。
- 移動状態のまま約3秒間まったく座標が変化しない場合、スタック救済は現在タスクだけでなく予定全体を消去する。

### 5. ダンジョンへの引き渡し

- スカルまたはクリスタルへ到着すると、最終ロード後の `dungeon_core.js` ラッパーが通常の `processExploration()` より先に処理する。
- `apprentice.rank.explore >= 10` なら、予定をすべて消去し、訪問思い出を判定して専用ダンジョンUIを開く。
- Rank 10未満なら現在の探検タスクだけを消し、「免許皆伝が必要」と報告する。
- ダンジョン側の入場条件は `retired.explore` を参照しない。
- ダンジョン候補を選んだ時点では通常探検の開始前判定と目的地までの移動消費を受けるが、ダンジョン入場フックが動いた探索処理では通常探検の階層・ドロップ処理を行わない。

### 6. 主な状態

| 状態 | 内容 |
|---|---|
| `schedule[0].type` | 通常探検中は `explore` |
| `schedule[0].duration` | 手動では60。自律時の150は初期化後に60へ変更 |
| `schedule[0]._started` | タスク初期化済みか |
| `schedule[0].aborted` | 開始失敗・到達失敗等で完了報酬を抑止する印 |
| `schedule[0].exploreTarget` | `forest`、`mountain`、または未指定 |
| `exploreState.depth` | 現在の通常探検階層。開始時0 |
| `exploreState.maxDepth` | 森・山は施設定義から15。旧値・未定義通常施設は通常処理中に最低15へ補正 |
| `exploreState.currentFacility` | 目的地UIDの最初の `_` より前の文字列 |
| `exploreState.name` | `facilityData` またはアセットの表示名 |
| `interactionTarget` | 実際に移動・耐久度処理する目的地アセット |
| `indoorTarget` | 探索アクション画面で参照する目的地 |
| `exploreTimer` | 到着後の探索処理呼び出し間隔 |

`currentFacility` はアセットの `type` ではなくUID接頭辞から決まる。名前が森でもUIDが `palms_` で始まらなければ `facilityData.palms` を使わず、未定義接頭辞は `facilityData.default` へフォールバックする。

### 7. 開始前の安全判定

睡眠、休息、食事等を除く共通タスク安全判定が、未開始の探検にも適用される。

#### 7.1 予測式

```text
階層消費
  = (15階 + 帰還判定1回)
  × 2
  × 種族消費倍率
  × 悠久の懐中時計倍率

探索中の連続消費目安
  = 16回 × 20更新 × 0.005
  × 種族消費倍率
  × 悠久の懐中時計倍率

開始可能条件
  体力 >= 階層消費 + 連続消費目安 + 残量5
  かつ
  満腹度 >= 階層消費 + 連続消費目安 + 残量5
```

- 標準倍率・時計なしでは、階層消費32、探索中の連続消費目安1.6、残量5の合計38.6が体力・満腹度それぞれに必要となる。整数入力で安全に開始する目安は39である。
- 手動・自律のどちらも同じ15階基準で計算し、予定へ追加された時点の `duration` には依存しない。
- 目的地までの移動時間と敵遭遇時の追加体力消費は不定なため計算へ含めない。ゲーム内では数値を表示せず、チュートリアル図鑑で余裕を持って準備するよう案内する。
- 条件不足では現在タスクを `aborted` にして予定から取り除き、探検を開始しない。
- キャラクターの吹き出しには体力・満腹度の準備不足と休息・食事のヒントだけを表示し、必要量、現在量、不足量は表示しない。初回だけチュートリアル図鑑の `探検前の準備` を未読解放する。

#### 7.2 種族消費倍率

- 開始前判定、毎更新の共通消費、探索処理、敵遭遇時の追加体力消費は、`getTraitData().consumption` が0ならすべて0として扱う。
- 消費倍率0では開始必要量と残量5も0になり、体力・満腹度が5以下でも疲労帰還を発生させない。

#### 7.3 悠久の懐中時計

悠久の懐中時計は装備状態ではなく、所持品に存在する最初の1個を参照する。

```text
時計倍率 = max(0.1, 0.8 - 0.02 × 強化値)
```

- 未所持は1.0。
- 未強化品は0.8。
- 開始前予測、毎更新の共通消費、探索処理ごとの消費、敵遭遇時の追加体力消費へ適用する。
- 中層・深層の固定負傷値20・40には適用しない。

### 8. 探検中の消費

#### 8.1 予定実行中の連続消費

プレイモードで探検タスクが予定の先頭にある間、移動中と探索中の両方で更新ごとに次を消費する。

```text
体力   -= 0.005 × 種族消費倍率 × 時計倍率
満腹度 -= 0.005 × 種族消費倍率 × 時計倍率
機嫌   -= 0.01  × 種族消費倍率
```

通常の50ms更新が維持されれば、1実秒あたり体力・満腹度は約 `0.1 × 倍率`、機嫌は約 `0.2 × 種族消費倍率` 減る。開始前予測式は探索処理16回までの320更新分を含めるが、目的地までの移動時間は含めない。

#### 8.2 探索処理ごとの消費

各 `processExploration()` の冒頭で、神モードでなければ次を消費する。

```text
体力   -= 2 × 探索用消費倍率 × 時計倍率
満腹度 -= 2 × 探索用消費倍率 × 時計倍率
```

消費直後に体力または満腹度が5以下なら、キャラクターが体力・満腹度の限界と休息・食事のヒントだけを話し、初回だけチュートリアル図鑑の `探検前の準備` を未読解放する。数値や詳細画面は表示せず、`finishExploration({ completed: false, reason: 'resources' })` を呼ぶ。この回は階層進行、能力の壁、成功判定、ドロップ、耐久度減少を行わず、探検完了進捗も加算しない。

### 9. 階層と能力の壁

#### 9.1 最深部補正

- 探索開始時の `maxDepth` は `facilityData` から取得する。森と山は定義自体を15へ統一する。
- 探索処理では、旧セーブや未定義通常施設への保険として、`maxDepth < 15` なら15へ変更する。
- 新規探索は深度0から始まり、森・山は最初から15、default等は最初の探索処理で15へ補正される。
- 1回につき必ず1階進み、能力値による複数階スキップはない。

#### 9.2 能力条件

| 到達階 | 条件 | 条件不足時 |
|---:|---|---|
| 1～3 | 固定条件なし | 通常の成功判定へ進む |
| 4～7 | 活力50以上、素早さ30以上 | 体力-20、機嫌-20、強制帰還 |
| 8以上 | 活力80以上、素早さ60以上、賢さ50以上 | 体力-40、機嫌-40、強制帰還 |

- 条件判定前に探索処理ごとの体力・満腹度消費が入る。
- 標準倍率・時計なしで深層条件に失敗した同一探索処理では、体力は通常消費2と固定負傷40、満腹度は通常消費2、機嫌は固定40に加えて連続消費分が減る。
- 能力不足ではドロップ、能力成長、耐久度減少を行わない。
- 神モードでは数値ペナルティを加えないが、条件判定自体と強制帰還は実行する。
- 能力不足時は必要能力名、必要値、現在値、特定の訓練名を表示しない。キャラクターは「今の能力では危険」「もう少し成長してから」とだけ話し、初回だけチュートリアル図鑑の `さらに奥へ進むには` を未読解放する。
- 中層・深層の能力不足帰還はタスクへ `aborted` を付け、探検完了進捗へ加算しない。

#### 9.3 最深部到達

- 深度15の処理を終えた時点では帰還せず、その階の成功・失敗・ドロップを処理する。
- 次の探索処理の冒頭で再度体力・満腹度を消費し、`depth >= maxDepth` を確認する。
- 条件成立時は機嫌+20、「最深部に到達」として帰還する。
- 新規の通常目的地では、異常終了がなければ階層を処理する15回と帰還判定1回の、最低16回の探索処理が発生する。

### 10. 施設別の探索データ

通常の森・山と未定義施設で使う主要データは次のとおり。

| 接頭辞 | 表示名 | 成功判定能力 | 階層難易度係数 | 定義上の最深部 | 新規探索の実動最深部 |
|---|---|---|---:|---:|---:|
| `palms` | 迷いの森 | 機嫌 | 2 | 15 | 15 |
| `mountain` | 険しい山 | 活力 | 4 | 15 | 15 |
| 未定義 | 建物 | 活力 | 1 | 3 | 15 |

`facilityData` にはスカル、クリスタル、王城、カジノ跡地の値もある。ただしスカル・クリスタルは専用ダンジョンへ引き渡され、王城・カジノが通常候補になるかは実際のアセット種別とUIDに依存する。

### 11. 成功判定

現在階層を1増やす直前に、次を計算する。式中の到達階は、増加後の階層と一致する。

```text
難易度 = 到達階 × 施設の階層難易度係数
参照能力 = aiPet.stats[施設の成功判定能力]

基本成功率 = 参照能力 ÷ (難易度 + 1)

参照能力 < 難易度 × 0.5 の場合は成功率10%
それ以外は基本成功率を10～100%へ制限
```

#### 11.1 成功してアイテムを発見した場合

- アイテムを所持品へ追加する。所持数上限の確認はない。
- 冒険家の次世代特別依頼対象なら、取得した個体へ証明情報を記録する。
- アイテム思い出の獲得判定を行う。
- 機嫌を `1 × 種族の機嫌成長倍率` 増やす。
- この回は施設参照能力の成長と「探索継続による機嫌低下」を行わない。

#### 11.2 成功したがアイテムを発見しなかった場合

- 施設の成功判定能力を `1 × その能力の種族成長倍率` 増やす。
- 神モードでなければ機嫌を `0.5 × 探索用消費倍率` 減らす。

#### 11.3 探索自体に失敗した場合

- 「敵に遭遇して逃げた」と報告する。
- 神モードでなければ、体力を `5 × 探索用消費倍率 × 時計倍率`、機嫌を5追加で減らす。
- 初めに支払った探索処理ごとの体力・満腹度消費は返さない。

### 12. アイテム発見率

探索成功後、次の式でアイテムを発見するかを判定する。

```text
能力余剰 = max(0, 参照能力 - 難易度)
発見率   = 0.30 + 0.005 × 能力余剰

森または山なら +0.20
最終上限は0.80
```

- 最低値は通常施設30%、森・山50%である。
- 上限は80%。
- 探求者のリボンはこの発見率自体を上げず、発見成功後の深層レア置換率だけを上げる。

### 13. 基礎候補

`facilityData.items` が季節別オブジェクトの場合、現在季節の配列の後ろへ `default` 配列を連結する。同じIDが両方にある場合は重複を除かないため、そのIDの抽選比率が上がる。

| 場所 | 季節 | 抽選配列 |
|---|---|---|
| 森 | 春 | `herb_spring`, `wood`, `wood`, `seed_carrot`, `seed_pepper` |
| 森 | 夏 | `bug_beetle`, `wood`, `wood`, `seed_carrot`, `seed_pepper` |
| 森 | 秋 | `wood`, `wood`, `seed_carrot`, `seed_pepper` |
| 森 | 冬 | `wood`, `wood`, `seed_carrot`, `seed_pepper` |
| 山 | 春・冬 | `stone`, `iron` |
| 山 | 夏 | `bug_beetle`, `stone`, `stone`, `iron` |
| 山 | 秋 | `mushroom`, `stone`, `stone`, `iron` |
| default | 全季節 | `stone` |

パティシエ素材や美容師Rank 2素材は、条件を満たすとこの基礎配列へ追加される場合がある。

### 14. 深層レア置換

深度8以上でアイテム発見に成功した場合、基礎候補を選んだ後に深層レア判定を行う。

#### 14.1 探求者のリボン

探求者のリボンも装備状態ではなく、所持品に存在する最初の1個を参照する。

```text
リボン補正 B = 0                              未所持
リボン補正 B = 0.15 + 0.02 × 強化値           所持

良質素材化率 R = 0.50 + B
第1特別品しきい値 C = 0.15 + B × 0.5
硬貨の実確率       = 0.10 + B × 0.5
```

これらの確率はコード上で100%へ明示的に制限していない。

#### 14.2 場所別の置換

| 場所 | 第1特別品 | 次の特別品 | 通常素材の置換 |
|---|---|---|---|
| 山 | `crystal` を確率 `C` | `coin` を実確率 `0.10 + B×0.5` | 元候補が `stone` なら確率 `R` で `high_stone` |
| 森 | `book` を確率 `C` | `coin` を実確率 `0.10 + B×0.5` | 元候補が `wood` なら確率 `R` で `high_wood` |
| その他 | なし | なし | `wood` / `stone` を確率 `R` で良質素材へ変更 |

第1特別品と硬貨は1つの乱数の累積範囲で判定し、どちらにも該当しない場合だけ良質素材化を別乱数で判定する。

### 15. 職業・特別依頼による最終上書き

深層レア判定の後、次の順でアイテムIDを上書きする。後の行ほど優先される。同じ探索で複数条件が成立しても、最終的に残るアイテムは1個である。

| 順 | 条件 | 上書き |
|---:|---|---|
| 1 | 薬剤師素材解放済み、35% | `herb` または `water` を50%ずつ |
| 2 | 毒キノコ課題中または薬剤師Rank 10以上、20% | `poison_mushroom` |
| 3 | パティシエのハチミツ解放済みまたはRank 1課題中、森、35% | `honey` |
| 4 | 美容師Rank 1課題中、森、65% | `pure_spring_water` |
| 4 | 美容師Rank 2課題中、森、55% | `seed_aroma_herb` |
| 4 | 美容師Rank 9課題中、森、70% | `seed_aroma_herb` |
| 4 | 美容師Rank 6～8課題中、深度12以上、60% | `rainbow_drop` |
| 4 | 美容師素材解放済みまたは美容師課題中、上記不成立、18% | 深度20以上でさらに35%なら `rainbow_drop`、それ以外は `pure_spring_water` |
| 5 | アトリエ図面所持、神秘の霊糸未所持、仕立屋未解放、15% | `mystic_thread` |
| 6 | 冒険家の次世代特別依頼対象が基礎候補に含まれる | 特別依頼対象を確定 |

冒険家特別依頼対象は基礎候補選択直後にも一度代入されるが、最後に再代入されるため、最終結果では他職素材より優先される。

#### 15.1 保護テスト中の課題素材固定

保護テスト環境でのみ、Debugの「森・山の探検ドロップ」を切り替えられる。通常セーブ中は設定値があっても無効であり、通常の抽選順へ影響しない。

| 冒険家課題 | 森 | 山 |
|---|---|---|
| Rank 3 | `wood` | `stone` |
| Rank 8 | `high_wood` | `high_stone` |

- `現在の冒険家課題素材だけ（確率は通常）` は、通常の探索成功率と発見率を残し、発見したアイテムIDだけを上表へ固定する。
- `現在の冒険家課題素材を各階で確定` は、探索成功率と発見率を100%にし、上表の素材を各探索処理で1個取得する。ただし開始前の体力・満腹度判定、中層・深層の能力の壁、階層消費、最深部帰還は残る。
- 固定対象は通常の冒険家Rank 3または8課題を受注中の森・山だけ。他の場所、他Rank、冒険家の次世代特別依頼だけを受注中の場合は通常抽選になる。
- 固定中は幻の染料花の先行取得を抑止し、職業・特別依頼による上書き後に課題素材を再適用する。このため対象素材以外は混ざらない。
- 操作と保護範囲は [`../internal/debug_and_testing.md`](../internal/debug_and_testing.md) を参照する。

### 16. 幻の染料花

次をすべて満たす場合、通常の成功率・発見率・上書き順より先に `phantom_dye_flower` を1個取得する。

- 幻の染料花の噂を解放済み。
- このセーブでまだ発見済みになっていない。
- 現在の所持品に同アイテムがない。
- `currentFacility` が `palms` または `nature`。
- 中層・深層の能力の壁を通過済み。

この取得回はその場で保存して処理を終了し、通常の成功・失敗、能力成長、施設耐久度減少を行わない。探索タスク自体は続く。

### 17. 施設耐久度

- 成功・失敗処理の末尾まで到達した探索処理だけ、`interactionTarget.durability` が数値なら1減らす。
- 疲労帰還、最深部帰還、能力不足帰還、幻の染料花取得では減らさない。
- 0以下になり、施設データに `depletedType` があれば、対象アセットの画像・種別を跡地へ変更して帰還する。
- `depletedType` がなければ、`assets` 内で同一オブジェクト参照のUIDを探して削除し、帰還する。
- 森と山の `facilityData` には `durability: 5` があるが、通常探検の開始処理はこの値を目的地アセットへコピーしない。目的地アセット自身に数値の `durability` がない限り、耐久度は減らない。

### 18. 帰還・中断・予定への影響

| 終了要因 | 現在タスク | 後続予定 | `finishExploration()` | 完了系進捗 |
|---|---|---|---|---|
| 開始前の体力・満腹度不足 | `aborted` で削除 | 保持 | 呼ばない | 加算しない |
| 重病 | `aborted` で削除 | 保持 | 呼ばない | 加算しない |
| 目的地なし・経路作成失敗 | `aborted` で削除 | 保持 | 呼ばない | 加算しない |
| 移動スタック救済 | 全予定を消去 | 消去 | 呼ばない | 加算しない |
| 手動の予定中断 | 全予定を消去 | 消去 | 呼ばない | 加算しない |
| 探索中に体力・満腹度5以下 | `aborted`、durationを0へ | 保持 | `completed: false` で呼ぶ | 加算しない |
| 中層・深層の能力不足 | `aborted`、durationを0へ | 保持 | `completed: false` で呼ぶ | 加算しない |
| 最深部到達 | durationを0へ | 保持 | 呼ぶ | 完了扱い |
| 施設枯渇 | durationを0へ | 保持 | 呼ぶ | 完了扱い |
| 皆伝済みでダンジョン入場 | 全予定を消去 | 消去 | 呼ばない | 通常探検完了としては加算しない |
| 未皆伝でダンジョン到達 | 現在探検だけ削除 | 保持 | 呼ばない | 加算しない |

`finishExploration()` は `completed` を受け取り、疲労・能力不足ではタスクへ `aborted` を付ける。`lastExplorationResult` とタスク上の `explorationResult` には完了/中断、理由、階層、施設、記録時刻を残す。

### 19. 進捗・思い出

- 通常探索処理へ入るたび、行動思い出 `action_cave`（表示上の「未知の洞窟探検」）を世代単位の重複防止付きで判定する。森・山でも同じキーを使う。
- アイテム取得時はアイテム思い出を判定する。
- 正常完了した場合だけ、`finishExploration()` は旧単一 `apprentice.activeQuest` の説明に `探検` を含む場合に `qVal` を1増やす。
- 正常完了した場合だけ、`finishExploration()` は `progressDailyQuest('explore')` を呼ぶ。
- その後の共通タスク完了処理も、説明に `探検` と `回行おう` を含む複数依頼を進め、さらに `progressDailyQuest('explore')` を呼ぶ。
- 現在の標準デイリー依頼には `explore` がないが、探検型デイリーが存在する状態では1回の帰還で二重加算され得る。
- 疲労・能力不足は完了系進捗へ加算しない。施設枯渇は従来どおり正常完了として扱う。
- 冒険家Rank 3・8の通常課題は最終的に所持品数を確認するため、帰還理由ではなく必要素材を実際に所持していることが重要となる。文字列所持品と鮮度付きオブジェクト所持品を同じアイテムIDとして数え、HUD表示と師匠への報告判定も一致する。納品時もアイテムIDで必要数だけを除去する。詳細は [`../careers/basic/adventurer.md`](../careers/basic/adventurer.md) を参照する。

### 20. 保存・再読み込み・リセット

- `aiPet` 全体をJSON保存するため、`schedule`、`exploreState`、`exploreTimer`、`actionState`、`interactionTarget` も保存対象になる。
- `assets` は別の保存キーへ保存する。
- ページ読み込み時のオフライン進行は、探検を通常の予定として処理し、実時間1分につき durationを1、体力を0.5、満腹度を `0.5 + 活力×0.005` 減らす。通常探検の階層、成功、ドロップは処理しない。
- ゲーム本編を開始する処理は `actionState`、屋内状態、移動経路、予定を強制リセットする。このため再読み込み後に通常探検をその場から再開する仕様にはなっていない。
- オフライン進行で減った体力・満腹度は残り得るが、途中の通常探検成果は生成しない。
- 手動の予定中断は `exploreState` を `null` にする。
- `finishExploration()` 自体は `exploreState` を消去せず、次の施設操作・手動中断・世代処理等まで最後の階層情報が残る。

## 既知の不一致・未検証

### 優先度: 高

- なし。2026-08-04に、自律資格、15階の開始必要量、森・山15階、疲労・能力不足の中断扱い、消費倍率0を決定・実装した。

### 優先度: 中

- 森・山の `facilityData.durability` は目的地アセットへ自動反映されず、通常配置では枯渇処理が動かない可能性がある。
- 対岸候補判定が通常の経路探索ではなく、カジノ用の橋完成条件へ依存する。
- 冒険家の次世代特別依頼候補作成はアセットの `type` を施設キーとして集め、`nature` を `palms` へ補完するが `mountain` へは補完しない。山の基礎候補が依頼候補から欠ける可能性がある。
- 通常探検で得る行動思い出が、森・山でも内部キー `action_cave` になっている。
- `finishExploration()` と共通完了処理がデイリー進捗をそれぞれ呼ぶ。
- 予定一覧の60分表示、約1秒ごとのduration減少、約16秒で起きる最深部帰還が同じ時間単位に見えない。

### 要検証

- `processExploration()` には `exploreTimer % 20` と `task.duration % 20` の2つの呼び出し経路がある。現在の通常施設は前者で最深部へ到達して後者の最初の条件へ届きにくいが、将来の深い通常施設や高速化状態では追加呼び出しになる可能性がある。
- 再読み込みでは `interactionTarget` と `assets` が別々にJSON復元されるため、同一オブジェクト参照を前提にした施設削除が成立しない可能性がある。ただしゲーム開始時に予定自体が消去される。
- 美容師の森優先フィルターに文字化けした名前判定が残る。`type === 'nature'` 等で通常の森は拾えるが、名前だけで判定する特殊アセットは漏れる可能性がある。
- 神モードで能力不足時に強制帰還する挙動が意図どおりか未確認。
