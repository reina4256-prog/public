# 共通ダイアログ・警告・通知UI仕様

状態: 一部実装

## 対象範囲

確認、警告、エラー、情報通知、文字入力、選択肢等をプレイヤーまたは開発者へ表示する共通UIと、ブラウザ・OS標準ダイアログを使用しないための全体制約を扱う。各コンテンツ固有の文面、発生条件、選択後の処理は、そのコンテンツの所有仕様書が管理する。

## 現在の実装仕様

- 師匠との会話イベント、各種オーバーレイ、ゲーム内通知、専用確認画面等、ゲームの見た目に合わせた独自UIが複数存在する。
- 一方、コード全体には `alert()`、`confirm()`、`prompt()` の直接呼出しが多数残っている。通常ゲーム、オンライン、クラウド、ダンジョン、闘技場、防衛戦、放牧、デバッグ等に分散し、一部の共通通知関数も独自UIを利用できない場合に `alert()` へ戻る。
- ブラウザ標準ダイアログはゲーム画面と外観が異なり、表示位置、配色、ボタン文言、入力方法、一時停止、前後関係、ローカライズをゲーム側で一貫して制御できない。

## 全体制約

- 新しく実装または変更するゲームコードでは、通常機能、オンライン機能、エラー処理、開発者向け機能を問わず、`window.alert()`／`alert()`、`window.confirm()`／`confirm()`、`window.prompt()`／`prompt()` を直接追加・利用しない。
- 警告を表示する場合も、ゲームの画面デザイン、入力体系、ローカライズ、一時停止規則に従うゲーム内UIを使用する。重要な警告ほどブラウザ標準ダイアログへ逃がさず、結果と選択肢をゲーム内で具体的に示す。
- OSのマイク許可、ファイル選択、フルスクリーン許可、ブラウザ終了時の制限された確認等、実行環境が所有してゲーム側から置換できない画面は例外とする。ただし、それらの前後説明と失敗後の案内はゲーム内UIで行い、例外を理由に任意の警告へ標準ダイアログを使用しない。
- 既存の直接呼出しは現行動作として容認するのではなく、共通UIへの移行が必要な実装不一致とする。対象機能を変更する実装ターンでは、同じ導線に残る標準ダイアログもあわせて置換し、新機能の完了報告時に新しい直接呼出しを残さない。

## 共通UIの役割

- 操作を求めない短い成功・情報通知は、ゲーム内トースト、ログ、吹き出し、画面内メッセージのうち、その機能に適した非モーダル表示を使う。
- 判断が必要な警告と確認は共通モーダルを使い、`修正する`、`承知して保存する`、`削除する`、`戻る` 等、実際に起きる結果が分かるボタン名を表示する。曖昧な `OK`／`キャンセル` だけで重大操作を選ばせない。
- 文字入力や名称入力はゲーム内入力画面を使い、入力規則、文字数、現在値、確定・取消を同じ画面で示す。ブラウザの `prompt()` は使わない。
- 複数の関連警告は別々の確認画面を連続表示せず、可能な限り一つのゲーム内UIへ集約する。ただし、本人音声の外部送信や完全初期化等、段階を分けること自体が安全要件である場合は、目的の異なる確認として明示的に分けてよい。
- 情報、注意、危険、成功、失敗、入力、選択の表示種別を言語非依存IDで管理し、見出し、本文、ボタン、代替文、読み上げ対象外の区分をローカライズ境界で解決する。

## 入力・一時停止・安全性

- モーダル表示前のゲーム停止状態とフォーカス位置を保存し、閉じた後は元の状態へ戻す。表示前から別の理由で停止していた場合は、閉じても通常進行を勝手に再開しない。
- モーダル表示中は背後のゲームへキーボード、マウス、タッチ、ゲームパッド入力を通さず、フォーカスを画面内へ閉じ込める。閉じた後は起点となった操作要素または安全なゲーム画面へフォーカスを戻す。
- 決定、戻る、Escape、方向入力、タッチ操作を共通化する。削除、上書き、完全初期化、世代交代等の重大操作は、Escapeや背景クリックを肯定扱いにせず、安全側の取消として処理する。
- 動的な名前、件数、エラー詳細を表示するときは文字列として挿入し、HTMLとして解釈させない。プレイヤー作成文字列を表示する場合も同じ規則に従う。
- 従来の同期的な `confirm()`／`prompt()` に依存しないよう、共通確認・入力UIは結果を非同期で返し、呼出し側は確定後にだけ破壊的処理や保存処理を実行する。

## ローカライズと検証

- 新規・変更する見出し、本文、ボタン、入力説明、代替通知は、対応する全言語カタログへ同じターンで登録する。動的値はプレースホルダーを使い、プレイヤー名や作品名を保存時に翻訳しない。
- 狭い画面、長い翻訳文、大きな文字、キーボード、タッチ、ゲームパッドで、内容、ボタン、スクロール、フォーカスが欠けないことを確認する。
- JavaScript変更時は直接の標準ダイアログ呼出しを検索し、変更対象の導線へ新規追加がないことを確認する。将来、禁止呼出しを検出する静的チェックを通常検証へ追加できる構造にする。

## 確定している将来仕様

- 情報通知、警告、確認、選択、文字入力を扱う共通ゲーム内ダイアログ基盤を用意し、現在分散している独自オーバーレイからも利用できるようにする。
- 現在残っている標準ダイアログは、影響の大きい破壊的操作と通常プレイ中に発生する警告から優先して移行し、最終的には実行環境が所有する不可避な画面以外をゲーム内UIへ統一する。
- 音楽制作の容量警告、復旧下書き、CD更新・削除、音声権利確認、作品バックアップ、マイク失敗もこの共通制約に従う。

## 構想段階の案

- 現時点で、確定済みの共通ダイアログ基盤とは別の構想案はない。

## 未決定事項

- 共通UIの正確なAPI名、見た目、アニメーション、効果音、各表示種別の既定アイコン。
- 現在残っている標準ダイアログの一括移行順序と、開発者専用画面を製品UIと同じ見た目にする範囲。

## 既知の不一致・未検証

- 現行JavaScriptには多数の `alert()`、`confirm()`、`prompt()` が残り、本仕様の将来制約を満たしていない。
- 同期ダイアログの直後に処理を続けるコードは、共通非同期UIへの機械的な置換だけでは成立しない。対象ごとに制御フロー、二重実行防止、保存タイミング、一時停止復元を確認する必要がある。
