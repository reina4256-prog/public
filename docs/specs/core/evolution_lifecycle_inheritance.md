# 進化・余生・世代交代・引継ぎ仕様

状態: 実装済み

## 対象範囲

進化判定、進化演出、寿命、免許皆伝後の余生、死亡、思い出生成、魂の引継ぎ、強くてニューゲームを扱う。

## 現在の実装仕様

### 進化

- 11種族に分岐・多段階・クロス進化を含む進化ツリーがある。
- 進化条件は能力、行動、性格、病気・薬の扱い、過去の姿など複数要素を参照する。
- 進化時は対応動画を使い、進化後の姿と履歴を更新する。
- ダンジョンの系譜特性は現在姿だけでなく `pastSkins` を参照する場合がある。
- 病気の放置や薬の乱用から闇落ち系の特殊進化へ到達する場合がある。

### 免許皆伝後と余生

- 1世代で1職業を皆伝すると、称号・能力報酬を受けて余生方針を選ぶ。
- 現在の余生タスクは `life_mentor`、`life_monument`、`life_seeker`、`life_guardian`、`life_author`、`life_slowlife` の6系統。
- 現在の `determineLifePath()` は、`actionHistory` の勉強、筋トレ、仕事、休息、世話、自由行動と、力・賢さ・機嫌の現在値から6方針のスコアを計算し、最大の1方針を自動決定する。弟子入りした職業は判定式へ使用していない。
- `actionHistory` はAI本体と一緒に保存され、通常の新規開始・世代交代で通る `applyInitialPet()` ではゼロ初期化される。ただし履歴自体に対象世代IDがなく、読込時に現在世代との一致を検証する防御はない。また現在の行動処理には、自由行動の一部で `free` を増やす箇所以外に `study`、`train`、`work`、`rest`、`care` を加算する接続が見当たらず、育て方を正しく集計できていない。
- 弟子、モニュメント、秘伝書、能力成長、施設保全など、方針ごとに遺産や効果が異なる。
- 現在の後進育成は余生タスクを1回終えるたびに一番弟子を作り直し、本人の全能力へ `賢さ / 100` を掛けた値を弟子の能力として上書きする。進捗段階や完成待ちはない。
- 現在のモニュメントと秘伝書は25%ずつ進み、4回で完成する。どちらも本人の最大能力種別を選び、モニュメントはその能力へ行動中の継続加算等を行い、秘伝書は最大能力値そのものを1回の加算値として保存する。
- 現在の秘伝書は引継ぎ画面で個別に複数冊を同時選択でき、選んだ各冊に10回分の使用回数を設定する。次世代では正常完了した行動の種類を問わず、完了ごとに有効な全秘伝書が同時発動し、各冊の保存値を対応能力へ加算して1回分ずつ消費する。著者の最大能力値を最大10回、複数冊なら冊数分だけ重複加算できるため、能力値が急激に膨らみ得る。
- 現在の限界突破は余生タスクごとにランダムで筋トレ、勉強、歩行を選び、世代数に比例した倍率で能力を直接加算する。ただし歩行開始時の内部値は `walk` なのに完了時は `move` と比較しているため、素早さ分岐へ入らず活力へ加算される。
- 現在の守護者は余生タスクを終えるたびに全農地の成長度と耐久値を持つ全施設を100へ戻し、スローライフは本人の体力と満腹度を100へ戻す。
- 余生タスクは年齢を進める。大事業は体力・満腹度20未満で開始せず、スローライフは例外。
- マイホーム内の余生は屋内状態を維持し、自動反復と早送りを利用できる。
- 現在は150分の余生タスク完了ごとに、後進育成・限界突破では寿命の10%、モニュメント・秘伝書では25%、守護者・スローライフでは5%を年齢へ直接加算する。さらに `isFastForwardLife` 中は更新60回ごとに1歳を加え、体力・満腹度・機嫌を100へ戻し、先頭予定の残り時間を15分減らす。この早送り処理は先頭予定が余生タスクかを検証していない。余生UI等でゲーム更新が停止すると加算も停止するが、早送りフラグを保持したまま通常更新へ戻れば再開する。

### 死亡と思い出

- `age >= lifespan` で死亡処理へ進む。
- 現在の種族・進化形態から世代付きの思い出を生成してから引継ぎ画面を開く。
- 同一世代で同一人物カードを重複取得しないなど、世代単位の獲得ガードがある。

### 魂の引継ぎ

- 選択肢は能力、持ち物、語彙・記憶領域、職業ライセンス、姿と性格、マップ、所持金。
- 基本費用は能力500G、持ち物300G、語彙400G、ライセンス800G、姿と性格200G、マップ300G、Gold500G。
- 能力引継ぎ率は10%刻みで、世代数に応じ上限が上がる。
- 将来追加する個体別の最大満腹度は、独立した有料項目ではなく既存の `能力値の引継ぎ` に含める。継承後の値は `100 + floor((前世の最大満腹度 - 100) × 選択率)` とし、基礎値100を重複加算しない。端数は既存能力値と同じく切り捨てる。
- 重病、風邪、腹痛、中毒等の病気・症状は引継ぎ対象ではない。能力、持ち物、語彙、ライセンス、姿と性格、マップ、Goldのどれを選んでも次世代へ渡さず、新しい主人公は健康な状態から開始する。
- 集中、頑丈その他の一時バフも、どの引継ぎ項目を選んでも次世代へ渡さず、新しい主人公ではすべて解除する。
- 支払いには手持ちGoldと金庫Goldを合算する。
- 選ばなかった要素は最終警告に列挙する。
- 図鑑と音楽館は選択にかかわらず保持する。
- チュートリアル履歴も選択にかかわらず保持する。保存境界と非表示方針は [`tutorial_archive.md`](tutorial_archive.md) が所有する。
- 持ち物を引き継ぎ、マップを引き継がない場合は倉庫・冷凍庫の中身を手持ちへ退避する。冷凍品は鮮度を再開する。
- マップ引継ぎは施設、店舗成長、金庫、カジノコイン、購入済みトランプ、カジノ設備を保持する。
- マップを引き継がない場合、マップ所有のカジノ状態はリセットする。
- コンシェルジュと現在のマイホーム屋内状態は、マップ引継ぎとライセンス引継ぎの両方を選び、前世にコンシェルジュが存在した場合だけ次世代へ保持する。片方でも欠ければ、コンシェルジュの存在フラグと屋内状態を初期化し、マイホーム屋内へ入れない。
- 将来の島自由エディット解放後、編集済み配置がある状態でマップを引き継がずに進める場合は、配置が初期化されることをゲーム内UIで警告する。エディット機能の解放自体は保持する。詳細は [`main_map_editor.md`](main_map_editor.md)。
- 将来のマイホーム自由エディットは、コンシェルジュ皆伝後にマップ引継ぎとライセンス引継ぎの両方を選んだ次世代会話で初回解放する。機能の解放状態はゲーム全体の完全初期化以外では永久保持するが、編集済み配置は両方の引継ぎを選んだ場合だけ次世代へ保持する。詳細は [`../myhome/myhome_editor_and_concierge_points.md`](../myhome/myhome_editor_and_concierge_points.md)。
- 音楽制作室の初回増築成立後は `音楽制作解放済み` を同じセーブ系譜へ永久保持する。マイホーム屋内が引継ぎ条件不足で初期化された場合、音楽室の現在配置も一旦失われるが、後の世代で利用可能なマイホーム屋内を再建・復旧すれば、200コンシェルジュポイントを貯め直さず安全な初期配置を復元する。編集済みの音楽室配置を保持できる条件は他のマイホーム屋内と同じとし、詳細は [`../collections/music_creation_studio.md`](../collections/music_creation_studio.md) が所有する。
- 将来の水槽・池に収容中の魚はマップ状態として扱い、マップ引継ぎがあれば持ち物引継ぎなしでも設備内に残す。マップなし・持ち物ありなら新鮮な魚として手持ちへ退避し、両方なしなら魚も初期化する。マイホームだけはマップのみでは通常屋内状態を維持できないため、収容魚をマップ所有の専用保護データへ分離し、生態進行を停止して次の入室可能時まで保持する。初期化、手持ち退避、保護が発生する選択は `次の世代へ` の最終確定前に個体数と具体的な結果を警告する。詳細は [`indoor_aquariums_and_ponds.md`](indoor_aquariums_and_ponds.md) が所有する。
- 未完了のレストラン一度だけ仕込み指示はマップ引継ぎの有無にかかわらず世代交代時に初期化し、残件があれば `次の世代へ` の最終確認へ件数を表示する。レストランのガンビット本体や恒久設定とは別に扱い、詳細は [`../business/restaurant_business.md`](../business/restaurant_business.md) が所有する。
- `次の世代へ` の最終確認は、選択しなかった通常引継ぎ要素、自由エディット配置、マイホーム配置・増築・コンシェルジュポイント、水槽・池、マイホーム保護魚、未完了の仕込み指示その他の確定済み警告を別々のダイアログへ分散させず、一つのゲーム内UIへ集約する。各項目に、初期化、手持ち退避、保護移行、保持等の結果と、対象施設名・件数・個体数を表示し、詳細を確認してから一度だけ世代交代を確定する。
- 美容師皆伝済みで姿と性格を引き継ぐと、カラーとオーラも引き継ぐ。
- 余生で作った弟子、モニュメント、秘伝書は個別の有料選択肢となり、選ばなければ消滅する。

### 職業と次世代

- 通常は皆伝Rank 10だけが恒久的な職歴として扱われ、中途Rankや破門状態は次世代で未入門へ戻る。
- ライセンス引継ぎは職業Rankと、次世代限定の特別依頼対象を保持する。
- 過去能力が条件を満たすと、次世代の師匠初対面で特待生・即皆伝が発生する場合がある。

## 確定している将来仕様

- 新職業を追加するときも、皆伝後の余生・次世代特別依頼・人物思い出との接続を定義する。
- 余生方針は皆伝した職業別には決めず、その世代における主人公本人の育て方から共通判定する。販売員も例外にせず、特定職業を皆伝したことだけで選ばれる職業専用余生は設けない。現在の6方針を固定上限とはせず、新しく利用可能になった行動や遊び方に対応する共通方針を追加できるカタログ構造へ改める。
- 現在の6方針に加え、共通余生候補として `composer`（音楽を遺す者）、`artisan`（希代の職人）、`pathfinder`（冒険の語り部）、`community`（島の架け橋）、`commander`（歴戦の指揮者）を追加する。いずれも職業皆伝の種類ではなく、その世代で本人が実際に行った活動から選ぶ。
- `composer` は音楽制作室での作曲、編曲、共同制作、`artisan` は料理、鍛冶、裁縫、菓子作り、建築等の制作、`pathfinder` はダンジョン、森、山、探索、救助、`community` は接客、店舗勤務、住人交流、贈与、共同活動、`commander` は闘技場、防衛戦、住人編成戦闘を主な判定対象とする。店舗内でも接客・会計時間は `community`、商品制作時間は `artisan` へ分ける。
- 既存6方針と追加5方針はカタログ内で対等な候補とし、列挙順を優先順位に使わない。主な活動対応は、`mentor` を他者への指導・手助け・世話、`monument` を島の大規模建築・公共施設整備、`seeker` を勉強・筋トレ・ランニング、`guardian` を施設点検・修理・島や住人を守る活動、`author` を勉強・研究・読書・言葉に関する活動、`slowlife` を休息・散歩・釣り等の趣味・自由時間とする。`仕事` のような広い一括区分だけで加点せず、接客、制作、建築、修理、研究等の言語非依存活動タグへ細分化する。
- 原則として全方針は、その世代の本人が対応行動を正常完了し、対応活動が合計60ゲーム内分以上、または方針別主要実績が1回以上の場合だけ候補になる。機能解放だけでは候補にしない。`slowlife` も通常は同じ条件で評価するが、どの方針も候補にならなかった場合だけ安全な最終候補として選べる。条件と時間は方針ごとに後から調整可能にする。
- 余生判定だけを目的として、1回の完了行動から同一方針へ加算できる時間を初期150ゲーム内分、1ゲーム内日に同一方針へ加算できる時間を初期300ゲーム内分までとする。実際の能力上昇、売上、制作、探索結果、熟練度等は制限せず、長時間の店舗勤務や探索が余生判定だけを一方的に占有することを防ぐための集計上限とする。
- 一つの行動へ複数の方針タグを明示できる。例えば勉強は `seeker` と `author`、建築は `monument` と `artisan`、住人との共闘は `community` と `commander` に関係し得る。候補成立の60分判定には分配前の実活動時間を使う一方、方針スコアでは設定比率に従って時間を分配し、一つの行動から配る判定時間の合計が元の実活動時間を超えないようにする。
- 一つの方針だけに対応する行動は初期100%、二つなら50%ずつ、三つ以上なら均等に判定時間を分配する。共同制作等、意味上の比重が異なる行動は活動タグごとに個別比率を登録できるようにし、コード内の条件分岐を変更せず調整できるようにする。
- 方針スコアの基本点は、上限と分配を適用した方針対応時間が、重複のない全対象活動時間に占める割合を0～100点で算出する。方針別主要実績は異なる実績種別の初回ごとに初期15点、合計最大30点を加え、同じ簡単な実績の反復では増やさない。点数、上限、実績種別はデータ上の調整可能値とする。能力値、能力引継ぎによる開始値、所持Gold、皆伝職業、世代数は使用しない。
- 主要実績は明確な正常完了結果を持つものだけを登録し、全方針へ無理に設けない。初期候補は、`mentor` を住人への支援による回復・成長・課題達成、`monument` を城・大規模施設完成、`guardian` を損傷施設の完全修復または施設を守った防衛戦完了、`author` を複数の正式語習得または完了結果を持つ研究とする。`seeker` と `slowlife` は初期主要実績を持たず活動時間だけで評価する。追加5方針は楽曲完成、対象作品完成、ダンジョン正式生還・救助完了、住人との関係段階上昇、正式な闘技場・防衛戦完了を初期主要実績とする。チュートリアル、デバッグ、保護テスト、移行前の不完全履歴は時間・実績とも対象外にする。
- プレイヤーが組んだ予定、AIの自律行動、不在中に正常完了した予定を区別せず、同じ活動タグと完了IDで集計する。余生方針は皆伝時の履歴で確定して以後変更しないが、確定した方針の成果物に使う題材は皆伝後の現役期間にも追加できる。本人が実際に余生へ入る瞬間に題材スナップショットを固定し、その後に施設・元作品・戦闘規則等が変化しても保存済み題材から可能な範囲で完成させ、別方針への変更や進行不能を発生させない。
- 候補条件を満たさない方針は性格相性にかかわらず除外する。性格は通常加点へ使用せず最終スコア同点時だけ照合し、それでも同点なら保存済み乱数により本人が一度だけ決定する。ロードや表示のたびに引き直さない。
- 皆伝前には、現在最も強い余生傾向を「最近は音楽に強く惹かれているようだ」等の数値を出さない様子・台詞として確認できるようにする。通常画面には候補一覧、点数、時間配分、除外理由を出さず、プレイヤーが方針を選択、固定、除外する操作も設けない。開発用画面では候補、活動タグ、分配時間、実績点、除外理由、性格照合、乱数、最終判定を確認できるようにする。皆伝時の確定後は後の行動で再判定しない。
- 余生判定用の行動履歴は現在世代専用の `lifePathHistory` として、対象世代IDと勉強、鍛錬、仕事、休息、世話、自由行動の完了時間を分けて保持する。新世代開始時は引継ぎ内容にかかわらず全項目をゼロにし、読込時に対象世代IDが現在世代と一致しなければゼロへ正規化する。旧 `actionHistory` に対象世代IDがない場合も、前世混入を避けるため新履歴へ数値を移さない。
- 余生ポイントは行動の指示回数ではなく、正常完了した行動の実ゲーム内活動時間から加算する。中断、取消、開始不能、到達不能、失敗終了した行動には加算せず、再読込・不在精算でも同じ完了時間を二重加算しない。勉強、筋トレ・ランニング、各種仕事、世話、睡眠・休憩、自由時間を対応する履歴区分へ接続する。
- 余生方針の計算には絶対能力値、能力引継ぎで得た開始値、皆伝職業を使用せず、現世代の `lifePathHistory` だけを使う。免許皆伝時に、その時点で利用可能な共通方針カタログから一つを自動決定して固定し、その世代では後の行動によって再判定・変更しない。
- 免許皆伝しても直ちに余生へ移行せず、同じ世代の現役期間へ入る。現役期間も通常の時計で加齢し、主人公は通常行動と、解放条件を満たしているレストラン、鍛冶屋、ショップ等の経営・勤務を継続できる。一方、1世代1職業皆伝の制約は維持し、現役期間に別職業へ弟子入りして複数皆伝することはできない。
- 余生へ入る時期はAIキャラクター本人だけが決定し、プレイヤーが開始を指示、確認、拒否または延期する操作は設けない。現在の `余生を早送りする` ボタンは廃止し、残りの余生を一度に消化して世代交代する一括清算機能も設けない。
- 免許皆伝後は最低1ゲーム内日を現役として過ごす。AIキャラクターは余生方針と性格をもとに、免許皆伝時点で1～7ゲーム内日の範囲から本人の余生決断予定を一度だけ決める。予定値、判定用乱数、規則版を保存し、ロード、不在精算、画面切替によって再抽選しない。1～7日の範囲は後から調整可能値にする。
- 余生入りが近づいた場合は、正確な残り時間や操作ボタンを示さず、本人が今後の生き方を考え始めたことを段階的な様子・台詞として伝える。寿命までの残り時間が最低現役期間より短い場合は、AIキャラクターが次の安全な区切りで余生入りを決断する。ただし、探索や戦闘その他の完了待ち活動中に自然寿命へ到達した場合は、通常の死亡導線を優先する。
- AIキャラクターが余生入りを決断した後は新しい予定を開始しない。通常行動は現在の1行動、店舗勤務は現在処理中の取引、ダンジョン・闘技場・防衛戦は現在の出撃が終わるまで待ち、安全に終了してからマイホームへ戻る。マイホームでは本人が通常の会話イベント形式で余生入りを宣言するが、これは結果報告であり、プレイヤーへ開始、拒否、延期の選択肢を出さない。
- 余生へ移行した後は現役へ戻れず、通常予定、店舗勤務、探索その他の余生活動以外を行わない。余生進行中は主人公以外の住人、店舗、鮮度、生態系その他の通常世界進行も停止し、余生だけを時間経過に沿って見届ける。
- 余生進捗は種族の寿命の長短に左右されない0～100%で管理する。初期調整値は1回150ゲーム内分で25%進行する4回構成とし、AIキャラクターが各工程を通常の時間経過で実行する。進捗に合わせ、余生開始時の年齢から寿命までの残存年数を比例配分して加齢し、100%到達時に寿命へ到達させる。所要時間、1回の進捗量、工程数は後から調整可能な設定値にする。
- ゲーム終了中もAIキャラクターの余生決断判定と余生工程を通常の不在時間として進行させる。不在中に余生へ入った場合、次回起動時に決断、安全な活動終了、帰宅、各25%工程の内容を時系列の詳細報告として示す。不在中に100%へ到達した場合も、報告後に最期の演出を省略せず、死亡と魂の引継ぎへ進む。これは一括清算操作ではなく、実際に経過した時間の精算として扱う。
- 余生100%到達時は既存の死亡、思い出生成、島住人名簿への登録、魂の引継ぎ、次世代開始の導線へ接続する。現役期間中に自然寿命へ到達した場合も同じ導線を使用する。
- 余生100%到達時は、最後の工程結果、成果物、人物史、次世代効果を一つの確定処理として保存した後に最期の演出へ進む。画面内進行と不在精算で同じ処理を使い、成果物の保存失敗時に死亡だけを先行させたり、再読込で成果物を重複生成したりしない。
- `後世への執筆` は構想、執筆、推敲、完成の4工程とし、各工程で25%進む。途中工程では能力効果を発生させず、100%到達時に1冊だけ秘伝書を完成させる。
- 秘伝書の能力種別は著者の絶対能力値や引継ぎ開始値ではなく、その世代で正常完了した対応育成時間のうち最長のものから決定する。対応は勉強を賢さ、筋トレを活力、ランニングを素早さ、十分な体力・満腹度を保った睡眠・休息を美しさとする。
- 秘伝書には著者の能力値そのものを加算値として保存しない。次世代で対応する育成行動を正常完了したとき、その行動中に本来得た対象能力の上昇量へ初期50%の追加ボーナスを一度適用する。50%は後から調整可能値とし、秘伝書自身の追加分を再び基礎値へ含めない。
- 秘伝書は初期10回分とし、対応行動の正常完了時だけ1回消費する。中断、失敗、開始不能、体力不足、到達不能では効果も消費も発生させない。同じ能力種別の秘伝書を複数引き継いでも1行動では古い1冊だけを発動し、同時加算しない。1冊を習得し終えた後に次の同種秘伝書へ移る。
- 秘伝書の能力効果は従来どおり引継ぎ画面で1冊ずつ400Goldを支払って選択する。選択した秘伝書は10回分の習得完了後に効果を失い、選択しなかった秘伝書も次世代へ能力効果を持ち越さない。一方、完成した全秘伝書は選択・消費にかかわらず、著者、世代、能力種別等を持つ `歴代の著作` 図鑑記録として永久に残す。
- `後進育成` は弟子探し、基礎指導、実践指導、卒業の4工程とし、各工程で25%進む。弟子探しで弟子個体を一度だけ生成し、人物ID、外見、性格、生成条件、判定用乱数を固定して、ロードや不在精算で別人に変えない。
- 後進育成の弟子は師匠の複製にせず、図鑑で発見済みの基本種族からAIキャラクター本人が選んだ基本姿と、自動決定した性格を持つ独立個体にする。現在の `師匠の各能力 × 師匠の賢さ / 100` は廃止し、通常の新主人公と同じ種族別基礎能力から始める。
- 卒業した弟子は固有特性 `教え上手な師匠の教え` を持ち、勉強、筋トレ、ランニング、十分な体力・満腹度を保った睡眠で本来得る能力上昇量へ初期10%を追加する。10%は後から調整可能とし、秘伝書、モニュメントその他の遺産ボーナスを基礎値へ含めない。この特性は同一個体で重複せず、通常の能力・ライセンス・性格等の引継ぎ項目を通じて別個体へ継承しない。
- 弟子は師匠が習得済みの正式語から1語を自律選択して習得する。判定用乱数を保存して再抽選せず、候補がなければ無理に付与しない。師匠の職業Rankや免許皆伝は受け継がず、弟子本人が主人公または住人になった後で通常の修行を行う。
- 卒業した弟子は従来どおり1000Goldの個別選択により次世代主人公候補にできる。選ばなかった場合も消滅させず、住居へ割り当てるまで `入居待ち名簿` に保持する。次世代主人公に選んだ弟子は入居待ち名簿から取り除き、同じ人物IDを主人公と住人へ二重登録しない。住人としての詳細は [`island_residents.md`](island_residents.md) が所有する。
- `生きた証を残す` は設計、基礎工事、彫刻、完成の4工程とし、各工程で25%進め、外観も段階的に完成させる。能力効果と歴史記録は100%到達時に一度だけ確定する。
- モニュメントの能力種別は作者の絶対能力値や引継ぎ開始値ではなく、その世代で正常完了した対応育成時間のうち最長のものから、秘伝書と同じ対応規則で決定する。現在の対応行動をほぼ即時完了させる効果と、更新ごとに能力を直接加算し続ける効果は廃止する。
- 能力効果を有効にしたモニュメントは、対応する育成行動を正常完了した際、その行動で本来得た対象能力の上昇量へ初期10%を追加する。使用回数は設けないが、有効期間は選択した次の1世代だけとし、10%は後から調整可能値にする。秘伝書、モニュメント、薬その他の増加率は互いに乗算せず、遺産ボーナスを除いた同じ対象上昇量から個別に算出して加算する。
- 引継ぎ画面では歴代モニュメントから1基だけを従来どおり500Goldで有効化でき、複数基の能力効果を同時に重ねない。完成した全モニュメントは、選択、非選択、効果終了にかかわらず作者、世代、能力種別、外観等を持つ `歴代の遺産` 図鑑記録へ永久保持する。
- 選択したモニュメントは、マップを引き継いだ場合は保存済みの有効な現在位置へ残す。マップを引き継がなかった場合は配置待ちとし、その世代で最初のマイホームが完成した後、周囲の到達可能で重ならない安全な空き位置へ自動配置する。島自由エディット解放後は通常配置物として自由に移動できるが、位置変更で能力効果を変更しない。配置と検証の詳細は [`main_map_editor.md`](main_map_editor.md) が所有する。
- `終わりのない修練` は鍛錬方針決定、基礎鍛錬、限界への挑戦、修練の完成の4工程とし、各工程で25%進む。現世代で正常完了した勉強、筋トレ、ランニングのうち活動時間が最長の一つを本人の専門分野として最初に決め、4工程を通して固定する。現在の工程ごとのランダム選択は廃止する。
- 修練中の能力上昇は、選んだ通常育成行動と同じ基礎計算へ初期2倍の余生専用倍率を適用する。世代数を直接掛ける現在の倍率は廃止し、2倍は後から調整可能値にする。秘伝書、モニュメントその他の遺産効果を余生中の修練へ適用せず、遺産効果による自己増幅を防ぐ。
- 修練で増えた能力は本人の最終能力として、人物カードと死亡後の本人の住人データへ全量保持する。次世代主人公へは既存の `能力値の引継ぎ` を選んだ割合分だけ反映し、限界突破専用の秘伝書、別の恒久バフ、無条件の能力継承は作らない。現在の歩行開始値 `walk` と完了比較値 `move` の不一致による素早さ分岐不発も、共通の通常育成処理へ統合して解消する。
- `村の守護者` は島内点検、応急修理、総点検、次世代への引渡しの4工程とし、各工程で25%進む。各工程完了時、主人公所有の建物、設備、橋、畑設備等の島内施設について、現在耐久値が進捗率を下回る場合だけ進捗率まで回復し、既に高い耐久値を下げない。100%到達時は全対象を最大耐久値へ戻す。
- 守護者の対象には主人公・住人所有の武器、防具、アクセサリーを含めず、装備修理は鍛冶屋の役割として残す。作物の成長度を100へする現在の効果も廃止し、作物、在庫、Gold、アイテムを生成しない。島施設の修理だけは余生固有の一度限りの行動として材料・Goldを消費しない。
- 守護者完成後に耐久減少を抑える恒久・次世代バフは設けない。マップを引き継いだ場合は整備済み耐久値をそのまま保持し、マップを引き継がない場合は通常の新品状態の新規マップを使用する。守護者として実行した世代、人物、点検・修理対象数は `歴代の遺産` へ永久記録する。
- `悠々自適なスローライフ` は家でくつろぐ、好きなことを楽しむ、これまでを振り返る、穏やかな最期の4工程とし、各工程で25%進む。音楽、料理、釣り、園芸、散歩等の解放済み要素と現世代の行動履歴から本人が趣味を自動選択し、利用可能な候補がなければマイホームで過ごす。プレイヤーによる趣味指定や再抽選は行わない。
- スローライフの現在の体力・満腹度を100へ戻すだけの完成効果は廃止する。代わりに次世代へ `穏やかな暮らしの知恵` を自動で残し、次世代開始から初期7ゲーム内日の間、体力、満腹度、機嫌の自然減少量を10%軽減する。期間と軽減率は後から調整可能値とし、同種効果を重複させず、別個体へさらに継承しない。
- スローライフの各工程で選んだ趣味、場所、振り返った出来事、最後の言葉は `余生アルバム` へ永久記録する。能力値やアイテムを直接増やさず、実用効果は一世代限定の `穏やかな暮らしの知恵` に限る。余生アルバムとTCG思い出の境界は [`../collections/memories_and_album.md`](../collections/memories_and_album.md) が所有する。
- `音楽を遺す者` は主題決定、作曲、編曲、仕上げとCD化の4工程とし、各工程で25%進む。既存プロジェクト、共同制作中の作品、他人が原作者の作品を変更せず、余生専用の新しいソロプロジェクトを一つだけ作る。
- 遺作の曲調、長さ、楽器、構成は本人の性格、職歴、能力、機嫌、習得語、過去の作風、解放済み楽器からAIキャラクターが自動決定する。生成条件と判定用乱数を工程開始時に固定し、ロードや不在精算で内容を引き直さない。各工程の実作業時間は通常規則で本人の作曲熟練度へ加算し、熟練度や能力の低さを失敗作・未完成の理由にせず構成の素朴さへ反映する。
- 遺作制作は原則として音楽制作室の作曲端末で行う。方針確定後に端末を利用できなくなった場合も余生を停止せず、マイホームで旋律を書き残す簡易制作へ切り替え、解放済みの基本楽器だけで完成させる。

- `希代の職人` は専門分野決定、意匠設計、試作、設計図完成の4工程とし、各工程で25%進む。専門分野はその世代で正常完成させた料理、菓子、鍛冶、裁縫、建築制作のうち、実制作時間が最長の分野から本人が決め、同点は性格相性、保存済み乱数の順で解消する。

- `島の架け橋` は交流の振り返り、手紙を書く、後継者の紹介、交流記録完成の4工程とし、各工程で25%進む。余生中に別の場所にいる住人をマイホームへ移動・ワープさせず、現世代で本人が実際に行った会話、贈与、食事、接客、共同制作、共闘等を、関係する人物IDとともに振り返って手紙・紹介記録へ残す。

- 紹介状は住人が次世代途中に待機状態から入居した場合も、その世代で初めて会った時点に一度適用する。物語NPCは交流記録へ載せられるが、紹介状によって師匠遭遇、職業、店舗、クエスト、住居、商品、価格、常連度、Gold、アイテムその他の解放・経済状態を変更しない。オンラインだけの人物は対象外にする。交流記録は引継ぎ・マップ選択に関係なく永久保持し、住人関係の詳細は [`island_residents.md`](island_residents.md) が所有する。
- `歴戦の指揮者` は戦歴整理、編成・行動・勝敗の分析、作戦の体系化、戦術書完成の4工程とし、各工程で25%進む。余生中に新しい闘技場戦・防衛戦を発生させず、本人が実際に参加し、正式な結果まで確定した過去の実戦記録だけを分析する。勝利だけでなく敗北、全滅、撤退も対象にできるが、中断した未確定戦、初回・再履修チュートリアル、デバッグ戦、生活側へ結果を反映しない練習戦は候補成立条件、方針スコア、分析対象のいずれにも含めない。
- 歴戦の指揮者は、対象モード、編成、役割、配置、移動、対象選択、個人作戦、使用した正式語IDと頻度、補給、被害、施設防衛結果等から、性格と戦果に応じた代表戦を保存済み規則・乱数で本人が選ぶ。プレイヤーは題材や完成内容を直接指定できず、敗戦中心でも敗北から学んだ戦術として成立する。自由入力語とチャット本文は保存・分析しない。
- 100%到達時は、著者人物IDを持つ変更不能な永久人物史 `戦術書` と、既存の合法な行動だけで構成した再利用可能な作戦テンプレートを1つ作成する。テンプレートは条件、優先度、使用頻度、役割分担だけを定義し、能力、ダメージ、射程、MP、行動回数、報酬、ランキング点、習得語を増やさない。使用者が未習得の正式語や対象モードで非対応の条件は理由付きでその行だけ無効化し、残る有効行は利用できる。
- 戦術書は何冊でも永久保存できるが、1回の出撃へ適用できる原本は1冊だけとし、複数の戦術書を合成・重複適用しない。`指揮する` では初期作戦と行動候補を読み込むだけでプレイヤー操作を奪わず、`全てAUTOでおまかせ` ではAIが有効な作戦行に従う。闘技場と防衛戦の間で非対応条件を無理に変換せず、原本を調整するときは編集可能な個人作戦へ複製する。引継ぎ枠・費用とオンライン接続を必要とせず、将来廃止された語・条件は該当行だけを無効化して人物記録を残す。モード別の適用規則は [`../castle/arena.md`](../castle/arena.md) と [`../castle/defense.md`](../castle/defense.md) が所有する。
- 新余生仕様へ移行するとき、既に確定した余生方針は再抽選せず、進行度を対応する0・25・50・75・100%工程へ引き継ぐ。旧工程で既に得た能力、品物、修理等を取り消さない一方、完了済み工程の新効果を再付与しない。現在有効な旧秘伝書は巨大な固定加算値を廃止して残り使用回数分の新しい割合効果へ、旧モニュメントは現在世代の残り期間に限る新しい10%効果へ変換し、旧仕様の継続加算を停止する。既に能力へ加算された値と生成済み弟子の現在能力は、由来を正確に分離できないため自動減算しない。詳細は [`../internal/save_data_and_migration.md`](../internal/save_data_and_migration.md) が所有する。
- 建築士皆伝後の島自由エディット解放クエストは、建築士ライセンスを引き継いだ次世代だけ受注可能にする。
- 死亡した過去世代のキャラクターを記憶・魂として島へ迎える将来仕様は [`island_residents.md`](island_residents.md) が所有する。
- 死亡した本人の恒常的な最大満腹度は、島住人として保存する個体データには減衰させずそのまま保持する。一方、新主人公への継承は既存の `能力値の引継ぎ` を選んだ場合だけ行う。
- 作曲熟練度は能力値へ含めず、独立した `作曲熟練度の引継ぎ` 選択項目を追加する。音楽制作が未解放のセーブでは項目名、解放条件、選択枠を引継ぎ画面へ表示せず、音楽制作室を初めて解放した後の引継ぎ画面から同じセーブ系譜で恒久的に表示する。初期費用は300Goldとし、能力値のような継承率やパーセント選択は設けない。選択時は前世主人公の作曲熟練度を全量そのまま新主人公へ継承する。死亡本人が島住人になる場合は選択に関係なく本人の作曲熟練度を全量保持する。制作・保存の詳細は [`../collections/music_creation_studio.md`](../collections/music_creation_studio.md) が所有する。
- 魂の引継ぎで使用するGold費用は廃止し、系譜専用の `魂の引継ぎポイント`（内部ID `inheritancePoints`）へ置き換える。ポイントは主人公個人の所持品・Gold・金庫・カジノコイン・オンライン通貨から独立し、購入、交換、贈与、課金、ランキング報酬では増やさない。未使用分は通常の世代交代、マップ・Gold非継承を越えて系譜へ全量蓄積し、完全な `はじめから` だけで初期化する。
- 引継ぎポイントは、正式な世代交代到達、職業皆伝、余生完成、主要コンテンツ実績等、その世代で初めて成立した言語非依存の人生実績から得る。同じ実績IDは1世代1回だけとし、単純反復、能力値、所持Goldの大きさから算出しない。死亡時にその世代分を一度だけ確定して系譜残高へ加え、能力、持ち物、語彙・記憶領域、職業ライセンス、姿と性格、マップ、所持金、作曲熟練度、弟子、モニュメント、秘伝書その他の有料引継ぎへ使用する。図鑑、人物史等の自動永久保持物はポイント選択にしない。
- 引継ぎポイントの初期付与は正式な世代交代到達10、新しく職業を免許皆伝3、余生100%完了2、異なる主要人生実績ごとに1とする。人生実績分は1世代最大5、1世代の初期獲得上限は20とし、系譜の累積残高には上限を設けない。引継いだ既存ライセンスだけでは皆伝分を再獲得せず、余生前に寿命へ到達した場合は余生完成分を得ない。通常の皆伝・余生完遂で15、さらに異なる人生実績を5種類達成すれば初代から20へ到達できる。各値は調整可能にする。
- 初期ポイント費用は、持ち物3、語彙・記憶領域4、職業ライセンス8、姿と性格2、マップ6、所持Gold5、作曲熟練度3、一番弟子を次世代主人公にする10、モニュメント能力効果5、秘伝書能力効果4とする。能力値は選択率10%ごとに1ポイントとし、現在と同じく選択可能上限を `世代数 × 10%`、最大100%とする。作曲熟練度その他割合指定を持たない項目は全量だけを選べる。費用と上限式は調整可能にする。
- そのセーブに存在しない弟子・遺産と未解放の作曲熟練度等は選択肢へ表示しない。何も選ばず0ポイントで次世代へ進むことも許可し、残高を全量保持する。
- 初代プレイ中は、引継ぎポイントの名称、残高、獲得予定、対応実績、魂の引継ぎ自体を通常UI・説明・チュートリアルへ表示せず、最初の最期と魂の引継ぎ画面で初めて存在とその世代の獲得結果を明かす。初回引継ぎ画面を一度表示した後は同じセーブ系譜で解放状態を永久保持し、次世代以降だけ系譜・世代情報画面から現在残高とその世代の獲得予定を確認できる。開発用確認機能は初代でも内部集計を検証できるようにする。
- 引継ぎ画面では選択中の消費予定だけを計算し、最終確認までは残高を減らさない。選択解除は即時に予定消費を戻し、不足する選択肢はゲーム内UIで理由を示す。最終確認時にポイント確定、選択内容、次世代用データ作成を一つの処理として保存し、Goldを支払わない。将来の引継ぎ項目も安定IDとポイント費用をカタログへ追加できる構造にする。
- 前世主人公は住人化後も本人の能力、スキル、性格、職歴、ライセンス、正式語、記憶容量を保持する。語彙・記憶領域と職業ライセンスの引継ぎは、前世住人から消す所有権移転ではなく、新主人公へ魂の記憶を複製する選択とする。選ばなかった場合も前世住人の知識・資格は失われず、新主人公だけが学び直す。
- 死亡時点の本人の手持ち品、装備、個人Goldは、原則として前世住人の個人財産になる。持ち物またはGoldの引継ぎを選んだ場合は、対応する実物・金額の所有権を新主人公へ移し、前世住人側から減らす。選ばなければ前世住人が保持して生活、勤務、探索、闘技場、防衛戦等で利用できるため、ポイントを節約して有力な住人へ財産を残す選択として成立する。
- マップを引き継ぐ場合、主人公宅の倉庫、冷凍庫、金庫と内容物は島・建物側の資産としてそのまま残し、前世住人の個人財産へ重複登録しない。死亡前に個人財産を主人公宅へ収納してマップとともに残す準備も許可する。マップを引き継がず持ち物またはGoldを引き継ぐ場合は、対応する収納品・金庫Goldを新主人公へ退避する。マップも対応財産も引き継がなければ、前世住人の個人財産は残るが、消える建物内の収納品・金庫Goldは失われる。
- 引継ぎ画面は現在の選択組合せから、`新主人公へ移る`、`前世住人に残る`、`島に残る`、`失われる` の四区分で、対象品数、装備数、Gold額、語彙数、ライセンス数等を表示する。選択によって移転対象が空になる持ち物・Gold項目は非表示または選択不能にして、効果のないポイント消費を認めない。最終確認も同じ区分と実数を使用する。
- `持ち物` は、死亡時点で前世主人公が個人所有している手持ち品と装備中の武器、防具、アクセサリを一括対象とし、初期実装では品目別・装備別の部分選択を設けない。選択時は個体ID、個数、品質、鮮度、耐久値、呪いその他の個体状態を変えず新主人公へ所有権移転する。特殊品、世界状態に属する品、施設・制作・取引等で使用中の品は、各所有仕様に従って対象外または処理完了後の所有者へ残し、引継ぎによる複製を行わない。生鮮品の経過時間も巻き戻さない。
- `所持Gold` は、前世主人公個人の手持ちGoldを全額一括で所有権移転し、一部金額の指定を設けない。マップを引き継がず所持Goldを引き継ぐ場合だけ主人公宅の金庫Goldも新主人公へ退避する。店舗レジ、前世以外の住人の個人Gold、カジノコインその他の別通貨は対象に含めない。
- `語彙・記憶領域` は、前世主人公が習得した正式語の安定ID、使用中・長期記憶を合わせた自由入力語の原文、お気に入り・使用履歴、および取得元ID付き恒久記憶拡張を一括で新主人公へ複製する。表示言語を変えても正式語はIDから表示し直し、自由入力語は翻訳しない。継承した語彙は会話・行動で使用できる知識に限り、チュートリアル履歴、師匠との遭遇、職業課題・試験の合格、施設・レシピ・階層その他の解放実績を自動達成しない。年齢・賢さ・種族から計算された前世の容量は新主人公の基礎値へ累積せず、新主人公の状態から再計算する。詳しい容量式、正式語専用枠、自由語の使用中・長期記憶区分は [`ai_words_and_tasks.md`](ai_words_and_tasks.md) が所有する。
- `職業ライセンス` は、死亡時点で免許皆伝している職業だけを一括で新主人公へ複製する。中途Rank、試行回数、失敗回数、破門状態、進行中・報告待ち課題、現在の師匠は引き継がず、新主人公は継承職とは別の職業へ通常どおり弟子入りできる。前世住人側は選択にかかわらず全職歴、皆伝済みライセンス、中途Rankと再開に必要な本人固有履歴を保持し、現在の島で出会える師匠の通常条件を満たせば住人として修行を再開できる。
- ゲーム終了中も主人公の年齢・寿命を進め、オフライン経過中に寿命へ到達した場合は死亡と世代交代導線を発生させる。終了前にはオフライン中も加齢し、次回起動時に世代交代となり得ることを毎回説明する。説明表示は初期状態で有効とし、端末のゲーム設定から表示・非表示を任意に切り替えられるようにする。終了警告の環境別導線は [`../internal/runtime_platform_and_audio.md`](../internal/runtime_platform_and_audio.md) が所有する。
- 不在区間中に主人公が寿命へ到達した場合、その時刻で主人公、住人、店舗、鮮度、生態系その他を含む全不在精算を停止し、寿命到達後から次回プレイヤー操作までの時間を次世代へ自動適用しない。次回起動時は、寿命到達までの不在報告、最期と死亡演出、思い出生成と島住人名簿への登録、魂の引継ぎ画面の順に進める。プレイヤーの選択なしに引継ぎ内容や次世代キャラクターを自動決定しない。
