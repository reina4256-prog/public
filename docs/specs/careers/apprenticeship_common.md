# 弟子入り共通仕様

状態: 実装済み

## 現在の実装仕様

### 遭遇から弟子入りまで

1. 解放条件を満たすと師匠の遭遇イベントが発生する。通常フィールドで出会う基本職の師匠は、任意の言葉を3語以上学習していることを共通の最低条件とする。
2. 初回は職業固有の動画・挨拶を表示し、`metMasters` と師匠名の学習語を記録する。
3. 基本職はテント・畑・レストラン等の拠点を作る。上級職は既存施設や専用屋内マップを使う場合がある。
4. Rank 0で三問の一問一答試験を受ける。問題文は概念を示し、正解語を直接教えない。
5. 三問合格で正式に弟子入りし、Rank 1以降の課題へ進む。

- いずれかの師匠と初めて顔合わせを完了したとき、具体的な師匠名や職業名を伏せた `修行への入口` チュートリアルを追加する。

### Rankと課題

- 内部職業IDごとに `apprentice.rank[masterType]` を持つ。
- Rank 0は入門前、Rank 1～9は修行、Rank 10は免許皆伝。
- 課題は `activeQuests` に保持し、開始時処理、達成判定、報告時消費を持てる。
- 能力上昇課題は受注時能力を基準に目標値を保存する。
- 回数課題は受注時に `qVal` 等を初期化し、対象行動の成功時だけ進める。
- 納品課題は報告時に対象物を消費するものと、所持確認だけのものがある。個別仕様とコードを正本とする。
- 師匠訪問では課題報告とバイト報告を安全に分け、特別依頼を通常Rank報告へ混ぜない。

### バイト・破門

- 各師匠は通常課題とは別に手伝い・バイトを提供し、主にGoldを報酬とする。
- 長期間の放置、失敗回数等により破門・出禁となる経路がある。具体条件とセリフは個別職業・実装を確認する。
- 世代交代では中途Rank、破門、リタイア等を未入門へ戻し、皆伝履歴だけを恒久職歴として扱うのが基本。

### 免許皆伝

- Rank 9課題の報告後、Rank 10、`isGraduated`、職業称号、能力・技能・アイテム報酬を確定する。
- 同じ世代で対応師匠の人物思い出を1枚獲得する。思い出が60枚未満等ではTCG用語を前面に出さない。
- 皆伝後は6種の余生方針から選び、寿命まで自動行動できる。
- ディーラーはカジノを正式退出してから余生選択へ進む。コンシェルジュはマイホーム屋内状態を維持できる。

### 世代交代と再会

- 職業ライセンスを引き継ぐとRank・皆伝履歴と次世代特別依頼の候補を保持する。
- 能力が十分高い次世代は、師匠初対面時にRankスキップまたは即皆伝となる場合がある。
- 皆伝済み師匠は新世代を前世と区別した再会セリフで迎える。
- 実装済み職のうちディーラーを除く11職は、次世代で1世代1回の特別依頼候補を持つ。
- 特別依頼は受注後に新しく行った成果だけを認め、アイテム成果は `masterSpecialProof` で個体を証明する。
- 特別依頼は同時に複数保持でき、対象師匠本人への個別報告で完了する。

## 確定している将来仕様

- 職業は基本職・上級職に分類し、今後の追加も1職業1仕様書とする。
- 入門試験は現在と同じく、プレイヤーがAIキャラクターへ事前に教えた言葉を正解概念群と照合し、AIキャラクター本人が試験中に自動回答する間接介入方式を維持する。プレイヤーが試験画面で答えを選択・入力する形式へ変更しない。
- 占い師、科学者を上級職候補として記録する。販売員は将来実装する上級職として確定し、内部ID `merchant` とショップ経営の解放資格を持たせる。現在一部の表示処理にある旧ID `salesperson` は実装時に移行し、新規保存へ使用しない。詳細は [`advanced/salesperson.md`](advanced/salesperson.md) を参照する。
- 販売員を含む新職業も既存の `1世代につき1職業だけ免許皆伝` の制限に従う。皆伝後の現役期間や住人化後の追加修行を、同じ主人公が一世代で複数職を皆伝する抜け道にしない。
- 販売員はライセンスを引き継いだ次世代向けに、既存師匠と同じ1世代1回の人物思い出クエスト `時代を読む商い` を持つ。現世代で師匠と再会し、その世代の人物思い出が未取得であることを提示条件とする。課題内容と消費は販売員仕様、人物思い出の世代別重複防止は [`../collections/memories_and_album.md`](../collections/memories_and_album.md) を正本とする。
- 皆伝後の繰り返し可能な設備獲得依頼を追加する場合は、通常Rank課題、1世代1回の次世代特別依頼、バイトと区別できる言語非依存の依頼種別を持たせる。`activeQuests` の複数保持と師匠本人への個別報告を再利用しても、別種別の報告・報酬を誤ってまとめない。最初の対象は漁師の水槽依頼と、それから派生する建築士の池制作依頼とする。
- 島へ定住した過去世代の住人も、保存済みの生前職歴だけで固定せず、定住後に本人の修行進行を持って師匠へ弟子入りし、能力と職歴を成長させて新たに皆伝できる。住人は現世代の主人公が初回遭遇を済ませ、師匠またはその拠点が現在の島へ登場した職だけを修行先にできる。歴代の主人公が以前会っていても、現世代の主人公がまだ再会していない師匠へ住人だけで通うことはできない。住人固有の修行進行、課題、報酬と師匠解放判定の詳細は [`../core/island_residents.md`](../core/island_residents.md) と各職業仕様へ接続する。
- 現行の基本職6職のRank 1～9は、能力の相対上昇、農業・釣り・料理・鍛冶・建築・通常探検の実行回数、本人の所持品からの納品で構成され、主人公だけの建物所有や世代限定イベントを達成条件にはしていない。住人にも勉強、筋トレ、ランニング、清潔な休息等の通常育成行動、各基本職の実技、個人所持品と納品を持たせ、基本職6職は主人公と同じRank課題を置換せず使用する。支給品と納品物は住人本人の所有物として処理する。
- 住人の皆伝ではRank、本人の能力・技能・職業資格を付与する一方、人物カード、主人公向けの世界・建物・上級職解放、世代限定品、余生選択等を重複発生させない。上級職には主人公本人の施設操作、物語進行、世代条件等へ依存する課題があるため、該当課題だけ難度と学習内容が同等の住人用実技課題へ置き換える。
- 現行実装の `getMasterQuestData()`、`currentMaster`、共有 `qVal`、課題の `setup/check/onClear` はグローバルな `aiPet` 一人を直接参照する。住人修行では、師匠ごとのRank・在籍・課題と対象住人を明示的に受け取る個体別処理へ分離し、主人公や別住人の修行進行・所持品を更新しない。

## 未決定事項

- ディーラーにも次世代特別依頼を追加するかは未決定。
- 上級職ごとに、どの課題をそのまま共用し、どの主人公専用課題を住人用実技へ置き換えるか。
- 現行の基本職Rank課題に能力上昇を多く要求しているのは、能力を育てる時間を意図的に挟み、短時間で免許皆伝して0歳のまま余生へ入る不自然さを避けるためである。将来、基本職全体の課題を見直す際はこの進行時間調整を失わないことを前提とし、能力値の強制上昇を維持するか、最低経過年齢、課題日数、実技回数、複合条件等へ置き換えるかを別途決定する。漁師ヌシの捕獲成功率下限5%はRank 8の自動失敗だけを解消する個別仕様であり、他の基本職の能力課題を自動的に撤廃する決定ではない。
