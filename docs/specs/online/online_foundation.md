# オンライン基盤仕様

状態: 実装済み・実機総合検証要

## 現在の実装仕様

- Firebase AuthenticationとFirestoreを利用した非同期オンライン機能。
- オンライン無効ビルドではFirebaseを読み込まず、認証選択・オンライン名登録を省略する共通起動経路を使用する。版別構成と現段階の対応範囲は [Steam体験版・製品版仕様](../internal/steam_demo_and_full_release.md) を参照。施設内の全導線監査と既存オンライン活動中セーブの再開は未完了。
- ブラウザではメール登録・ログイン、Steam/Electronではタイトル画面の明示選択後にSteamIDから派生した認証情報でログインする。起動時のSteam自動ログインは行わない。
- 新規開始と続きからで、オフライン開始、ログイン、クラウド競合選択の導線を分ける。
- `cloud_manager.js` に `handleSignOut()` は存在するが、`index.html` のログイン中メニューにはログアウトボタンがない。既存処理の通知は標準 `alert()` を使用しており、導線追加時にゲーム内通知へ移行する。
- プレイヤー名はオンライン表示名として登録し、酒場、ランキング、フレンド、島訪問、取引に使う。
- オフラインでも基本ゲームは遊べるが、Firestoreを使う各関数は内部で通常アカウントの認証を再確認し、未認証およびP2P専用匿名ユーザーでは読み書きしない。
- 酒場AIの30秒定期公開は通常アカウントのログイン監視に連動して開始し、ログアウト、匿名セッション、明示オフライン開始では停止する。
- TCGリアルタイム対戦だけは明示操作後の匿名認証を許可する。詳細は [`tcg_realtime_p2p.md`](tcg_realtime_p2p.md) が所有する。
- クラウドへローカルセーブ一式をバックアップし、クラウドから復元できる。
- ローカルとクラウドが競合した場合は専用選択UIを表示し、暗黙に上書きしない。

## 通信キャッシュ

- 酒場AI、オンラインデッキ、ダンジョンランキング、闘技場ランキング、防衛ランキング、カード市場などの取得結果を `dataCache` に保存する。
- キャッシュ有効期間内は再読込を避け、明示更新時だけ強制取得する。
- ゲーム開始・ロード時は専用UIの一時状態をリセットし、保存データ本体とオンライン表示状態を混同しない。

## データ所有と安全

- 自分の通常ゲーム状態はローカルセーブが基盤で、クラウドバックアップは明示同期する。
- 他人の島訪問中は表示用の他人データと自分の実データを分離し、他人のセーブを自分の保存先へ誤上書きしない。
- 取引・食事効果・救助・競売は対象ドキュメントへの非同期通知として処理する。

## 主な実装

- `cloud_manager.js`: 認証、名前、バックアップ、復元、キャッシュ、全オンラインAPI。
- `electron_main.js`: Steam APIブリッジ。
- `system.js`, `main.js`: ローカル保存と開始フロー。

## 確定している将来仕様

- オンライン機能はSteamリリースを前提に、Firestore Read数を抑える設計を維持する。
- オンラインを採用する場合は、他人の島・施設・AI・共有資源・行動結果が持続的に関係するゲーム中核として扱う。ただしオンラインなしの製品版も配布可能にし、搭載を発売条件にしない。販売構成の正本は [オンライン・販売方針](../internal/online_release_and_localization_strategy.md)。
- オンライン無効構成では認証選択・オンライン用プレイヤー名登録・ログインボタンを省き、認証の復元や定期通信を開始しない。ゲーム進行が認証や名前登録待ちで停止しないようにする。
- オンライン有効の製品版では、ログイン中にユーザーが任意のタイミングで操作できるログアウトボタンを用意する。ログアウトはローカルセーブの削除・ニューゲームではなく、オンライン認証と通信を終了してオフラインへ戻る操作とする。意図しない自動再ログインで取り消さない。
- ログアウト完了・失敗の通知は [共通ゲーム内UI](../core/ui_dialogs_and_notifications.md) を使用する。訪問・対戦・取引中の終了手順や未完了処理の整合性は、実装前に個別フローと照合する。
- オンライン運営中の中核的な交流価値と、購入済みゲームの単独動作を分ける。サーバー運営を継続できなくなった場合は、ローカル育成、世代交代、職業、施設経営、自由エディット、収集、生態系等の一人用本編を完全オフラインで起動・保存・継続できる版へ移行できなければならない。ログイン失敗やサービス終了を本編ロード失敗にしない。
- 一人用状態はローカルセーブを正本とし、オンライン機能は公開スナップショット、共有資源、通知命令等の分離データとして接続する。サーバーにしか存在せずオフライン移行時に失われる一人用の所有物・進行・配置を作らない。
- 所有者専用セーブ、公開用島概要、施設別屋内スナップショット、共有資源、イベント履歴、対戦用AIデータを分離する。
- 現在の個人用クラウドバックアップは開発初期の補助実装であり、オンライン運用やフレンド訪問の必須基盤として固定しない。将来、完全オフライン版への移行方針や運用判断により、機能全体を廃止するか、少なくともユーザーが任意時点でアップロード／復元するUIを廃止できる設計にする。
- フレンド訪問用公開スナップショットは個人用クラウドバックアップから完全に分離し、バックアップの無効化・廃止後もオンライン運用中は単独で公開・取得できるようにする。公開データへ個人用セーブ一式を流用せず、訪問表示と許可された共有機能に必要な最小データだけを含める。
- 共有資源の変更はサーバー上の最新状態へ原子的に適用し、一意のイベントIDにより再送時の二重反映を防ぐ。
- ゲーム内部のプレイヤーIDをSteam等の外部IDから独立させ、将来の販売先も同じ世界へ接続できる構造にする。
- 詳細な製品方針、運営費、販売、ローカライズは [`../internal/online_release_and_localization_strategy.md`](../internal/online_release_and_localization_strategy.md) が所有する。

## 構想段階の案

- 将来のプラットフォーム追加では同じプレイヤーID・セーブ競合方針を再利用する可能性がある。
- 運営費と終了時移行を許容できる場合に限り、ゲーム終了中にも個人別の重要イベントを知らせる共通外部通知基盤を追加する。イベントは言語非依存の種別ID、対象、重要度、発生日時、期限、重複防止キー、ローカライズ引数、任意の外部操作先を持ち、水槽以外の通知も登録できるようにする。
- 外部通知を採用する場合、LINE Messaging API、Steam Game Notifications、Web Push等を独立したチャネルアダプターにし、種類別ON/OFF、緊急通知の即時配信、通常通知の1日1回集約を共通制御する。別Webアプリのインストールは必須にせず、必要な操作だけHTTPS画面で行う。通知・外部操作は丸ごと無効化してもローカル本編を変更せず動作させる。
- 水槽の外部救済を採用する場合、サーバーは魚本体ではなく監視用スナップショット、危険時刻、ローカル魚IDに対する一時保護命令だけを保持する。命令は一意のIDで次回起動時にローカルへ一度だけ適用し、通知サービス停止時はローカルの不在報告と通常の救済だけへ戻る。詳細は [`../core/indoor_aquariums_and_ponds.md`](../core/indoor_aquariums_and_ponds.md) が所有する。

- 外部アカウントのリンク・復旧・同時利用排他、データ削除UIは未決定。
