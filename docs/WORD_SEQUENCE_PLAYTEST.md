更新: 2026-09-27。実装・自動検証済み。ユーザーから3例のノート表示を受領し、期待結果との一致を確認。返答・保存再開の確認範囲は補足待ち。
内容仕様の正本は [3c3c節](specs/core/experimental_word_learning.md#文の関係の習得の小単位3c3c同じ食事の未完了完了と休息提案)。

## 共通の準備

- 日本語で「理解の土台＝関係の土台から育てる」「生活知識＝基本の生活語・感覚・気持ちを知って始める」「発話＝短文の形式を使える」を選ぶ。土台ありでは順序を最初から知っているため、新規習得の確認には使わない。
- 保存を使う通常起動は `npm run start:word`。既存データが自動再開されて設定を変えられない場合、既存保存を消さず、`npm run start:web:words` で表示される `http://127.0.0.1:4175/` を開くと新規の一時試遊ができる。Web版は保存されず、再読み込みで最初からになる。
- 先に、本人の休息中に `【お願い】「休んでね」` を送り、休息完了を待つ。別の休息中に `【誘い】「一緒に休もう」` を送り、その休息も完了させる。ノートでお願い／誘いの限定理解を確認する。この前提操作は各新規試遊で必要。
- 動作は本人が自然に選ぶのを待つ。入力欄に文字がある間は生活時間が止まるので、食事が始まったら入力して落ち着いて送れる。送信後は進む。「ひと休み・再開」で明示停止中は送信できないため、教示時は停止を解除する。

## 1. 同じ食事の前後から習得できる

1. 食事中に `【順序・未完了】「あなたが食べ終わったら、休んでね」` を送る。
2. 食事が終わったら、次の食事が始まる前に `【順序・完了】「あなたが食べ終わったら、休んでね」` を送る。直後でなくても、次の食事の開始前ならよい。
3. ノートを開く。

期待結果：未完了側だけでは照合途中。完了側を送ると「同じ食事の前後を照合し…分かった」と返し、ノートに両教示の原文と「同じ相手・言語・表現に限る」「実行や予約とは別」の説明が出る。完了教示を何度送っても教示が重複して増えない。

## 2. 逆順や別の食事では誤って習得しない

テスト1で習得済みなら、別の新規試遊で共通準備を済ませて行う。

1. 未完了教示を一度も送っていない状態で `【順序・完了】「あなたが食べ終わったら、休んでね」` を送る。
2. ある食事中に未完了側を送り、完了側を送らずに次の食事まで待つ。次の食事では教示せず、終了後に完了側を送る。
3. ノートを確認する。

期待結果：どちらも順序を習得しない。前の食事の未完了側が記録として残っていても、別の食事と接続されない。以後、新しい食事で正しく未完了→その食事完了→完了側を教えれば習得できる。拒否時の返答が一般的な未理解表現になることはあるため、「分かった」と扱われたか・ノートで習得済みになったかを確認する。

## 3. 習得後の理解・ノート・再開を確認する

テスト1の習得済み状態を使う。

1. 印を外した `あなたが食べ終わったら、休んでね` を送る。
2. ノートを開き直す。通常Electron版で試している場合は、保存エラー表示がないことを確認してウィンドウを閉じ、`npm run start:word` で再開し、同じ文をもう一度送る。Web版では再開部分だけ対象外とする。
3. `あなたが食べ終わったら、散歩してね` のように後続行動を変えた文も送る。

期待結果：元の文には「食べ終えた後に休んでほしいんだね…」と返す。両原文と限定理解がノートに残り、再開でも失われず重複しない。散歩へ変えた文は、この教示だけでは全文理解にならない。休息の予約・食事の打ち切りは追加されない。本人が通常の自律判断で木陰へ向かうことはあるので、たまたま休息したことだけを不具合とは判定しない。

## 結果の伝え方

「例1はOK／例2の2番で習得してしまった」のように、例番号・開始三設定・使った入力・画面の返答・ノートの表示を伝える。保存テストはElectronかWebかも添える。表示のはみ出し、入力しにくさ、BGMの不自然な停止など、実画面で気付いた点も併記する。自動検証済みの八設定×七言語すべてを手で繰り返す必要はない。
